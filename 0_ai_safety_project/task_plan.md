# AI Safety 调研与项目规划

## 目标

结合本地知识资产与外部一手资料，形成三个可在 3 至 12 个月内执行的 AI Safety 项目，并制定个人 1、3、5 年长期目标。

## 背景与约束

- 优先复用现有风控、Agent、图/时序、多模态、对抗样本与证据仲裁积累。
- 项目必须有明确问题、数据、基线、评测指标、MVP 和停止条件。
- 研究结论优先使用论文、官方基准、标准和原始项目资料。
- 不设计未经授权的真实系统攻击；对抗实验限定在沙箱、合成或脱敏环境。
- Wiki 正文使用简体中文，并更新 `wiki/index.md` 与 `wiki/log.md`。

## 关键决策

| 决策 | 理由 | 日期 |
|---|---|---|
| 以 Agent 安全、证据可靠性和多模态风控为候选主轴 | 与本地资产和职业背景重叠度最高 | 2026-10-22 |
| 采用“一个近期主项目 + 两个递进项目”的组合 | 避免三个项目并行争夺同一批资源 | 2026-10-22 |
| 三个项目共享证据事件、攻击场景和审计协议 | 本地资料显示行动面、感知面、长期状态面可以复用基础设施 | 2026-10-22 |
| 近期只启动 BRIC-SafeAct | Agent 行动安全已有成熟动态基准、清晰工具边界和最快的工程反馈 | 2026-10-22 |
| 把自适应攻击、重复尝试和影响加权列为硬指标 | NIST 评测显示静态单次 ASR 会显著低估实际风险 | 2026-10-22 |
