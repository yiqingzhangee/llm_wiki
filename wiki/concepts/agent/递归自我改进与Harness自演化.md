# 递归自我改进与 Harness 自演化

> 关联来源：[[来源-递归自我改进与Harness自演化-2026]]、[[来源-Dream-RSI-演化世界递归自我改进-2026]]、[[来源-Agent记忆综述-2026]]。

## 核心命题

**“自我改进”不是一个能力标签，而是一条必须逐环验证的链路。** 对当前 LLM Agent，最可操作的对象通常不是直接修改权重，而是目标定义、外部记忆、执行 Harness 与经验整合；它们只有在独立留出评估上形成可保留、可迁移的增益，才构成有意义的持续改进证据。

## 从自我精炼到递归改进

| 层次 | 是否留下持久变化 | 是否改进产生改进的机制 | 例子 |
|---|---|---|---|
| 自我精炼 | 否 | 否 | 单轮反思、重写、投票 |
| 持续性改进 | 是 | 未必 | 更新记忆、技能、提示、Harness 或权重 |
| 递归自我改进 | 是 | 是 | 系统评估并修改自身的目标操作化、经验整合或优化机制 |

因此，把“反思后答案更好”直接称为 RSI 是概念外推。真正需要检验的是：改进是否跨任务保留、是否能诊断并修正改进机制本身、是否在独立评估上仍成立。

## 四个必要环节

1. **目标操作化**：将模糊意图转成可验证目标、数据与成功标准。ASPIRE 表明，这一步本身会吞噬大量搜索预算，且自造验证信号不保证指向真实能力。
2. **执行 Harness**：以工作流、工具、上下文、状态、权限、验证和恢复把模型能力变成可执行系统。HarnessDev 表明，Harness 是性能杠杆，也可能过拟合 creator 或 executor。
3. **经验整合**：把观察到的成功/失败转成历史、摘要记忆、技能或参数更新。S3Gym 表明，状态密集型任务和规则可压缩任务需要不同载体。
4. **独立验证与治理**：冻结制品，用未见任务、跨模型/跨任务测试、成本与失败轨迹评估；将权限、监控、停止和回滚纳入循环。

缺少任一环节时，系统最多展示了局部优化，而不是可信的持续改进。

## Harness：当前更现实的改进基底

Harness 处在基础模型与真实环境之间，决定 Agent 如何：

- 规划和组织工作流；
- 调用并约束工具；
- 选择、压缩与持久化上下文；
- 使用子 Agent 或后台任务；
- 测试、验证、恢复和停止。

其工程优势是**可检查、可版本化、可回滚**；相较直接权重更新，风险和成本通常更易控制。代价是接口、提示或工具策略可能绑定具体 executor，且开发集反馈容易把局部技巧误认为普适能力。

## 第三种改进基底：经验重放驱动的元策略优化

除"Harness 工程"和"权重更新"外，Dream-RSI 给出第三种可操作的递归改进基底：**把历史探索经验组织成可回放的世界/模拟器，在离线"做梦"里优化 exploration 策略（元层）**。其核心是把"元级反馈延迟且昂贵"这一瓶颈转变成"一次在线探索支撑海量廉价离线策略评估"。

| 改进基底 | 改进对象 | 反馈来源 | 代表来源 |
|---|---|---|---|
| Harness 工程 | 工作流/工具/上下文/记忆 | 冻结 Harness 留出评估 | [[来源-递归自我改进与Harness自演化-2026]]（HarnessDev/Harness Engineering） |
| 权重更新 | 模型参数 | 训练/对齐数据 | [[参数高效微调与对齐训练]] |
| 经验重放驱动的元策略优化 | exploration-policy 代码 | 离线 replay simulator | [[来源-Dream-RSI-演化世界递归自我改进-2026]] |

Dream-RSI 与既有负面证据并不矛盾：它证明的是"**在固定历史平均分上**，离线重放能选出更好的探索策略、且收益在递归轮内、任务内成立"——它没有推翻"跨任务/跨 executor 的留出迁移不稳定"这一更宽的边界。阅读时应把"基于重放的策略改进在新世界是否泛化"单独设为待验证问题。

## 经验的载体应匹配信息结构

| 经验类型 | 较合适载体 | 主要风险 |
|---|---|---|
| 可表达为稳定规则的策略 | 摘要记忆 / 技能条目 | 过度压缩丢失例外条件 |
| 强依赖当前状态与细节的经验 | 原始轨迹 / 检索上下文 | 上下文成本与检索噪声累积 |
| 跨分布稳定、数据与验证充分的模式 | 参数更新 | 负迁移、遗忘、奖励或数据污染 |

这将 [[Agent记忆系统与自我演进]] 的“记忆基底/认知机制”与 [[参数高效微调与对齐训练]] 的“权重适配/行为塑形”放进同一个选择框架：先问经验是什么，再决定写到哪里，而非默认训练最强。

## 工程与治理含义

- 对 [[多Agent系统研究趋势与工程映射]]：子 Agent 并行必须配套文件化状态、日志、结果合并和取消恢复；否则并发只是在制造不可审计的上下文碎片。
- 对 [[知识图谱驱动的深度研究Agent]]：证据图谱是把“我为什么认为某个改进有效”外化为可追溯状态的一个强结构化实例。
- 对生产系统：应优先选择可冻结、可 replay、可回滚的改变；把开发期自评与部署期独立评估隔离，避免闭环自我确认。

## 结论边界

现有资料支持“模型可在局部环节上构建或改进 Harness、记忆和训练方案”，但不支持“当前系统已实现稳定开放式 RSI”。最强的共同负面证据是：留出迁移不稳定、持续搜索可能回退、跨 executor 泛化有限、不同经验整合路径没有通用赢家。
