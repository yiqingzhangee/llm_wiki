# 知识图谱驱动的深度研究Agent

> 关联来源：[[来源-DeepEvidence-生物医学知识图谱深度研究-2026]]

## 核心命题

当“deep research”进入高专业度领域，仅靠网页检索 + 长上下文总结通常不够。真正能支撑**多跳、可追溯、可复核**研究流程的，不是把更多文本塞给模型，而是让 Agent 站在**结构化知识图谱、统一工具层与外部记忆**之上工作。

[[来源-DeepEvidence-生物医学知识图谱深度研究-2026]] 给出的关键启示是：**知识图谱驱动的深度研究 Agent**，本质上是一种把“研究过程”外化为**可编排动作 + 可执行分析 + 可追踪证据图谱**的系统。

## 最小结构

### 1. 研究编排器

负责把开放问题拆成多步研究计划，并决定：

- 先广搜还是先深挖；
- 哪些实体/关系值得继续追踪；
- 当前证据是否足以回答问题；
- 何时停止，何时回溯。

### 2. 专职研究子 Agent

最常见是两类：

- **广度优先研究（BFRS）**：快速铺开候选实体、关系、文献与桥接点；
- **深度优先研究（DFRS）**：沿引文链、关系链与机制链条向下钻取。

这和 [[多Agent系统研究趋势与工程映射]] 中“协作拓扑 → 工程编排”的主线一致，但比一般的“多 Agent 分工”更进一步：其目标不是并行聊天，而是**围绕证据累积进行协作**。

### 3. 统一工具层

知识图谱驱动研究的关键，不在“有没有工具”，而在**是否有统一入口**：

- 统一实体检索；
- 统一关系搜索；
- 跨库 ID 对齐；
- 查询结果可落盘、可再分析。

否则 Agent 很容易退化为“会调用很多零散 API，但不会系统研究”。

### 4. 可执行分析环境

仅靠工具返回字符串摘要不够。真实研究往往需要：

- 批量查询；
- 结果清洗与归并；
- DataFrame / CSV 处理；
- 统计或规则校验；
- 中间结果持久化。

所以这类系统天然需要代码执行沙箱或等价的可编程环境。

### 5. 证据图谱记忆

这是与普通 deep research 最大的分水岭。

证据图谱不只是缓存，而是把以下对象显式记录下来：

- 实体（论文、基因、药物、疾病、试验、工具、基准）
- 关系（支持、反驳、引用、靶向、关联、上下游）
- 观察（定量结果、实验设定、筛选结论）
- 来源（哪篇论文 / 哪个数据库 / 哪次查询）

这样做的价值有三点：

1. **可追溯**：结论能回到来源；
2. **可累积**：跨轮研究不会只留在上下文里；
3. **可处理冲突**：相反结论可以并存，而不是被后来的总结悄悄覆盖。

## 相比普通网页型 Deep Research 的差异

| 维度 | 网页型 Deep Research | 知识图谱驱动 Deep Research |
|---|---|---|
| 主要知识源 | 网页、博客、文档、论文文本 | 结构化 KG + 文献 + API + 数据 |
| 研究动作 | 搜索、阅读、摘要 | 搜索、桥接、对齐、分析、持久化 |
| 中间记忆 | 上下文 / 文本笔记 | 证据图谱 / 结构化外部记忆 |
| 多跳推理 | 依赖上下文串联 | 依赖关系图与桥接实体 |
| 冲突处理 | 容易被摘要掩盖 | 可保留冲突边与来源 |
| 适用场景 | 通用信息检索、行业研究 | 生物医学、金融、代码、科研等高结构化领域 |

## 工程收益

### 1. 更适合长程任务

这类系统天然适合系统综述、临床试验更新、代码知识图谱研究、复杂技术调研等需要多轮证据累积的任务。

### 2. 更适合审计与复核

证据图谱 + 结构化观察，使“为什么得到这个结论”可被复查。这一点与 [[流量风控技能栈与Agent治理]] 中的可审计链路是同构的。

### 3. 更适合人与 Agent 协作

人类不必接收所有中间上下文，而可以查看被持久化的证据节点、关系链和中间表格，这比读一大段思维链更有效。

## 冲突与不确定性

- 不是所有领域都值得上知识图谱：如果任务短、源少、关系稀疏，普通检索 + 摘要就够，硬上 KG 只会增复杂度。
- 统一工具层的价值很高，但建设成本也高；如果底层知识源接口质量差、字段缺失严重，系统收益会被抵消。
- 证据图谱能提升可追溯性，但不自动保证正确性；图里也可能积累错边、错实体与错误桥接。

## 何时值得用

优先考虑以下场景：

- 需要跨多个结构化知识源对齐实体；
- 需要多跳推理，不止找“相关文档”；
- 需要把研究过程保存为可复用资产；
- 需要对结论做事后审计或冲突复核。
