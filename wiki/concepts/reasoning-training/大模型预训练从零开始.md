# 大模型预训练从零开始

> 范围：从随机初始化开始训练文本生成模型，采用稠密、仅解码器式 Transformer 与自回归目标作为入门主线。不是所有预训练架构的统一配方，也不是已执行的训练实验。整理日期：2026-11-02。

预训练用大量文本训练模型预测下一个 token。文本自己提供目标标签，预测误差通过反向传播改变参数；因此不需要逐句人工标注答案，但仍需要选择、清洗和组织数据。数据分布、模型容量、训练预算和评估共同决定结果。

## 一、先区分四件事

| 过程 | 起始权重 | 主要学习材料与目标 |
|---|---|---|
| 从零预训练 | 随机初始化 | 从广泛文本学习语言、知识与任务模式 |
| 继续预训练 | 已有预训练权重 | 用新增语言、领域或其他语料继续语言建模 |
| 指令微调 | 通常已有预训练权重 | 用提示与回答示例训练指令遵循 |
| 偏好或强化学习训练 | 通常已有模型权重 | 依据偏好或奖励改进回答行为 |

不同阶段可能使用相同的自回归损失，但数据分布、哪些位置参与损失和训练目的不同。LoRA是更新参数的方法，不是一个与预训练并列的数据目标；RAG是检索与生成的系统组合，不等于训练模型权重。后训练见 [[参数高效微调与对齐训练]]。

## 二、token是什么

模型不直接处理字符串。Tokenizer将文字映射成词表中的整数编号；每个token可能对应一个字、子词、标点或字节片段，不保证“一个中文字符等于一个token”。

```text
原始文本 → Tokenizer → 整数序列 → 词嵌入向量
```

入门可理解BPE的基本思路：从较小单元出发，根据训练文本中的频率反复合并相邻单元，形成固定词表。不同实现的初始单元、规范化和特殊符号处理不同。Tokenizer应在选定训练语料上拟合并固定版本。

词表越大，并不自动越好：它可能缩短序列，但也增加嵌入与输出层规模。应检查目标语言的编码长度、罕见字符、代码、数字和特殊符号，以及编码—解码是否符合预期。

## 三、模型到底在预测什么

下面使用教学token序列，不表示真实Tokenizer的切分：

```text
完整序列：开始符  我  爱  北京  结束符
模型输入：开始符  我  爱  北京
目标标签：我      爱  北京  结束符
```

输入与标签错开一个位置。模型读取“开始符、我、爱”，输出词表上的概率分布，目标是提高“北京”的概率。

记序列为$x_1,\ldots,x_T$，训练目标为：

$$
\mathcal L(\theta)
=-\frac{1}{M}\sum_{t\in\mathcal I}
\log p_\theta(x_t\mid x_{<t})
$$

其中$\mathcal I$是参与损失的位置集合，$M$是其数量；批训练时应在全部有效目标位置上汇总。Padding和其他明确不训练的位置要排除。公式里的对数通常是自然对数。

单个目标的预测概率从0.1增加到0.5时，该位置损失从约2.303降到约0.693。数字只是解释公式，不是实际模型测量。

模型并不是“先生成一句，再看整句错了多少”。标准训练通常输入真实前文，计算各位置预测，这称为教师强制。因果掩码禁止每个位置读取未来token，因此多个位置的训练预测可以并行计算；推理时则通常需要依次生成新token。进一步见 [[自回归掩码、解码与生成评测]]。

**实现检查**：确认模型或训练框架是否已经内部移动标签，避免手动移动一次后又被移动一次；对照每个位置的输入可见范围、目标索引与损失掩码。

## 四、Transformer怎样把编号变成概率

入门路径是：

```text
token编号
  → 词嵌入与位置信息
  → 多层因果Transformer
  → 输出词表上的logits
  → 概率与交叉熵
```

每个Transformer块主要包含注意力、前馈网络、归一化与残差连接。

- **注意力**让当前表示整合允许读取的前文；查询、键和值由输入投影得到。
- **前馈网络**对每个位置的表示做可学习的非线性变换。
- **位置信息**帮助区分顺序，可用位置嵌入或旋转位置编码等方式。
- **残差与归一化**帮助深层网络优化与稳定。

现代常见配方包含RMSNorm、RoPE、SwiGLU等，但它们不是理解预训练目标的前提。最初的Transformer论文是编码器—解码器结构，不能把其全部实现细节直接称为现代GPT架构。[原始架构摘要](../../sources/multimodal/来源-Transformer-Attention-Is-All-You-Need-2017.md)

没有加载已有预训练权重，才属于这里的“从零”。词嵌入、注意力、前馈和输出层等可学习权重共同训练；部分归一化参数可能按常量初始化，并不要求每个参数都随机。

## 五、一轮训练发生什么

1. **取数据**：读入一批token序列，构造位置、注意力与损失掩码。
2. **前向计算**：用当前参数得到每个位置的词表logits。
3. **计算损失**：对真实下一token计算交叉熵，按有效位置归一化。
4. **反向传播**：计算每个可训练参数对损失的梯度。
5. **更新参数**：优化器利用梯度与历史状态调整权重。
6. **监控与保存**：记录损失、吞吐与异常，定期验证并保存检查点。

AdamW、学习率预热后衰减、梯度裁剪和BF16混合精度是常见选择，具体配置取决于模型、数据和硬件。BF16不等于整个训练状态只有16位；优化器状态和某些计算可能保留更高精度。交叉熵通常应由稳定的logits接口计算，不手写容易下溢的“Softmax后取对数”。见 [[Softmax与交叉熵的浮点数值稳定性]]。

梯度累积是在多个微批次后执行一次更新，不增加单次前向的序列长度。跨微批与跨设备的损失归一化，应与有效目标token数量相匹配，不能在长度不同的时候无条件平均每批均值。

## 六、数据工程往往比训练循环更长

| 环节 | 要做什么 | 容易出错的地方 |
|---|---|---|
| 数据选择 | 明确语言、领域、质量、来源与使用条件 | 把来源多或体积大当作质量保证 |
| 文本清洗 | 去模板噪声、乱码与无效内容，检查敏感信息 | 过滤过度，损失少数语言或真实表达 |
| 去重与划分 | 识别重复及近重复，按文档或簇隔离训练和验证 | 同一文档切块后出现在两边 |
| 分词 | 固定Tokenizer及特殊符号约定 | 训练、评估和推理使用不同版本 |
| 序列打包 | 把token组织为指定长度，明确文档边界 | 将跨文档可见性默认为所有框架相同 |
| 混合采样 | 记录不同来源的比例与重复次数 | 数据集大小被误当成训练采样比例 |

文档结束符是边界提示，不会自动屏蔽跨文档注意力。是否允许同一打包序列中后一个文档读取前一个文档，是需明确的训练策略；若不允许，需要对应分段掩码和正确的目标损失处理。

训练token数是**实际消费量**，独立token数是**去重后可用量**。同一批语料读多遍会增加前者，却不等于新增独立信息。训练后期提高优质语料占比是一种可实验的方案，不能脱离数据、预算和固定评估集宣称必然有效。

## 七、参数、数据与算力怎样一起规划

用$N$表示参数规模、$D$表示消费的训练token数。在稠密Transformer、参数矩阵乘占主要开销的粗略假设下：

$$
C\approx 6ND
$$

它是前向与反向计算的数量级估算，省略长序列注意力、重计算、通信等开销；不同参数统计口径也会影响精度。对MoE不能直接用总参数数目套用。

例如，1亿参数消费20亿token，对应约$1.2\times10^{18}$次浮点运算。这个算术例子不是推荐配方，也不等于某张GPU上的实际耗时。

训练时间需要用端到端实测吞吐估算：

```text
预计训练秒数 ≈ 剩余训练token数 / 全系统每秒处理token数
```

同样，显存不仅放权重，还包括梯度、优化器状态、激活和临时缓冲；长上下文与大微批会增加激活压力。多卡训练可涉及数据并行、状态分片、张量并行和流水线并行，但应在单卡闭环正确之后逐步引入。

Chinchilla研究强调，在其固定训练计算预算与实验范围内，应同时增加模型规模与训练token数，不能只增大模型。[来源](../../sources/reasoning-training/来源-预训练入门-GPT3与Chinchilla.md) 这不等于“每个模型都必须训练固定倍数的token”：数据质量、推理成本、可用语料和研究目的都会改变取舍。

## 八、怎样判断训练有效

| 检查 | 能回答什么 | 不能证明什么 |
|---|---|---|
| 很小固定数据上明显拟合 | 前向、标签、梯度与更新是否形成基本闭环 | 全部实现正确或能泛化 |
| 独立验证集损失 | 对同一评估分布的预测是否改善 | 所有知识与推理能力都提高 |
| 生成样例 | 是否出现重复、乱码、失控长度等问题 | 少数好样例代表整体能力 |
| 任务评估 | 目标任务的能力与局限 | 污染的题目得分反映真实泛化 |
| 中断后恢复训练 | 检查点是否包含所需状态 | 换任意环境都可逐位复现 |

困惑度为$\mathrm{PPL}=\exp(\mathcal L)$，要求这里的损失是自然对数下的有效token平均负对数似然。不同Tokenizer或测试分布下的PPL不能直接当作统一能力排名。

监控还应覆盖梯度范数、异常值、学习率、token吞吐、数据来源采样和有效token数量。恢复长期训练通常需要模型权重、优化器、调度器、随机状态及数据进度等，而不只是权重文件。评测污染见 [[推理评测污染与捷径风险]]。

预训练模型更接近学会延续文本的基础模型；它未必可靠遵循指令，也不保证真实、无偏或善于使用工具。GPT-3论文展示了大规模自回归训练后通过上下文示例执行多种任务，也明确报告了局限；不能由此声称任何小模型都有同等能力。

## 九、从零练手的建议顺序

这是教学建议，没有执行训练或测量硬件需求。

1. **基础**：理解张量、矩阵乘法、概率、交叉熵、梯度与自动求导。
2. **数据**：完成一种Tokenizer、文档去重与独立验证划分，人工核对若干样本。
3. **模型**：实现或使用小型因果Transformer，验证每个预测位置的目标和可见前文。
4. **闭环**：先在很小固定数据上拟合，再扩大数据，观察训练与验证曲线。
5. **可恢复性**：保存、加载、继续训练，验证模型与数据处理版本一致。
6. **扩展**：实测吞吐与显存后，再尝试更长序列、更大模型或多卡训练。

可以将**1000万—5000万参数、256—512上下文长度、1000万—5000万训练token**作为可调整的教学探索范围。参数统计应包含所选架构的嵌入与输出层。这个范围用于观察训练过程，不是计算最优比例，也不承诺获得可用的通用助手。

建议先从**单GPU**练手，理由是消除多卡通信与分布式状态的复杂性；能否容纳具体配置取决于显存与实现，需要短程实测。没有硬件信息，不能给出确定时长、GPU型号或显存承诺。若目的只是获得一个能用的领域助手，应先比较已有模型的继续预训练、指令微调和检索增强成本。
