# 参数高效微调与对齐训练

> 关联来源：[[来源-LoRA低秩适配原理-2026]]、[[来源-GRPO分组相对策略优化原理-2026]]、[[来源-Qwen2.5与Qwen3微调深度调研-2026-06-21]]

## 核心问题

在 LLM / 多模态模型的后训练链路里，常见混淆不是“某个算法好不好”，而是把**不同层的问题混在一起**：

- **参数高效微调（PEFT）** 解决“怎么便宜地更新模型”；
- **偏好对齐 / 强化对齐** 解决“模型应该偏向什么行为”；
- **推理结构设计** 解决“模型应该如何组织思考与行动”。

LoRA 与 GRPO 经常同框出现，但它们分属不同层：前者更像**参数更新约束**，后者更像**策略优化规则**。

## 一条最小训练栈

### 1. 基座适配层：先让模型学会任务

这一层通常用：

- **SFT**：直接学习示范数据；
- **LoRA / QLoRA**：在不大幅增加算力成本的前提下完成任务适配。

它关注的是：模型**能否进入目标任务分布**。

### 2. 行为对齐层：再让模型偏向更想要的回答

这一层通常用：

- **DPO**：基于偏好对做直接优化；
- **GRPO / PPO**：基于奖励信号做策略优化。

它关注的是：模型**在多种可行回答里更偏向哪一种**。

对于长规则分类，可先比较 `pass@1` 与 `pass@k`：若多次采样能稳定覆盖正确答案，说明模型可能已有能力但策略不稳定，GRPO 才有较明确的介入理由；若 `pass@k` 仍低，应优先修数据、规则或基座能力。

奖励不应只覆盖最终标签。[[长多模态上下文的证据约束意图分类]] 给出一种分层形式：

```text
总奖励 = 标签奖励 + 证据奖励 + 格式奖励 + 长度奖励
```

证据奖励继续检查可回溯性、证据与类别一致性、证据强度和推理前后一致性。这样可以区分“答案错了”背后的证据幻觉、组合错误和规则误用，但新增奖励后仍需检查逐类表现及精确率—召回率取舍。

### 3. 系统治理层：最后把训练目标放回真实链路

这一层关注：

- 奖励是不是和业务目标一致；
- 线上是做“最终裁决”，还是做“触发增强审核 / 二审”；
- 成本是不是主要耗在参数更新、采样、奖励模型，还是人工复核。

这也是为什么 [[流量风控技能栈与Agent治理]] 里会把识别、处置、治理拆开：训练算法的优劣，最终必须落回链路位置。

训练栈还需要单独审计**损失函数的浮点路径**。高置信度 hard target 可能触发 Softmax Collapse，近教师 soft target 可能触发 Softmax Cancellation；这类问题不会因为更换 LoRA、DPO、GRPO 或优化器名称而自动消失。诊断不变量、稳定公式和框架版本边界见 [[Softmax与交叉熵的浮点数值稳定性]]。

## 方法分层表

| 层级 | 代表方法 | 主要解决什么 | 典型代价 | 常见误解 |
|---|---|---|---|---|
| 基座适配 | SFT | 让模型学会任务与格式 | 需要高质量示范数据 | 以为做完 SFT 就已经完成对齐 |
| 参数高效微调 | LoRA / QLoRA | 降低参数更新与显存成本 | 表达上限受 rank / 量化约束影响 | 把它误当成“对齐算法” |
| 偏好对齐 | DPO | 根据偏好对调整回答倾向 | 依赖偏好数据质量 | 以为不需要考虑 reward 或系统目标 |
| 强化对齐 | GRPO / PPO | 根据奖励信号优化策略 | 采样、奖励评估与稳定化成本高 | 只看训练曲线，忽视奖励设计偏差 |

## 外部特征接入与参数更新不是同一层

当统计特征、时序编码或视觉/图结构表示需要进入语言主干时，常需增加编码器、投影器或适配器，将外部表示变成连续 token 或侧路 memory。它解决“**外部信息怎样进入模型**”；LoRA/QLoRA 解决“**主干参数怎样低成本更新**”。二者可组合，但互不替代。

更稳健的训练顺序通常是：冻结主干，仅训练投影器/门控；在已验证输入通道有效后再叠加 LoRA；只有存在可复现容量瓶颈时才有限解冻或改造层间交互。参见 [[Qwen异构特征接入与事件序列建模]]：能传入 `inputs_embeds` 仅是接口可行性，不是业务效果或替代专用模型的证据。

## LoRA 与 GRPO 的关系

### 不是替代关系，而是可串联关系

一个常见但错误的问法是：“LoRA 和 GRPO 哪个更好？”

更准确的分解应是：

- **LoRA**：回答“训练时参数怎么省”；
- **GRPO**：回答“训练后期策略怎么调”；
- 它们可以串起来：**SFT + LoRA → 偏好 / 强化对齐（如 GRPO）**。

### 一个偏“静态参数增量”，一个偏“动态行为偏好”

- LoRA 假设任务增量可由低秩权重变化表达；
- GRPO 假设同题多答之间的**相对奖励排序**足以构造训练信号。

因此，前者更接近“模型内部怎么改”，后者更接近“模型输出应该往哪儿推”。

## 在本库中的两个典型落点

### 1. 视觉 / 多模态微调：LoRA 作为效率层

[[Stable-Diffusion微调技术矩阵]] 展示了 LoRA 在扩散模型里为何常成为默认起点：低成本、好迁移、好组合。这一逻辑同样适用于语言模型和部分多模态模型。

### 2. 推理 / GUI Agent 对齐：GRPO 作为策略层

[[来源-Qwen2.5与Qwen3微调深度调研-2026-06-21]] 与 [[来源-视频审核与电商风控GUI-Agent批次-2026]] 共同表明，GRPO 已不只是“论文名词”，而是在**推理类对齐**与**GUI Agent 行为学习**里开始落地的强化优化工具。

## 冲突与不确定性

- 当前两条新增 raw 都是**解释型材料**，足够支持概念分层，但不足以独立支撑不同算法的严格性能排序。
- LoRA 在不同模型家族里的最佳注入位置差异较大；GRPO 在不同奖励模型、采样规模、任务难度下的稳定性也差异明显，不能抽象成单一通用配方。
- 本页强调的是**训练栈结构**，不是统一 benchmark 结论；若要做真实选型，还需回到任务、数据、奖励与上线链路。
