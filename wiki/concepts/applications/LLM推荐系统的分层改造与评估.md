# LLM 推荐系统的分层改造与评估

> 关联来源：[[来源-LLM推荐技术范式与落地边界-2026]]。

## 核心命题

LLM 在推荐系统中的合理定位不是替代整条主链路，而是按其擅长的**开放语义、复杂条件理解与交互编排**分层进入；协同关系建模、目录约束与低时延服务仍应由专门模块和确定性控制面承担。是否“更好”必须同时经过效用、生成可靠性、治理鲁棒性和系统在线四层验证。

## 分层责任图

| 层 | LLM 的合理职责 | 应保留的专门能力 | 上线前关键问题 |
|---|---|---|---|
| 离线数据 | 摘要、标签、内容向量、用户语义画像、训练数据 | 清洗、时序切分、隐私与数据质量治理 | 是否改善冷启动而未泄漏未来信息？ |
| 表征与索引 | 文本/多模态语义表征、行为表征融合、Semantic ID | 向量检索、目录映射、索引更新 | 语义压缩是否丢失关键协同邻域？ |
| 召回与排序 | 小候选池重排、受约束候选生成、列表级偏好目标 | 全库召回、实时排序、库存与业务规则 | 候选是否合法、时延可控、能否确定性回退？ |
| 交互与编排 | 意图理解、条件澄清、解释、工具调用 | 召回/排序服务、政策校验、状态存储 | Agent 是否把工具职责和生成职责混淆？ |
| 治理控制面 | 辅助审计、解释与异常归因 | 规则、权限、监控、实验平台、人工兜底 | 失败能否发现、隔离、回滚与复盘？ |

## 三条改造路线

### 1. 语义增强：默认起点

在不改变成熟主链路的前提下，LLM 提供离线内容理解、用户画像、冷启动特征或教师信号。这一路线最容易做增量实验，也最容易保留召回、排序、库存和安全的确定性边界。

### 用户表征基础模型：表征层能力而非第四种系统范式

[[LLM用户表征基础模型与场景适配]] 将多源历史编码成静态、量化或 query/指令条件化的用户向量，主要服务离线画像、检索特征与受控重排。它不同于物品表示、全库召回、实时排序和生成式候选：即使用户 embedding 在离线任务上提升，也仍须单独验证候选覆盖、目录/库存约束、p95/p99 与线上因果价值。量化用户 token 也不等同于物品 Semantic ID；前者首先解决长历史压缩与更新容量，后者还承担目录编码与受约束解码问题。

### 2. 受约束生成：架构取舍

Semantic ID 或列表生成把部分推荐改写成序列建模，有利于语义共享和统一接口；但 token 化会引入码本、可逆性和前缀剪枝问题。应以目录合法率、候选召回损失、解码时延和长尾偏差评估，而不只看离线排序分。

[[万物皆可Tokenization：统一接口、离散化与连续建模]] 补充了 2026 年 Semantic ID 路线的分化：长 ID 压缩、软路由变长 ID、时间间隔 token、投影残差量化，以及用 SimHash + 并行解码反驳“复杂 learned tokenizer 必然更优”。这些工作共同说明 tokenizer、解码器和语义对齐应作为一套接口联合评估。

### 3. 智能体编排：交互层能力

推荐 Agent 最适合在高价值、多轮、条件复杂的入口负责理解与编排；专业推荐服务仍应是工具。它与 [[Agent任务分流：工作流与智能体边界]] 的原则一致：确定性、高频、错误成本高的部分应留在 workflow/服务控制面，而把开放式解释和澄清交给 Agent。

## 三种“统一”与输出边界

[[来源-RecFormer-P5-M6Rec推荐数据文本化-2026]] 提醒：推荐数据进入语言模型时，至少要区分三种统一。

| 统一对象 | 代表路线 | 工程含义 |
|---|---|---|
| 输入表示 | RecFormer | 属性与历史可文本化并恢复字段/物品位置；常仍走向量检索 |
| 任务接口 | P5 | 多任务可共享 prompt 与 input→target 格式；不意味着每个任务都适合生成 |
| 主干与输出 | M6-Rec | 同一骨干可按任务接分类头或自回归出口 |

闭集 CTR/CVR、风险分类或固定评分优先使用隐藏状态加分类头，以便校准、低延迟与确定性策略消费；解释、摘要、开放对话才需要生成出口。文本化本身也不是数值、顺序和缺失结构无损的证明，需与 [[Qwen异构特征接入与事件序列建模]] 的专用通道和强基线比较。

## 四层证据栈

| 证据层 | 核心问题 | 指标示例 |
|---|---|---|
| 离线效用 | 能否重现/改善历史偏好？ | Recall、NDCG、MRR、AUC/GAUC |
| 生成可靠性 | 输出是否可服务且满足用户条件？ | 目录合法率、条件命中、事实一致性、幻觉率 |
| 鲁棒与治理 | 输入、群体和协议变化下是否稳定？ | 提示/顺序稳定性、长尾覆盖、多样性、公平性 |
| 系统与在线 | 价值能否以可接受成本兑现？ | p50/p95/p99、吞吐、成本、失败率、CTR/CVR/GMV/留存 |

任何只在“1 正 + 少量负例”候选池上得出的结果，最多证明局部重排能力，不能替代全库检索、长期反馈或真实经营价值的结论。

## 与训练与治理的关系

- [[参数高效微调与对齐训练]]：LoRA/SFT 可以减小推荐任务适配成本；DPO/GRPO 类偏好优化则会把奖励与曝光偏差带入系统，需与线上因果评估配合。
- [[多模态嵌入与检索基座]]：内容与多模态表征可以增强冷启动与语义召回，但不能替代用户行为序列和业务约束。
- [[流量风控技能栈与Agent治理]]：二者共享“开放模型给出语义证据，确定性规则/服务承担最终裁决”的责任分层；推荐中的目录、库存、政策约束相当于不可绕过的控制面。

## 结论边界

公开研究显示 LLM 能带来场景依赖的增益，尤其在冷启动、复杂条件、解释与交互方面；目前不足以支持“LLM-only 是推荐系统通用最优架构”。工程决策应从已验证瓶颈、候选规模、服务预算和错误成本出发，逐层扩张，而非先进行全栈生成式重构。
