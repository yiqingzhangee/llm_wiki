# 风控表格数据编码器的自监督学习目标设计

> 证据来源：[[来源-风控表格编码器自监督目标公开文献调研-2026]]
>
> 关联主题：[[表格数据深度学习]] · [[Qwen3-VL统计特征编码器选型-2026]] · [[风控行为序列表征的自监督学习目标设计]] · [[风控表征学习中的生成机制、风险定义与表征分工]] · [[压缩表征的事实保真与关系可读性]]

## 一句话结论

风控表格编码器不应直接照搬图像增强或只追逐单一预训练榜单。首轮实验建议采用**类型感知的遮蔽字段建模**，再增加 VIME 式 corruption detection 辅助头；只有在字段扰动可以证明不改变风险语义时，才加入行级对比学习。低标注冷启动、跨表迁移和缺失值插补应分别使用自生成任务、跨表目标和重遮蔽目标，不宜混成一个默认方案。

纯自监督目标学习字段依赖、缺失结构和扰动不变性，不会自行定义风险。风险相关字段保护、策略引导采样和按业务重要度加权属于领域先验或弱监督层，应与纯自监督基线分开报告。

## 证据裁决

- **[CONFIRMED]** 通用表格自监督主要分为预测式、对比式和混合式目标；VIME、SCARF、SAINT、STUNT、TransTab 等原论文给出了不同实现。
- **[CONFIRMED]** 树模型在典型中型表格上仍是强基线；自监督预训练不能替代 CatBoost、LightGBM 或 XGBoost 对照。
- **[MAJORITY]** 遮蔽或扰动目标在标签稀缺、字段缺失或输入退化场景更有机会产生收益，但效果依赖数据集和缺失机制。
- **[SINGLE-SOURCE]** 企业信用评级研究显示 Feature Masking、Feature Swapping 与对比预训练可能改善少数类表现；该证据来自单一场景，不能外推为一般风控结论。
- **[CONFIRMED]** 对表格异常检测，已有系统实验发现自监督表示总体不优于原始特征。若目标是无监督异常检测，必须把“不做编码”作为正式基线。

## 为什么风控表格需要单独设计目标

一行风控表格通常混合数值、类别、计数、时间窗统计、缺失状态和治理元数据。与图像不同，字段位置、取值范围和可扰动语义并不对称：

1. 金额、次数、比例和类别不能共享同一种重建损失。
2. 原生缺失可能本身是风险信号，不能与人工遮蔽合并处理。
3. 从其他行替换字段可能制造业务上不可能的组合。
4. 低频关键字段容易被平均重建损失淹没。
5. 同实体、同团伙或同风险模式的样本可能被错误地当作对比负样本。
6. 聚合窗口、统计截止时间和标签成熟时间若未对齐，预训练也会放大未来泄漏。

因此，自监督目标首先是一份**数据语义合同**，其次才是损失函数。

还需区分两类表格输入：

- **同源统计**：由同一事件序列、同一窗口和同一截止时点确定性聚合，属于序列的有损摘要；
- **外部表格**：画像快照、跨实体聚合、图特征、外部名单或设备状态，可能提供序列中没有的新信息。

只有前者适合用“序列与统计互预测”检查压缩保真。不能把所有表格字段都视为可从行为序列免费生成，也不能用未来扩展窗口监督当前表示。

## 目标族与适用场景

| 目标族 | 学习信号 | 代表工作 | 适合场景 | 主要风险 |
|---|---|---|---|---|
| 遮蔽字段重建 | 从可见字段恢复人工遮蔽字段 | TabNet、MET、ReMasker | 标签稀缺、缺失鲁棒、字段依赖学习 | 学到高频/易恢复字段，忽略风险相关字段 |
| 重建 + corruption detection | 同时恢复原值并判断哪些字段被替换 | VIME | 需要识别输入可靠性或异常扰动 | 替换分布过于简单，模型只识别伪影 |
| 行级对比 | 拉近同一行的两个合法视图，推远其他行 | SCARF、SAINT | 需要稳定行向量、标签较少 | 假负样本、语义破坏、依赖大 batch |
| 字段子集一致性 | 同一行不同字段子集产生一致表示 | SubTab、TransTab | 字段缺失、schema 增量、跨表迁移 | 部分字段不足以决定语义时强制错误不变性 |
| 潜空间预测 | 用可见字段潜表示预测被遮蔽字段潜表示 | T-JEPA | 原值噪声大、重建被尺度主导 | 表示坍塌、训练与诊断更复杂 |
| 自生成伪任务 | 随机选列并聚类形成伪标签，执行元学习 | STUNT | 新风险任务、few-shot 冷启动 | 伪任务与真实任务错配 |
| 共享/特有信息解耦 | 分离跨样本共享因素与样本特有因素 | SwitchTab | 探索结构解耦 | 组件多，收益难归因 |
| 跨表共享主干 | 表私有输入层 + 跨表共享编码器 | XTab | 多市场、多产品、schema 不一致 | 列语义错配、预训练域负迁移 |

## 推荐的第一版目标

### 1. 类型感知遮蔽字段建模

对一行输入 `x` 采样人工遮蔽集合 `M_artificial`，编码器只观察未遮蔽字段。损失仅在人工遮蔽位置计算：

```text
L_masked =
  Σ 数值字段 w_j · Huber(x_j, x̂_j)
  + Σ 类别字段 w_j · CE(x_j, x̂_j)
  + Σ 分箱字段 w_j · CE(bin_j, b̂in_j)
```

关键约束：

- 数值字段优先使用稳健回归；长尾数值可增加分位数分箱分类头。
- 类别字段使用字段独立词表，保留 `UNK`、`MISSING` 和 `MASK` 三种不同状态。
- `M_native` 与 `M_artificial` 分开输入；自然缺失不参与“恢复已知真值”的损失。
- 每个字段先做损失归一化，再按采样频率或重建难度校正，避免高方差数值字段支配训练。
- 若按业务风险重要度调整遮蔽率或损失权重，应将其标为领域引导或弱监督实验，并与不使用风险先验的版本对照。
- 统计窗口和可用时间进入字段元数据，预训练切分与下游任务使用同一时间边界。

### 2. Corruption detection 辅助头

在人工替换字段上增加二分类头，预测字段是否被污染：

```text
L = L_masked + λ_corrupt · BCE(m_artificial, m̂)
```

它比单纯重建多问了一个问题：编码器是否知道输入中的哪部分不可信。替换值应来自同字段、相近时间和兼容业务状态的训练数据；不能跨未来分区取值，也不能把内部编码或缺失哨兵当作捷径。

### 完整输入保真探针

遮蔽重建检查字段依赖，不证明最终行向量保留了每个已出现字段。首版训练可不把保真探针加入损失，但验收时应从完整输入的压缩表示读取字段值，并分开报告低频字段、原生缺失状态和语义关键字段。

字段间比较、比率和约束关系先作为探针。只有稳定发现某类关系不可读，并确认它影响下游任务后，再将关系目标加入训练。否则，额外损失容易增加优化冲突，却没有可验证收益。详见 [[压缩表征的事实保真与关系可读性]]。

### 3. 受约束行级对比

只有前两项达标后才增加：

```text
L_total = L_masked + λ_corrupt · L_corrupt + λ_contrast · InfoNCE(z, z+)
```

正样本视图只允许以下操作：

- 遮蔽非关键冗余字段；
- 在同一字段合法范围内做小幅数值扰动；
- 删除可证明不影响标签语义的派生字段；
- 对重复统计窗口做受控 dropout。

以下字段默认禁止扰动：决定性风险事件、策略结果、处置状态、标签代理、金额方向、身份与实体关联字段。负样本池排除同实体、同事件链、已知关联主体和高相似风险簇，降低假负样本。

## 场景化选择

### 同源序列与统计联合预训练

可以用序列表征预测同窗统计族，检查水平、波动、尾部、结构、趋势和持续性信息是否被保留；也可以用统计表示预测序列池化表示，约束全局尺度。该任务提高的是压缩保真，不会凭空补回统计量中不存在的顺序和路径。

完整的双向对齐并非默认安全。若强制序列表征贴近统计表示，编码器可能丢掉统计量无法表达的顺序与绑定。优先采用分族的 `Seq → Stats` 预测头，并同时监控顺序和关系探针；只有消融证明无损后，再考虑反向对齐。

多尺度窗口必须共享同一右端截止时间。由于短窗被长窗确定性包含，建议预测近期增量、相对长窗的残差或趋势，而不是直接回归长窗总量。按统计族分别报告误差，避免总量或活跃度掩盖其他结构。

Level–Shape 解耦可作为可检验假设：将总量水平与比例、熵、趋势分支分开，观察是否改善时间外探针和校准。但绝对水平也可能具有风险价值，不能预设 level 分支只是应被剔除的干扰。

### 标签稀缺或新任务冷启动

优先比较 STUNT 式自生成任务与普通遮蔽重建。前者的价值在于学习“如何用少量支持样本快速定义新任务”，而非追求统一静态表示。验收应使用新任务、新时间段和新实体，而不是随机行切分。

### 跨市场、跨产品或 schema 演进

使用 TransTab/XTab 类目标前，先建立字段语义注册表：

- 字段名、类型、单位、窗口、来源和缺失含义；
- 可合并、可共享和禁止对齐的字段组；
- schema version 与训练时间；
- 跨域迁移时的冻结、重置和校准策略。

跨表预训练的成功标准是新表少样本适配和 schema 增量稳定性，不是源表训练损失降低。

### 缺失值插补

ReMasker 类“自然缺失 + 额外重遮蔽”适合单独训练插补器。其插补精度不能直接证明下游风险分类更好；应分别报告插补误差、下游指标、校准和最差缺失模式。

### 无监督异常检测

默认先比较原始特征上的 k-NN、Isolation Forest、LOF 和树模型派生方法。自监督表示只有在时间外异常、依赖结构异常或局部异常切片上稳定提升，且没有引入冗余维度时才保留。

## 风控特有的失败模式

| 失败模式 | 表现 | 检查方法 | 修复方向 |
|---|---|---|---|
| 未来泄漏 | 离线收益大，时间外崩溃 | 按字段审计可用时间，时间切分预训练语料 | 截断数据快照，移除后验字段 |
| 原生缺失与人工遮蔽混淆 | 缺失人群校准异常 | 分别评估原生缺失与完整样本 | 双 mask、独立 embedding |
| 风险关键字段被增强破坏 | 少数类召回下降 | 按字段禁用增强消融 | 关键字段保护清单 |
| 对比假负样本 | 同风险簇表示被推远 | 实体/关系/聚类去重 | 多正样本或软负样本 |
| 重建捷径 | 预训练损失低但探针无收益 | 单字段、字段置换、mask-only 探针 | 提高条件难度，重加权字段 |
| 频率支配 | 高频正常模式主导表示 | 按频率桶检查梯度与误差 | 字段/样本重加权 |
| 业务不可能扰动 | corruption detection 近乎满分 | 人审扰动样本与规则校验 | 条件采样、因果约束 |
| 跨表负迁移 | 源域提升、目标域下降 | leave-one-table/domain-out | 表私有适配器、选择性迁移 |

## 最小实验矩阵

固定同一编码器、优化器、切分和训练预算，只改变目标：

1. CatBoost/LightGBM；
2. 同一深度编码器从头监督训练；
3. 纯去噪自编码器；
4. 类型感知遮蔽重建；
5. 遮蔽重建 + corruption detection；
6. 第 5 项 + 受约束行级对比；
7. 仅在对应场景加入 STUNT、TransTab/XTab、ReMasker 或 T-JEPA。

每项至少报告：

- PR-AUC、固定误报率下召回、KS、Brier/ECE；
- 时间外、实体外、新 schema 和低频风险切片；
- 线性探针、浅层 MLP、k-NN 或检索、全量微调等逐级读出；
- 多随机种子均值与波动；
- p95/p99 时延、吞吐、显存和训练成本；
- 字段置换、去 missing mask、描述错配和关键字段保护消融。

## 停止条件

出现任一情况即不继续增加目标复杂度：

- 未稳定超过同主干从头训练；
- 未超过树模型，且没有跨任务复用、缺失鲁棒或多模态融合价值；
- 随机切分提升但时间外/实体外无收益；
- 置换字段或错配 schema 后性能几乎不变；
- 少数类、校准或最差业务桶退化；
- 对比学习需要不可接受的 batch、延迟或样本治理成本；
- 自监督表示用于异常检测时不优于原始特征。

## 最终建议

默认从“**类型感知遮蔽重建 + corruption detection**”开始。这一组合目标清晰、易诊断，并能把字段依赖学习和输入可靠性识别分开。对比学习、潜空间预测、自生成任务和跨表预训练都应由具体瓶颈触发，不应作为首轮默认复杂度。

该建议的目标是保留和组织字段信息，不是让编码器直接学习风险边界。风险定义仍由下游标签、代价敏感目标、阈值校准和治理流程承担。
