# 风控模型训练、部署与监控生命周期

> 来源依据：[[来源-风控模型安全部署与监控内部实践-已脱敏-2026]]
>
> 相关验证：[[来源-LLM推荐向风控迁移机制与验证路径-2026]]

## 核心问题

风控模型上线不是把训练制品复制到推理服务。这条链路还要回答四个问题：

1. 训练与推理是否执行同一套特征语义；
2. 模型制品能否被目标服务正确加载；
3. 资源和性能是否承受预期流量；
4. 上线后的分数与业务代理指标是否持续处于可解释范围。

这些问题分属不同控制面。离线指标良好不能替代部署验证，服务成功加载也不能替代线上分布监控。

## 生命周期

```text
训练空间
  → 特征表达式校验
  → 样本生成
  → 训练、校准与评估
  → 制品序列化和注册
  → 推理资源评估
  → 隔离测试服务加载
  → 压测与性能门禁
  → 生产部署与在线因子注册
  → 版本管理、灰度、监控与回退
```

每个阶段都应产生明确状态和可检查产物。任一门禁失败时停止推进，而不是把异常留给后续阶段吸收。

## 训练与推理的特征一致性

训练侧和在线侧使用同一套特征执行 SDK，可以减少表达式在不同语言或系统间翻译造成的语义漂移。统一执行仍不能自动保证一致性，还需要以下约束：

- 特征配置使用表达式列表，而不是依赖换行拆分的长字符串；
- 单个表达式可包含多行逻辑，并明确定义返回值；
- 初始化阶段校验语法、依赖和返回类型，错误时快速失败；
- 样本查询显式加载特征参数、公共参数与标签；
- 样本生成后抽查特征值，线上前再核对模型注册所依赖的特征集合。

统一 SDK 解决的是执行路径差异，不解决时间穿越、数据版本、缺失值或统计口径问题。这些仍要由数据契约和回放测试约束。

## 训练与注册

训练空间应把运行环境、任务状态和指标放在同一上下文中。典型阶段包括：

| 阶段 | 主要产物 | 最低检查 |
|---|---|---|
| 资源准备 | 可复现运行环境 | 依赖版本、计算资源和数据访问 |
| 样本生成 | 训练与测试数据 | 时间边界、标签可用性、特征完整性 |
| 训练与校准 | 模型和校准器 | 训练稳定性、校准误差、最差切片 |
| 评估 | 离线评估结果 | 时间外切分、成本指标、延迟与资源 |
| 序列化 | 模型制品 | 格式、大小、依赖和完整性 |
| 注册 | 可追踪模型版本 | 制品位置、特征清单、配置和状态 |

迁移训练后端时，训练、校准与评估 API 可以保持稳定。平台选择、特征表达式和样本查询契约应显式版本化。这样可以避免兼容逻辑散落在训练代码中。

## 安全部署门禁

模型部署常见风险包括资源不足、流量估计偏差、制品格式错误和加载时异常。这些问题可能造成加载失败、服务过载或进程崩溃。部署流水线应按以下顺序设置门禁：

1. **资源评估**：检查生产推理服务是否有足够的 CPU、内存和实例容量；
2. **隔离加载**：先把模型加载到测试服务，验证格式、依赖和初始化行为；
3. **性能压测**：测量吞吐、延迟、资源水位和错误率；
4. **生产部署**：门禁通过后再进入生产环境，记录每个实例的加载状态；
5. **在线注册**：部署完成后注册模型因子，并核对在线特征与训练特征；
6. **灰度与回退**：逐步切换版本，保留旧版本和可执行的回退路径。

自动推进不等于取消控制。资源不足、加载异常、性能不达标或特征不一致时，流水线必须停止并保留诊断信息。

## 模型管理与监控

上线后的管理对象包括模型版本、部署记录、在线因子、特征重要性和运行指标。监控既要覆盖工程健康，也要覆盖模型行为：

| 类别 | 示例 | 作用 |
|---|---|---|
| 工程指标 | QPS、延迟、超时率、错误率、资源水位 | 发现服务容量和依赖异常 |
| 模型指标 | 分数分布、命中率、拦截率 | 发现输入漂移、模型异常或策略影响 |
| 特征指标 | 缺失率、值域、重要性、在线取值失败 | 定位特征生产和数据契约问题 |
| 发布指标 | 版本流量、加载状态、回退状态 | 判断灰度和版本切换是否正常 |

告警规则可统一表示为：

```text
规则 = 指标 + 观测窗口 + 聚合函数
     + 对比时间偏移 + 比较函数 + 阈值 + 接收人
```

对比偏移为零时，规则检查当前窗口的绝对值；对比历史窗口时，规则检查相对增减。绝对阈值用于捕捉越界，相对变化用于捕捉分布突然偏移，因此两类告警应同时保留。

告警管理需要查询、创建、更新和删除能力。更新后应回读确认，删除等高风险操作要求显式确认并保留审计记录。

## 验收清单

- 训练和在线特征由同一执行契约描述，并完成样本与在线取值核对；
- 模型制品经过隔离服务加载，不直接进入生产主链；
- 压测覆盖目标流量、尾延迟、资源上限和错误路径；
- 生产部署有逐实例状态、灰度范围和回退操作；
- 在线模型因子与训练特征清单一致；
- 工程、模型、特征和发布四类指标都有监控；
- 告警同时覆盖绝对越界和相对历史变化；
- 版本切换、告警修改与删除均可审计。

## 证据边界

本页来自一份内部工程实践的脱敏提炼。材料记录了一种可操作的生命周期设计，但没有提供跨系统对照、长期故障统计或独立复现实验。具体资源阈值、压测时长、灰度比例和告警参数，应根据目标系统的流量、SLO、错误成本与历史分布确定。
