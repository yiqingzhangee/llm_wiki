# 事件序列编码器的自监督联合预训练

> 核心来源：[[来源-序列编码器自监督联合训练内部实践-已脱敏-2026]]
>
> 相邻方法：[[BERT4Rec数据处理与输入张量]]、[[LLM用户表征基础模型与场景适配]]、[[Qwen3-VL事件序列编码器选型-2026]]

## 核心结论

事件序列编码器可以联合使用对比目标和掩码恢复目标。对比目标约束同一条序列的不同增强视图保持一致，掩码目标要求模型保留事件级信息。两者关注的表示性质不同，联合训练时应分别监控，不能只看加权总损失。

这类预训练适合标签稀缺、下游任务较多或需要离线复用序列向量的场景。它不会自动保证跨任务迁移、冷启动或异常识别收益。有效性仍需通过时间外数据、线性探针、最近邻或聚类结构以及具体下游任务验证。

## 输入与编码器

设一条事件序列为：

```text
x = [e_1, e_2, ..., e_L]
```

每个时间步可以包含事件类型、时间信息和数值或枚举属性。推荐先在时间步内完成特征编码，再交给序列主干：

```text
event_features
  → feature encoders
  → per-step projection
  → position / time representation
  → bidirectional Transformer encoder
  → mask-aware pooling or designated readout
  → projection head
  → sequence embedding
```

位置表示负责区分顺序。若任务依赖不规则时间间隔，还应单独编码时间差或事件年龄，不能假设绝对位置已经表达真实时间。

投影头只负责把主干输出映射到训练和服务所需的向量空间。它不应承担原始特征清洗、时间排序或 padding 语义。

## 联合训练目标

### 对比目标

从同一原序列构造两个增强视图 `x^a` 和 `x^b`：

```text
z_a = g(f(x^a))
z_b = g(f(x^b))
```

其中 `f` 是序列编码器，`g` 是投影头。InfoNCE 类目标提高正样本对的相似度，并降低与批内或记忆库负样本的相似度：

```text
L_con = -log exp(sim(z_a, z_b) / τ)
              --------------------------------
              Σ_j exp(sim(z_a, z_j) / τ)
```

增强必须尽量保留序列语义。可从掩码位置或掩码强度入手，但应验证增强后样本是否仍代表同一实体状态。随机打乱顺序、删除关键事件或大幅改变时间间隔可能制造错误正样本。

内部材料把这一项描述为 MoCo 式对比学习，但已读取内容没有说明是否实际使用动量编码器、负样本队列或具体更新规则。因此，这里只保留 InfoNCE 类目标，不将某个 MoCo 实现细节写成既定事实。

### 掩码恢复目标

对输入序列的部分事件或属性做遮蔽，让编码器从双向上下文恢复原目标：

```text
L_mask = CE(p(target | masked_sequence), target)
```

材料将这一项简称为 MSM，但没有公开目标是事件 ID、单个属性还是组合标签。工程实现必须明确：

- 遮蔽单位是整事件、事件类型还是字段；
- 标签空间与特殊 token 是否分离；
- padding 和未选中位置是否从损失中排除；
- 连续字段使用分类、分桶还是回归目标；
- 训练 mask 与推理输入之间是否存在分布差异。

若输入是纯离散 item ID，[[BERT4Rec数据处理与输入张量]] 给出了成熟的 Cloze 数据契约。多特征事件序列则需要额外定义字段级遮蔽和恢复头。

### 组合损失

联合目标可写为：

```text
L = λ_con L_con + λ_mask L_mask
```

权重应通过验证集选择，不宜照搬其他任务。训练日志至少分别记录 `L_con`、`L_mask`、正负样本相似度、有效 mask 数量和表示方差。总损失下降时，某一分支仍可能失效。

## 多来源联合训练

多来源数据可以扩大行为覆盖面，但简单拼接容易让高频来源主导梯度。联合训练前应固定以下契约：

| 问题 | 建议 |
|---|---|
| 时间边界 | 所有来源按统一预测截止时间截断，禁止未来信息进入输入 |
| 事件语义 | 同名事件先校准定义，不同语义不要强行共用 ID |
| 采样 | 记录来源占比、实体去重规则和长尾重采样策略 |
| 序列长度 | 分来源报告截断率、padding 比例和有效时间跨度 |
| 增强 | 检查每种来源的掩码是否仍保留足够上下文 |
| 验证 | 同时报总体、分来源和时间外结果 |

来源标识可以用于分桶审计，不应默认成为模型输入。否则模型可能通过来源捷径区分样本，而没有学习事件动力学。

## 训练与检查点选择

推荐流程：

1. 按实体和时间排序，确定预测截止点，再构造窗口；
2. 完成事件映射、缺失处理、截断和 padding；
3. 为每条序列生成两种语义保持的增强视图；
4. 在其中至少一个视图上构造掩码恢复标签；
5. 联合优化对比项与恢复项，并分别记录诊断指标；
6. 定期冻结编码器，运行线性探针、检索或聚类评估；
7. 按时间外和下游指标选择检查点，不默认使用最后一轮。

内部实践观察到，继续训练未必改善表示空间的可分结构。这个现象只说明预训练损失与表示质量可能不同步，不能据此推导固定的最佳轮数。

## 表示质量验收

| 层次 | 问题 | 示例检查 |
|---|---|---|
| 优化 | 两个目标是否都在学习 | 分项损失、梯度、表示方差、相似度分布 |
| 信息保留 | 向量是否保留事件内容 | 掩码恢复、属性探针、顺序扰动 |
| 可迁移性 | 简单模型能否读取任务信号 | 冻结编码器后的线性探针 |
| 几何结构 | 近邻和簇是否稳定 | 最近邻一致性、簇纯度、轮廓指标 |
| 时间稳定性 | 表示能否跨窗口复用 | 时间外探针、邻域漂移、质心迁移 |
| 下游价值 | 是否超过简单基线 | 分类、检索或排序任务的同预算比较 |

PCA、t-SNE 等降维图适合发现异常结构，不适合作为单独的检查点选择依据。二维图形会改变距离关系，且容易受抽样与参数影响。

## 大规模聚类与漂移

当全部向量无法一次装入内存时，可以用 mini-batch 或 streaming KMeans 逐批更新质心。该方法把内存占用限制在当前批次和质心集合，但结果仍受初始化、批次顺序、样本分布和簇数影响。

聚类属于表示分析或候选发现步骤，不是编码器训练目标本身。固定质心跨时间使用时应检查：

- 新窗口到旧质心的距离分布；
- 最近质心与次近质心的间隔；
- 簇规模、密度和来源构成变化；
- 旧质心与滚动窗口重训质心的匹配关系；
- 下游探针在不同时间窗的校准变化。

若漂移明显，应先区分输入分布变化、编码器版本变化和聚类器陈旧，再决定刷新质心或重训编码器。

## 与相邻方案的关系

| 方案 | 主要监督 | 适用位置 | 与本方法的关系 |
|---|---|---|---|
| 单层 GRU + 分类头 | 下游标签 | 短序列强基线 | 先验证监督基线是否已足够 |
| BERT4Rec | 离散 item 的 Cloze 目标 | 推荐或离散事件预测 | 对应联合目标中的掩码恢复分支 |
| 对比式序列预训练 | 增强视图一致性 | 多任务复用 | 对应联合目标中的对比分支 |
| 联合预训练 | 对比目标 + 掩码恢复 | 标签少且需要迁移 | 同时约束全局表示与局部信息 |
| Qwen soft token 接入 | 下游任务损失 | 与语言模型联合建模 | 预训练向量可作上游输入，但需单独验证接口收益 |

[[Qwen3-VL事件序列编码器选型-2026]] 的 GRU 方案仍是短序列首版基线。只有当多任务复用或低标签性能成为明确瓶颈，并且监督基线已经稳定后，才值得增加自监督 Transformer 预训练。

## 常见失效

- 同一实体的两个视图实际跨越不同预测时点，形成未来泄漏；
- 增强过强，正样本已不再语义等价；
- 负样本中存在同状态实体，导致假负样本；
- 模型只识别来源、序列长度或 padding 模式；
- 掩码恢复头学习高频事件，序列向量却缺少下游信号；
- 对比损失下降但表示方差收缩，出现坍塌迹象；
- 只用降维图判断质量，没有时间外探针或下游对照；
- 固定聚类质心长期复用，却没有漂移监控；
- 最后一轮训练损失最低，因此被直接当作最佳检查点。

## 证据边界

核心来源是一份单一内部实践材料，适合说明一种工程设计及其诊断方法。材料中的数据构成、模型配置、资源消耗、效果数字、阈值、日期和真实案例均未保留。当前证据支持把联合目标作为候选训练框架，不支持声称它普遍优于监督 GRU、单独掩码建模或其他序列模型。
