## 核心命题

用户表征基础模型将多源历史压缩为可复用表示，服务用户定向、推荐、营销和风险等不同下游；它不是这些下游的替代品。有效设计必须同时回答：历史如何与未来目标隔离、异构信号如何保真、同一用户怎样随任务变化、长历史如何在成本内保留，以及表征如何被安全地接回确定性业务链路。

## 表示接口与服务边界

**静态表示**适合一个稳定的下游接口或离线特征库；**条件化表示**适合一个用户在多个意图、任务或策略下被重新解释。Query 尾置可复用用户前缀 KV cache，但缓存命中、过期、权限与 query 污染应是服务协议的一部分。

量化将连续历史变成可管理的离散容量，不应与推荐中的物品 Semantic ID 混为一谈：前者优化用户历史的压缩、上下文和更新，后者通常关联候选目录与生成约束。无论采用哪种表示，表格、事件序列和文本仍需要各自合适的编码与缺失值处理；“投影到共享空间”不是“结构信息已无损统一”。

公开模型的编码器对照见 [[多模态行为序列与表格编码器对比-2026]]。其中 LUMOS 代表“连续统计向量按时间点融合后进入 Transformer”，FOUNDv2 代表“多源连续表示经共享/专属码本离散化”。前者适合直接预测未来多变量行为，后者适合压缩和复用长历史。

## 与推荐链路的关系

如 [[LLM推荐系统的分层改造与评估]] 所述，用户表征主要位于离线数据、表征与索引层：它可产生画像、检索特征、教师信号或场景化重排特征。全库召回、实时排序、物品目录、库存、政策与回退仍应由专门服务承担；表征提升也不能直接推导为 CTR、GMV 或长期留存提升。

## 训练、治理与评估

1. **时间与数据契约**：未来行为只能作为训练目标，不能通过标签、模板、特征窗口或缓存泄漏进输入；不同任务需按上线时点重放。
2. **表示质量**：同时看线性探测/检索、量化碰撞、长尾与新用户、跨任务迁移和任务无关行为抑制，不能只看预训练 loss。
3. **系统成本**：报告 token 数、存储、训练/推理吞吐、p95/p99、缓存命中率、刷新频率与失败回退。
4. **治理**：用户历史、敏感属性、合成 QA、指令与 query 都是访问控制与审计对象；应支持授权、删除、最小化保留和群体公平检查。

## 证据边界

七篇来源共享工业规模、多模态用户数据与 Ant Group/DeepFind/Google DeepMind·YouTube 研究背景，但训练语料、任务、模型、容量和评测协议不同。不能将报告的 AUC、KS 或线上增益拼成统一排行榜，也不能从某一业务 A/B 推出跨平台通用收益。较稳健的结论是：当历史冗余、任务分化或多源异构成为瓶颈时，未来对齐、容量控制、条件化、掩码适配与共享词表的离散用户表示是应分别验证的设计杠杆。
