# 时间序列 LLM 智能体分类法

> 关联来源：[[来源-时间序列LLM智能体综述-2026]]

## 核心命题

LLM 在时间序列场景的价值，**不在"当模型"直接吐数值**，而在作为**会规划、调工具、维护记忆**的 Agent，处理演化观测与多步决策。[[来源-时间序列LLM智能体综述-2026]] 给出"问题驱动"分类法：按所解决的时序问题归为四类，并以**架构 / 工具 / 记忆**三维度贯穿设计。

## 四个问题类

| 问题类 | 关注点 | 代表系统 |
|--------|--------|---------|
| **预测与推理** | 预测未来值；从时序证据推出解释/答案。输出须有**数值证据**与上下文支撑，而非仅语言上合理 | TimeSeriesScientist、TS-Agent、ZARA、CLIMATEAGENT、FETA |
| **增强与合成** | 数据增强、合成时序 | TESSA、ChatTS、BRIDGE |
| **异常检测与诊断** | 检测异常 + 定位/解释根因 | AD-Agent、ARGOS、CALM、SAGE、AgentFM |
| **决策支持** | 交易、交通控制、电网控制等运营决策 | FinMem、Open-TI、LLMlight、Grid-Agent |

**预测的关键设计**：多阶段工作流（诊断→预处理→选模型→上下文分析→预测→验证）与竞争假设——早期阶段错误会失效后续结论，故每阶段须以**显式中间证据**而非自由推理为锚。

## 三个设计维度

### 架构

- **单 Agent**：一个 LLM 规划、调工具、维护记忆、产输出。
- **多 Agent**：
  - **协作**：互补角色分解，协调向共同输出。
  - **竞争**：多 Agent 产替代假设/预测/解释/动作，由打分/排序/投票/辩论/裁判裁决。
  - **混合**：协作分解 + 竞争比较/辩论/选择共存。

→ 与 [[多Agent系统研究趋势与工程映射]] 的协作拓扑主轴直接同构；竞争式多 Agent 与 [[LLM推理结构与自纠错框架]] 的辩论/回滚/多假设机制同源。

### 工具

数据库 API / 检索 API / 数据处理工具（含 DTW）/ 统计与 ML 模型 / 模拟器-求解器-优化器。工具的价值在于提供**参数化知识不可靠给出的可验证反馈**——这与"LLM 不直接算数，而是调度数值工具"的设计哲学一致。

### 记忆（时序特化三分类）

| 类型 | 内容 |
|------|------|
| **证据日志** | 中间决策痕迹：预测、检索证据、工具输出、候选动作、验证结果 |
| **模式库** | 可检索历史案例/典型片段：重复市场形态、故障签名、相似过往情境 |
| **分析策略** | 可复用的"如何分析"经验：用什么工具、关注哪些特征、如何解读信号 |

→ 这是 [[Agent记忆系统与自我演进]] 的"基底/认知机制/主体"分类在时序域的**具体实例**：证据日志≈情景记忆、模式库≈语义记忆、分析策略≈程序记忆。

## 边界判定（何为"时序 Agent"）

LLM 必须**至少做出一个改变多步时序工作流的决策**（选动作/工具、更新记忆、修正假设、协调阶段）。

**明确排除**：① 一次性 prompting；② LLM 仅作静态编码器或事后解释器；③ 非时序约束的通用 Agent。

→ 这与 [[Agent任务分流：工作流与智能体边界]] 的判定标准同构：流水线里 LLM 只当编码器/解释器 = workflow，非 agent。

## 异常检测子域的方法谱（本批次重点）

逐篇深读见独立来源页：

- **可解释规则生成**：[[来源-ARGOS自主规则时序异常检测-2025]] — LLM 训练期生成可复现 Python 规则，运行时不调 LLM；三 Agent（Detection/Repair/Review）+ 模型融合。工程对应"规则可审计"。
- **LLM-as-a-Judge**：[[来源-CALM流式异常检测LLM裁判-2025]] — Apache Beam + TimesFM，LLM 判官区分噪声 vs 漂移，闭环持续微调。工程对应"评判可治理"。
- **专门分析器分工 + 合成 ICL**：[[来源-SAGE专家式多Agent时序诊断-2026]] — 5 阶段管线、4 族 9 类分析器、k-medoids+DTW 检索正常原型、LLM 打分 temperature=0。工程对应"诊断可结构化"。
- **多 Agent 自动化管线 + 开源**：[[来源-AD-Agent多Agent异常检测-2025]] — 7 Agent + 短/长期记忆，自然语言→可执行 AD 流水线，集成 PyOD/PyGOD/TSLib，BSD-2 开源。
- **多 Agent 角色感知**：[[来源-AgentFM-数据库故障管理Agent-2025]] — 分布式数据库运维场景，区分系统/数据/任务角色，meta-agent 编排聚合；IoTDB 初步验证（preliminary）。工程对应"编排可治理（meta-agent 归因）"。
- **LLM + XAI 混合 + 语义记忆**：[[来源-IoT异常检测LLM-Agent-2025]] — 关键 IoT 基础设施场景，LLM 上下文推理 + XAI（SHAP/LIME/注意力热图）+ 语义记忆缓冲，强可解释 + human-in-the-loop；仿真 smart grid/healthcare，95.4% vs 82.1%。工程对应"XAI 可审计 + 人在回路"。

这些与 [[流量风控技能栈与Agent治理]] 的"可审计链路"在治理诉求上同构——时序运维与风控都要求"可解释 + 可追溯 + 可干预"。

## 与既有结论的关系

- 与 [[多Agent系统研究趋势与工程映射]]：协作/竞争/混合拓扑在时序域的实例化，呼应"协作拓扑 → 工程编排"。
- 与 [[Agent记忆系统与自我演进]]：时序三分类记忆是通用记忆分类的具体样本，可作跨页对照。
- 与 [[Agent任务分流：工作流与智能体边界]]：综述的排除标准即 workflow vs agent 边界。
- 与 [[流量风控技能栈与Agent治理]]：异常检测的可解释规则 / LLM-as-Judge / 专门分析器，与风控可审计链路同构。

## 冲突与不确定性

- "问题驱动分类"与按设计维度分类的既有工作重叠——同一系统常横跨多类，归类以"主要解决的问题"为准，含主观判断。
- 各子论文量化口径不同（ARGOS 公开+9.5% vs 内部+28.3%；CALM 用 ROC AUC；SAGE 用 benchmark 排名），**不可直接横比**。
- raw 含知乎中文导读与智谱译文合集，转述可能偏差；技术细节以 arXiv 英文原文为准。
