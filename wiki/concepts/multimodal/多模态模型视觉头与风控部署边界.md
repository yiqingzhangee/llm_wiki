# 多模态模型视觉头与风控部署边界

> 关联来源：[[来源-开源多模态模型ViT视觉头与风控落地选型报告-2026]]

## 核心命题

在风控里，**视觉头决定“模型能看见什么”**，但**系统链路决定“业务能赚到什么”**。

这意味着多模态模型选型不能只看通用榜单，也不能把线上效果直接归因到 ViT。更稳妥的做法是把问题拆成三层：

1. **视觉头层**：输入保真、视觉 token、编码成本；
2. **整模型层**：给定版本与推理模式下的能力与效率；
3. **风控系统层**：Recall、FPR、人审量、损失与处置闭环。

## 为什么视觉头重要

视觉头覆盖的不只是 ViT 主干，还包括：

- 图像预处理与采样；
- 固定分辨率 / 动态切片 / 原生可变分辨率；
- 位置与时间编码；
- 连接器与视觉 token 压缩；
- 视觉特征如何注入语言模型。

它直接影响三个现实问题：

- **小字和局部异常能不能保住**；
- **版式、跨区域关系和时间顺序会不会丢**；
- **视觉信息进入 LLM 要花多少 token、显存和时延**。

其中连接器不是简单的“视觉头尾部”。[[多模态大模型跨模态投影与连接器]] 将其拆成维度适配、压缩、信息选择和融合：简单 MLP 往往是强基线，但 OCR、小目标、强压缩和多视觉塔可能需要局部感知或空间聚合。选型时应固定分辨率与输出 token 数，避免把视觉像素预算带来的收益误归因于 connector 复杂度；具体对照见 [[跨模态连接器实现方案对照-2026]]。

## 三层归因边界

| 层级 | 应看什么 | 能支持什么结论 | 不能越界到什么 |
|---|---|---|---|
| 视觉头 | 分辨率、切片数、视觉 token、编码时延、小目标/OCR 消融 | 输入保真与视觉侧成本 | 不能单独解释线上收益 |
| 整模型 | MMMU、OCRBench、DocVQA、业务离线集、TTFT、显存 | 给定口径下的能力与效率 | 不能直接等同生产 Recall / FPR |
| 风控系统 | Recall、Precision、FPR、金额加权召回、人审率、P99、单位真阳性成本 | 整链路净收益 | 没有消融时不能归因给 ViT |

## 当前主流视觉路线

### 1. 固定视觉塔 + 切片扩容

代表路线：LLaVA、Idefics、部分 MiniCPM-V。

- **优点**：成熟、实现清晰、工程路径短。
- **缺点**：tile 数上来后成本近似线性增长，跨 tile 布局要额外补偿。

### 2. 专用大视觉塔 / 多塔

代表路线：InternVL、CogVLM、NVLM、Eagle、Cambrian。

- **优点**：更强细节和多尺度表征。
- **缺点**：视觉侧 FLOPs、显存和依赖明显增加，部署成本更前移。

### 3. 原生动态分辨率 / NaViT

代表路线：Qwen2-VL / 2.5-VL / 3-VL、Ovis2.5、Pixtral。

- **优点**：减少切片边界损失，更适合文档和复杂布局。
- **缺点**：视觉 token 波动更大，批处理和 P99 更难控。

### 4. 视频时空编码路线

代表路线：Qwen-VL、GLM-V、MiniCPM-V 4.5、Molmo2、NVILA。

- **优点**：更适合时刻定位、跨帧事件与视频语义。
- **缺点**：真正成本核心不在“模型名”，而在 FPS、帧数、分辨率和总 token 预算。

## 对风控最重要的不是“谁榜单第一”，而是谁更匹配子场景

结合 [[来源-图像对抗攻防答辩文档-2026]] 可以把这件事再说得更细：视觉头边界至少要区分两类失败。

- **视觉头盲区**：模型根本没把风险证据编码进去，例如 Illusion 类攻击；这时继续加提示通常收益很小，应该优先做缩放、频域过滤、对比增强、结构恢复等前处理。
- **决策层盲区**：视觉证据已进入模型，但 LLM / 分类头没有稳定输出正确判断，例如低对比文本或部分结构攻击；这时更适合做 SFT、困难样本回流和“增强审核触发器”。

因此，“视觉头决定看见什么”不是抽象结论，而是会直接改变你的防御链路排布：先修视觉，再修决策，最后才谈最终裁决。

### 优先试点场景

- **静态内容审核 / 广告合规**：需要跨图文的隐含语义判断。
- **文档抽取与一致性核验**：需要跨页、跨区域、多图理解。
- **退款 / 售后证据二审**：需要看懂多图与上下文，但最终还要专模保真伪。

### 不宜把 VLM 放到最终裁决位的场景

- **证件真实性 / 活体 / 防伪**：局部篡改、全息、防复制特征仍是专模主场。
- **纯支付交易反欺诈**：若主要信号是交易、行为、关系图和设备链路，ViT 不是首要组件。

## 推荐的风控链路分工

- **OCR / 检测专模**：保留字段、坐标、局部伪造与检测信号；
- **VLM**：负责开放语义理解、跨区域证据归纳和解释；
- **规则 / 图模型 / 行为模型**：负责确定性约束、链路归因与最终裁决；
- **人工复核**：处理高影响、低置信、证据冲突与疑似攻击样本。

这与 [[流量风控技能栈与Agent治理]] 的“识别层 / 行为层 / 处置层 / 治理层”是兼容的：多模态模型主要增强识别层与治理层的语义能力，不应直接吞掉处置层与治理层的全部责任。

## 冲突与不确定性

- 同一模型家族内不同 checkpoint 的视觉路线可能完全不同，不能沿用家族名做粗粒度结论。
- 公开生产 KPI 稀缺，尤其在支付交易反欺诈领域；很多案例只能证明“流程有价值”，不能证明“ViT 单独有价值”。
- 思维模式、提示、量化、像素预算、推理后端会显著影响排序；任何固定结论都应附带实验口径。
