# 多模态大模型跨模态投影与连接器

> 证据综述：[[来源-跨模态投影与连接器研究-2026]]。实现对照：[[跨模态连接器实现方案对照-2026]]。

## 一句话结论

跨模态 projector 首先是**表示接口与带宽控制器**，有时也是信息选择器，但不能默认视为把视觉语义“投进文本空间”的唯一对齐者。独立复杂 connector 不是所有多模态大模型的必要条件；某种输入表示转换则几乎不可避免。

## 先拆开四种职责

| 职责 | 解决的问题 | 典型机制 | 不能据此自动声称 |
|---|---|---|---|
| 维度与分布适配 | 视觉特征维度、尺度与 LLM embedding 不一致 | linear、MLP、归一化 | 已完成任务级语义对齐 |
| token 压缩 | patch、帧或多图 token 超出预算 | pooling、pixel shuffle、Q-Former、Perceiver | 被丢弃的信息不重要 |
| 信息选择与聚合 | 需要按查询、尺度或视觉塔筛选证据 | learned queries、cross-attention、SVA | 选择结果一定忠于原始局部证据 |
| 融合与条件化 | 让语言层持续访问非文本信息 | 前缀 token、门控交叉注意力、深层注入 | 模型实际使用了该模态 |

训练目标、LLM 参数更新和数据配比共同决定语义对齐。把所有能力归因给 connector，会忽略视觉编码器、语言主干和训练制度。

## 正方：为什么需要专门的连接器

### 1. 它是复用强两端的最小改造

冻结视觉编码器和 LLM，只训练小型接口，可以减少训练参数、稳定初期优化，并让成熟单模态组件快速组成系统。LLaVA、BLIP-2 和 MiniGPT-4 都利用了这一工程价值。

### 2. 它控制视觉带宽

高分辨率图像、视频和多图输入会产生大量 token。Q-Former、Perceiver Resampler、池化和 coarse-to-fine 压缩可把成本约束在固定范围，使长上下文推理和服务部署成为可能。

### 3. 它可保留局部性或聚合多源

OCR、图表、文档、小目标和多视觉塔任务不只需要全局语义，还需要二维位置、跨尺度细节与来源对应。Honeybee、TokenPacker、Cambrian-1 的价值主要在这里，而不是“层数更多”。

### 4. 它形成清晰的工程边界

独立 connector 便于分阶段训练、特征缓存、视觉塔替换和模块消融。对已有 LLM 服务体系，这种边界常比从头联合预训练更现实。

## 反方：为什么不应神化 projector

### 1. 任务提升不证明语义已被投影

同名论文的 LLaVA-1.5 实验显示，只调 projector 可改善闭集分类，但投影后表征的领域属性 probe 未同步增强。更谨慎的解释是：projector 改善了下游可用接口，而具体任务语义仍可能主要由 LLM 参数形成。

### 2. 复杂度可能不是主要变量

MM1 的受控消融把视觉 token 数和分辨率列为更重要因素，connector 类型影响较小。若实验没有控制 token 数、分辨率、训练数据和可训练参数，不能把榜单增益单独归因于 connector。

### 3. 提前语义压缩可能损失证据

查询式连接器先根据少量 learned queries 抽象视觉内容，LLM 再按用户指令做第二次选择。DeCo 将其称为双重语义抽象风险：早期被忽略的文字、坐标或长尾局部信息，后续无法恢复。

### 4. 统一主干提供存在性反例

SOLO / Fuyu 类路线以连续 patch embedding 直接进入 decoder；Chameleon / Emu3 以离散视觉 token 进入统一 Transformer。它们表明独立 connector 不是架构公理，但代价转移到视觉 tokenizer、端到端预训练、序列长度和训练稳定性。

## 争议的准确表述

不准确的二元问题是：“要不要 cross-modal projection？”

更准确的问题是：

1. 输入表示转换放在哪里：独立 connector、patch embedding、离散 tokenizer，还是外部工具？
2. 在什么阶段压缩：编码前、编码后、进入 LLM 前，还是 decoder 层间动态重访？
3. 压缩依据是什么：固定空间池化、学习查询、文本条件，还是任务工具调用？
4. 哪些信息必须保留：全局语义、文字、坐标、小目标、时间顺序或多视觉塔来源？

## 三种训练制度不能混比

| 训练制度 | connector 的责任 | 常见优点 | 主要风险 |
|---|---|---|---|
| 冻结视觉端与 LLM，只训 connector | 承担主要接口适配与信息选择 | 参数少、训练快 | 容量瓶颈明显，依赖两端已有能力 |
| 冻结视觉端，联合训练 connector + LLM | connector 提供输入，LLM 学会解释视觉 token | 指令适配更强 | 任务语义可能主要落在 LLM，模块归因困难 |
| 端到端联合训练 | 表示和接口共同演化 | 潜在上限高 | 数据、算力、稳定性和灾难性遗忘成本高 |

同一 connector 在三种制度下的结论可能相反。评审论文或内部实验时，应先确认冻结策略。

## 选型决策

1. **先测简单基线**：linear、两层 MLP、无参数池化 + linear，并严格匹配输出 token 数。
2. **细节优先**：OCR、文档、图表、小目标采用保留型 mapping，或局部感知 / coarse-to-fine 连接器；不要先做强语义压缩。
3. **预算优先**：视频、多图、移动端采用空间池化、pixel shuffle 或固定查询压缩，同时建立细粒度回归集。
4. **多塔或跨尺度**：只有在简单拼接和匹配预算基线失败后，再引入 SVA、深层 cross-attention 等聚合机制。
5. **统一主干**：只有具备大规模端到端多模态预训练能力，且系统同构收益足够大时，才考虑连续早期融合或离散 token 路线。
6. **可外置任务**：精确 OCR、检测、分割、数值计算或高风险核验，可保留专用工具，把结构化结果作为证据输入，避免让 connector 承担所有感知责任。

## 最小评测矩阵

不能只报综合 benchmark。至少同时检查：

- **能力**：粗粒度理解、OCR / 定位 / 图表 / 小目标、跨图与视频；
- **信息保留**：投影前后 probe、结构恢复、模态打乱与局部遮挡敏感性；
- **实际使用**：替换视觉 token、删除某视觉塔、冲突图文和反事实输入；
- **成本**：视觉 token 数、TTFT、吞吐、峰值显存、KV cache 和特征缓存；
- **公平性**：固定视觉编码器、LLM、分辨率、数据、训练步数和输出 token 预算；
- **最差桶**：小字、密集目标、长尾类别、极端宽高比与多图冲突。

如果 connector 的指标增益在匹配 token 数和训练预算后消失，应优先采用更简单实现。如果压缩后粗粒度指标不降但 OCR / 定位显著退化，应将其视为有损预算交换，而不是无损优化。

## 不确定性

目前没有跨主干、数据和 token 预算都稳定获胜的 connector。合理默认不是“越简单越好”或“越复杂越强”，而是：先固定信息预算和任务红线，再选择最小、可证伪的接口。
