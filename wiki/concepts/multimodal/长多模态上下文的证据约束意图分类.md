# 长多模态上下文的证据约束意图分类

长多模态上下文的细粒度意图分类，不应被简化为“看到某个关键词或图像就归类”。更稳健的系统需要先定位可回溯证据，再依据显式规则组合证据，最后输出类别；数据治理、标注、蒸馏和强化学习应围绕同一证据契约设计。

> 关联来源：[[来源-长多模态意图分类内部实践-已脱敏-2026]]。该来源仅保留方案与算法，身份、业务标识、样本、内部数值和链接均已删除。

## 问题结构

这类任务通常同时具备五个难点：

1. **长上下文**：资料、内容、互动、关系和行为等模块共同构成输入。
2. **多模态**：关键证据可能来自文本、OCR、小区域图像或跨模态组合。
3. **稀疏证据**：决定性线索只占输入中的很小部分。
4. **强干扰**：表面相似内容可能对应不同真实目的，单点启发式容易误伤。
5. **长规则**：类别边界依赖多条正向条件、排除条件和证据强度判断。

因此，任务应拆为：

```text
输入治理
  → 候选证据定位
  → 证据去噪与强度判断
  → 跨模块证据组合
  → 规则匹配与排除
  → 类别输出
  → 证据链与结果校验
```

## 一、先定义数据与证据契约

### 输入标准化

| 操作 | 目的 | 验收点 |
|---|---|---|
| 实体去重 | 防止同一对象重复进入训练或评测 | 切分前按稳定实体键去重 |
| 泄漏字段移除 | 避免先验结论、处置结果或标注理由直接暗示标签 | 训练与线上输入字段一致 |
| 失效资源清理 | 删除不可访问或不可解码的视觉资源 | 数据加载失败率可监控 |
| 视觉去重与默认内容清洗 | 降低重复图像和模板背景噪声 | 感知哈希与规则双重检查 |
| 同语义单元拼接 | 保留局部上下文并控制视觉 token 数量 | 拼接顺序确定且可复现 |
| 层级结构化 | 将扁平长文本恢复为明确模块 | schema 版本化 |
| 证据溯源 | 支持人工与程序复核 | 每项证据含唯一 ID、来源模块和位置 |

证据对象至少应包含：

```json
{
  "evidence_id": "stable-id",
  "source_module": "content_or_profile_or_behavior",
  "location": "field_or_region",
  "content": "normalized_evidence",
  "strength": "weak_or_medium_or_strong",
  "supports": ["candidate_label"],
  "contradicts": ["candidate_label"]
}
```

其中 `content` 应是脱敏、规范化后的信息；原始敏感字段不得进入训练记录或模型输出。

## 二、人机协同标注

纯人工标注真实但成本高，纯合成数据可控但有分布偏差。较实用的折中是“模型提出候选，人类处理边界”：

1. 多个模型对同一样本独立预测，避免共享上下文造成相关性偏差。
2. 对候选类别投票或聚合，但不把多数票直接当金标。
3. 独立回看输入，抽取支持与反对候选类别的证据。
4. 审核模型检查类别、证据强度、规则匹配和输出格式，并给出置信度。
5. 人工按低置信度、模型分歧、类别均衡和新模式覆盖抽样。
6. 将确认错例归因为类别定义、证据遗漏、证据误读、组合错误或格式错误。
7. 更新类别规则与标注技能，使用冻结验证集重新评估后再进入下一轮。

人工反馈不应只写“标签错了”，还应指出哪条规则、哪项证据或哪一步组合发生错误，否则无法驱动标注技能稳定改进。

## 三、长规则与证据链蒸馏

目标不是复制教师的文风，而是把审核逻辑压缩进可部署学生模型：

```text
规则显式化
  → 教师生成类别与证据链
  → 纠错与推理链重构
  → 多维质量门禁
  → 去重、类别均衡与难例采样
  → SFT 学生模型
  → 独立测试集验证
```

### 推理链质量门禁

- **结果正确性**：最终类别与金标一致。
- **证据真实性**：证据可以在原输入的明确位置找到。
- **证据充分性**：关键支持、反证和排除条件没有缺失。
- **规则一致性**：证据与类别定义之间的映射成立。
- **推理一致性**：中间判断与最终结论不矛盾。
- **格式质量**：输出可被稳定解析和回放。

教师直接推理表现最好的提示词，不一定生成最适合学生学习的数据。提示词选择必须以学生模型在冻结测试集上的蒸馏结果为准，并同时检查总体宏平均指标与逐类表现。

## 四、用 `pass@k` 判断是否值得做强化学习

在同一输入上独立采样多次，若 `pass@k` 随 `k` 增长明显，而 `pass@1` 较低，说明模型并非完全缺少能力，更可能是类别边界、证据选择或输出稳定性不足。这时强化学习可能有价值。

反之，如果 `pass@k` 也低，应优先补数据、修规则、提高输入质量或更换基座；直接强化错误策略通常收益有限。

## 五、从结果奖励走向过程奖励

GRPO 的总奖励可写成：

```text
R = w_y R_label + w_e R_evidence + w_f R_format + w_l R_length
```

- `R_label`：最终类别是否正确。
- `R_evidence`：证据位置、内容、强度和解释是否可靠。
- `R_format`：结构是否可解析、字段是否完整。
- `R_length`：抑制过短的无依据结论和过长的无效推理。

证据奖励还可以继续分解：

```text
R_evidence =
  a R_traceability
  + b R_label_consistency
  + c R_strength
  + d R_reasoning_consistency
```

只奖励最终类别，会把长推理链压缩成一个粗粒度信号：模型无法知道错误来自证据幻觉、证据与类别不一致、证据强度误判，还是跨模块组合错误。过程奖励的价值在于定位这些中间失效，而不是单纯增加奖励项数量。

## 六、评估矩阵

| 层级 | 核心指标 | 必须拆解的维度 |
|---|---|---|
| 数据 | 重复率、泄漏率、资源可用率 | 来源、模态、模块、时间 |
| 标注 | 标签准确率、证据准确率、证据充分性、幻觉率 | 类别、置信度、模型分歧 |
| 分类 | Macro F1、逐类 P/R/F1、校准 | 类别、证据位置、上下文长度 |
| 稳定性 | `pass@1`、`pass@k`、多次采样方差 | 类别边界、难例类型 |
| 推理 | 可回溯率、规则一致率、前后一致率 | 证据抽取、组合、结论 |
| 工程 | 时延、吞吐、失败率、成本 | 输入长度、图像数量、模型规模 |

总体指标提升不代表所有类别改善。新增证据奖励后，还要检查精确率与召回率的取舍，以及弱势类别是否退化。

## 七、失败模式与停止条件

- 多模型投票只能降低部分单模型偏差，不能替代金标与人审。
- 模型生成的“证据”必须回指原输入；无法回指的解释按幻觉处理。
- 推理链更长不等于更可信，长度奖励只能约束形态，不能证明正确性。
- 标注技能自更新必须通过冻结集和人工盲审，不能用训练回流数据自证。
- 学生蒸馏效果应决定提示词与教师数据是否保留，不能只看教师自身表现。
- 当 `pass@k` 不提升，或过程奖励改善解释却损害关键类别时，应停止强化学习扩展，回到数据、规则和模型能力诊断。

## 八、正反证据与适用边界

现有研究对本页方法给出的是**条件支持**，不是“证据链越长越好”：

- 数学推理与部分文本分类研究说明，步骤级监督或 rationale 联合训练可以改善信用分配、任务表现或解释指标。
- CoT 忠实性研究说明，模型可能受未披露偏置影响，再生成看似合理的事后解释。
- 解释评测研究说明，sufficiency、comprehensiveness 等指标可能被优化目标利用，不能单独证明忠实性。
- 人工 rationale 的预测效用并不均匀；对每项证据等权监督可能收益很小或产生负迁移。
- 在 guided decoding 等面向未来结果的任务中，结果监督形成的 value 判断可能比步骤正确性更适合路径选择。

因此，证据链的首要定位应是**可审计的中间接口**：它帮助定位输入、执行规则、复核错误和组织数据回流，但不能自动证明模型真实依赖这些证据。

上线前必须加入证据删除、证据替换、无关证据注入、位置扰动和规则冲突测试。若关键证据变化后预测基本不变，当前证据链只能视为可读解释，不能视为决策依据。
