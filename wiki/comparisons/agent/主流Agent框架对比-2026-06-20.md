## 对比表

|---|---|---|---|---|---|

| LangChain/LangGraph（来自综述） | 组件化 + 图编排 | Python 为主 | LangGraph 指向有状态工作流 | 工程化能力取决于周边集成 | 与本库既有 LangGraph 页面存在可对齐基础 |
| OpenAI Agents SDK（来自综述） | 轻量 Agent 原语（Agent/Handoff/Guardrail） | Python | 支持多 Agent 流程，但范式更轻 | 强调 tracing 与 guardrail | 模型侧偏 OpenAI 生态 |
| Agently | 企业交付导向 Agent 框架 | Python | TriggerFlow / Dynamic Task 等流程能力 | 强调结构化契约、可观测、上线链路 | 宣传叙事较强，需结合实测 |
| Agents-Flex | Java 轻量高性能 Agent 框架 | Java | 提供工具调用与扩展链路 | 强调可观测与责任链扩展 | 适合 Java 既有系统场景 |

## 观察

1. **市场叙事从“能不能做 Agent”转向“如何稳定上线 Agent”**。
2. **工作流编排能力成为框架差异核心**，尤其在长流程与人工介入场景。
3. **语言生态决定组织落地摩擦**：Python 常用于创新速度，Java 常用于系统整合与治理。
