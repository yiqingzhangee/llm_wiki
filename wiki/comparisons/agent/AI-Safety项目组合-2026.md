# AI Safety 项目组合（2026）

> 结论：先做 Agent 行动安全，再扩展到多模态感知安全，最后研究长期证据状态。三个项目共享事件、策略、审计与回放协议，但不并行启动。
>
> 关联页面：[[Agent对抗安全：从briccli攻击面出发的调研与启动方案]]、[[图像对抗防御链路对照-2026-09-02]]、[[LLM统计特征编码的证据仲裁]]、[[AI-Safety长期研究与项目路线图]]。

## 组合总览

| 顺序 | 项目 | 周期 | 核心问题 | 首个可用产出 | 主要价值 |
|---:|---|---|---|---|---|
| 1 | **BRIC-SafeAct** | 0—3 个月 | Agent 能否在不可信工具返回值下安全完成高价值任务 | briccli mock benchmark + 策略网关 | 最快形成可复现基准和工程闭环 |
| 2 | **MM-SafeRoute** | 3—6 个月 | 视觉注入与内容规避应如何路由到恢复、精审和人工 | 多模态安全路由器 + 成本/漏放曲线 | 把本地图像对抗与 VLM 审核接入真实链路 |
| 3 | **EviGuard** | 6—12 个月 | 跨会话记忆被投毒、过期或冲突时，系统如何发现、回滚并限制行动 | 长期证据状态 benchmark + 回放引擎 | 形成区别于普通 RAG 安全的长期研究主张 |

## 共用基础设施

三个项目统一使用以下契约，减少重复建设：

```text
安全场景
  -> 可信用户目标
  -> 不可信证据事件
  -> Agent / VLM / Memory 状态变化
  -> 候选工具调用或业务裁决
  -> 策略授权
  -> 环境状态检查
  -> 审计与回放
```

最小事件字段包括：

- `scenario_id`、`actor_id`、`session_id`、`task_goal`；
- `evidence_id`、来源、模态、`event_time`、`available_at`、版本与信任域；
- 攻击类型、注入位置、攻击预算与重复尝试编号；
- 候选行动、工具、参数、所需 capability、审批结果；
- 正常任务结果、攻击目标结果、影响等级、回滚结果和人工覆盖记录。

## 项目一：BRIC-SafeAct

### 问题与用户

目标用户是 Agent 平台、briccli 工具所有者和风控研发。项目回答：当 Agent 读取不可信数据并拥有读写工具时，哪些攻击能造成高影响行动，哪些运行时策略能在保留任务效用的同时阻断攻击。

### 威胁模型

- 直接与间接提示注入；
- 单步合法、组合后形成数据外泄或越权的调用链；
- 目的地址、参数和工具替换；
- 重复尝试与针对防御做优化的自适应攻击；
- 不覆盖真实生产攻击，所有写操作只进入 mock、dry-run 或隔离沙箱。

### 12 周 MVP

| 周期 | 交付 |
|---|---|
| 第 1—2 周 | 6 个 mock 域、12 个读写工具、统一调用日志；优先覆盖查询、导出、规则修改、案例创建、文件写入和工作流触发 |
| 第 3—4 周 | 40 个正常任务、120 个攻击场景；每个场景有确定性 utility 与 attack goal 检查 |
| 第 5—7 周 | 四条基线：无防御、提示检测、白名单 + 参数校验、capability + HITL |
| 第 8—10 周 | 自适应改写、每场景 10 次重复尝试、跨工具外泄链和影响分级 |
| 第 11—12 周 | 评测报告、策略网关原型、失败案例库和下一阶段决策 |

### 数据与基线

- 数据以合成和脱敏 fixture 为主，结构参考 AgentDojo，不复制生产数据。
- 基线包括 AgentDojo 风格 detector、工具白名单、写操作 HITL、最小权限、控制流/数据流分离。
- 若能获得授权，再增加只读 briccli dry-run；未获授权时不阻塞 MVP。

### 指标

| 指标 | 定义 | MVP 目标 |
|---|---|---:|
| 正常任务完成率 | 正确完成的正常任务占比 | 不低于无防御基线 90% |
| 单次与 10 次攻击成功率 | 一次及重复尝试下攻击目标达成率 | 高影响写操作为 0；整体相对下降 80% |
| 影响加权风险 | `ASR × 行动影响 × 可恢复性` | 相对无防御下降 90% |
| 策略误拒率 | 合法工具调用被拒绝比例 | 低于 5% |
| p95 策略延迟 | 网关增加的决策时延 | 低于 100 ms，不含人工确认 |
| 审计完整率 | 关键行动可追溯到目标、证据和授权 | 100% |

### 停止条件

- 不能获得 mock 工具契约，且两周内无法定义确定性任务检查；
- 防御仅靠 prompt 改写，不能在工具边界形成独立策略执行；
- 四周后仍无法稳定复现任何高影响攻击，说明场景设计失真，应先重做 benchmark。

### 产出

- 工程：运行时策略网关、场景生成器、审计回放工具；
- 研究：领域化 Agent 安全 benchmark 与影响加权评测方法；
- 组织：briccli 工具风险分级、HITL 与 capability 最小规范。

资源下限：1 名主研发，工具 owner 每周 2—4 小时评审，模型 API 或本地推理预算，以及一个不连接生产数据和凭据的执行沙箱。

## 项目二：MM-SafeRoute

### 问题与用户

目标用户是内容安全、VLM 审核和 Computer-Use Agent 团队。项目不直接寻找“最强分类模型”，而是决定一个多模态样本应走正常链路、结构恢复、OCR、VLM 二审、规则还是人工。

### 威胁模型

- 页面或图片中的视觉提示注入诱导 Agent 执行越权行动；
- 裁剪、低对比、字符拆分、隐喻和图文组合规避内容规则；
- 像素与频域扰动导致视觉头看不见证据；
- 不研究生成违法内容，不对真实网站投放攻击。

### 12 周扩展 MVP

- 从 VPI-Bench、EVADE-Bench 和本地合成数据构建 600 个受控场景；
- 标注失效位置：感知失败、规则理解失败、行动授权失败；
- 实现四路路由：直接通过、结构/OCR 恢复、VLM 精审、人工复核；
- 对照单模型直判、OCR + 规则、全量重模型二审三条基线；
- 输出风险、算力、时延和人工量之间的 Pareto 曲线。

### 指标与门禁

| 指标 | 关注点 |
|---|---|
| 高风险漏放率 | 最终链路是否放过注入或规避样本 |
| 正常内容误升级率 | 多少正常样本被送入昂贵链路 |
| 危险行动阻断率 | 视觉注入是否真正被挡在工具授权前 |
| 证据恢复率 | 恢复后 OCR/VLM 是否重新看到关键证据 |
| 单千样本成本与 p95 | 是否优于全量重模型二审 |
| 最差切片表现 | 语言、攻击类型、规则类别和图像变换下是否退化 |

停止条件：若路由方案在相同漏放率下不能比“全量 OCR + 规则”减少至少 30% 的重审成本，或不能比单模型直判显著降低高风险漏放，则不进入线上化，保留为数据与评测资产。

### 资源与产出

- 资源：1 名多模态/安全研发、1 名兼职规则或标注专家、受控 CUA 沙箱，以及 OCR、VLM API 或 2—4 张训练/推理 GPU 的等价预算；
- 工程产出：可配置路由器、失效分层标注工具、成本与风险看板；
- 研究产出：多模态安全路由 benchmark、系统报告或应用型论文；
- 落地产出：选一个真实审核队列做离线回放；未经过数据授权和隐私审查不做在线实验。

## 项目三：EviGuard

### 问题与用户

目标用户是长期 Agent、RAG、风控状态和审计平台团队。项目研究：当长期记忆中同时存在恶意、过期、修订、撤回和相互冲突的证据时，系统能否保持可追溯状态，限制其对高影响行动的影响，并在污染后正确回滚。

### 威胁模型

- 低投毒率的触发式记忆/RAG 后门；
- 旧证据与新证据并存造成时间错位；
- correction/retraction 未生效，污染状态跨会话持续；
- 同源转述伪装成多源共识；
- 一个 Agent 污染共享记忆后传播到其他 Agent。

### 16—24 周研究 MVP

- 基于 EviState 的 stable evidence ID、cutoff、版本、correction、retraction 和 missing reason 建立状态引擎；
- 构建至少 500 条、覆盖 30 天的合成证据序列，包含正常更新、目标化投毒、过期证据、冲突和撤回；
- 对照无治理 RAG、只做内容过滤、版本 + 回滚、完整证据状态仲裁；
- 复用项目一的高影响行动策略，验证污染是否越过授权边界；
- 发布可重复的时间切分、污染预算和回放协议。

### 指标与门禁

| 指标 | 关注点 |
|---|---|
| 持续攻击成功率 | 攻击跨会话或跨天维持成功的比例 |
| 污染发现时间 | 从首次写入到隔离的时间 |
| 回滚正确率 | 回滚后是否恢复正确状态且不删除合法更新 |
| 时间一致率 | 决策是否只使用 cutoff 前可见的正确版本 |
| 来源与版本覆盖率 | 影响行动的证据是否可追溯 |
| 正常记忆效用 | 治理后是否仍能利用合法历史信息 |
| 跨 Agent 污染率 | 共享状态下污染传播范围 |

停止条件：若 EviState 真实数据门禁长期无法满足，则只做合成 benchmark，不宣称业务效果；若 stable ID、版本和 cutoff 相对简单的检索过滤没有增益，则暂停复杂状态模型，先解决数据契约。

### 资源与产出

- 资源：1 名主研发，1 名兼职数据/检索研发，版本化文档库或向量库，以及可重放的合成 Agent 环境；
- 工程产出：证据状态引擎、记忆写入策略、污染定位与回滚工具；
- 研究产出：长期记忆安全 benchmark，重点刻画污染持续性、时间冲突、修订/撤回与行动影响；
- 落地产出：先接非生产知识库或冻结样本回放，真实业务接入以 EviState 数据门禁和安全审批为前置条件。

## 启动决策

只批准 **BRIC-SafeAct** 进入执行。进入下一项目需满足：

1. 正常任务、攻击目标和影响评分均可重复计算；
2. 策略网关能在模型之外阻断至少一种高影响行动；
3. 场景、事件与审计格式可被下一项目复用；
4. 已形成一份可公开脱敏或可内部评审的基准报告。

## 证据边界

不同基准的攻击者能力、环境、任务和指标不同，不能直接横比攻击成功率。本文给出的样本数、周期和阈值是项目管理门禁，不是已有论文结论；需要在第一轮基线后校准。
