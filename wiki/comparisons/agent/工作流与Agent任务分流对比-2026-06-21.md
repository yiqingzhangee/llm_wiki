# 工作流与Agent任务分流对比（四问框架）

> 关联来源：[[来源-构建Agent的四个问题-2026-06-21]]

## 对比目的

将“workflow 优先”与“agent 优先”的常见争论，转化为可执行的任务分流规则，降低拍脑袋选型。

## 对比表

| 维度 | workflow 路径 | agent 路径 |
|---|---|---|
| 任务复杂度 | 低到中等复杂度、步骤可枚举 | 高复杂度、需要动态规划与探索 |
| 任务价值 | 低价值任务更经济 | 高价值任务才更可能覆盖治理成本 |
| 可执行性要求 | 依赖明确接口与稳定步骤 | 也依赖可执行接口，但需额外策略与恢复机制 |
| 错误成本 | 高错误成本下更稳健（可控） | 低错误成本场景可放宽自治 |
| 治理开销 | 相对低，运维模型简单 | 相对高，需要审计、回滚、权限边界 |
| 适用目标 | 稳定吞吐、可预测执行 | 开放任务、复杂决策、策略优化 |

## 结论

1. **不是“workflow 或 agent”二选一，而是按任务分层组合。**
2. **高风险任务默认 workflow + HITL，低风险高复杂任务可试点 agent。**
3. **agent 的收益必须与治理成本联算，否则容易出现“技术可行、业务不划算”。**
