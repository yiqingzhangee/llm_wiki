# 多模态行为序列与表格编码器对比（2026）

## 结论

公开模型中，同时原生处理**行为序列**与**统计/表格特征**的代表主要是 [[来源-LUMOS多模态用户行为预测-2026]] 和 [[来源-FOUNDv2统一量化用户Tokenizer-2026]]。两者路线不同：

- LUMOS 把连续统计向量融合成等间隔时间 token，再用 encoder-decoder Transformer 预测未来行为；
- FOUNDv2 把多源连续表示量化成离散用户 token，重点是长历史压缩、跨源共享和下游复用。

其余模型通常只覆盖一侧：TableGPT2、MultiModalPFN 重点处理表格与文本/图像；MP4SR、Molar、MLLM-MSR 重点处理行为序列与物品图文内容。通用 Qwen3-VL、LLaVA、Flamingo 没有原生行为序列或统计表格编码器。

## 按编码器类型分类

### 分类总览

| 编码器类型 | 代表模型 | 主要解决的问题 | 中间表示 | 最接近的工程场景 |
|---|---|---|---|---|
| 连续时序融合编码器 | LUMOS | 同时建模行为统计、事件上下文和静态属性 | 每个时间点一个连续 daily token | 多指标未来行为预测 |
| 离散用户 tokenizer | FOUNDv2 | 压缩多源长历史并保留跨源共性与来源差异 | 多级离散用户 token | 用户表征复用、召回或排序特征 |
| 结构化表格编码器 | TableGPT2 | 保留行列结构并接入语言模型 | 固定数量的列 token | 整表问答、分析与指令生成 |
| 表格主干上的模态适配器 | MultiModalPFN | 让图像/文本进入 TabPFN | 表格兼容的多模态 token | 表格为主的分类或回归 |
| 多模态序列推荐编码器 | MP4SR、Molar、MLLM-MSR | 在交互顺序中加入物品图文语义 | item embedding、用户序列 embedding 或偏好摘要 | 下一物品预测 |

### 1. 连续时序融合编码器

| 模型 | 输入粒度 | 模态前端 | 时序主干 | 融合位置 | 输出表示 | 训练目标 | 发布边界 |
|---|---|---|---|---|---|---|---|
| LUMOS | 按日排列的行为统计；同日事件；静态属性 | 三路独立两层 MLP | Transformer encoder；无 self-attention 的 future decoder | 三路 embedding 在每个时间点拼接，经投影 MLP 形成 `d_model` token | 每个未来时间点的多任务行为向量 | 多个分类与回归目标联合训练 | 论文公开；未发现官方代码或权重 |

**结构路径**：`activity_t / event_t / static → MLP → concat → projection → daily token_t → Transformer encoder → future event query cross-attention → prediction heads`

### 2. 离散用户 Tokenizer

| 模型 | 输入粒度 | 模态前端 | 压缩主干 | 融合机制 | 输出表示 | 训练目标 | 发布边界 |
|---|---|---|---|---|---|---|---|
| FOUNDv2 | 文本画像；多源行为窗口；结构化表格属性 | 文本/行为用预训练 embedding；表格用 MLP | Multi-View RQ-VAE | 共享码本编码跨源共性，来源专属码本编码残差 | 短离散用户 token 序列 | token、时间窗口、语义三级未来对齐 | KDD 2026；公开 MRQ-VAE 核心代码，不含完整工业训练栈 |

**结构路径**：`text / behavior / table → source encoders → shared latent space → shared codebook + source-specific residual codebooks → user tokens`

### 3. 结构化表格与表格主干编码器

| 模型 | 输入粒度 | 表格编码器 | 其他模态编码器 | 连接器/融合 | 下游主干 | 输出表示 | 发布边界 |
|---|---|---|---|---|---|---|---|
| TableGPT2 | 单元格、行、列、整表 + 用户指令 | 无位置 embedding 的行列双维注意力；分层提取单元格/行/列/整表表示 | 文本使用 Qwen2.5 token embedding | 每列配置 learnable queries，以 Q-Former 风格 cross-attention 压缩变长行数 | Qwen2.5 decoder | 固定数量列 token + 文本 token | 当前公开 TableGPT2-7B 是 standalone decoder；table encoder 尚未开放 |
| MultiModalPFN | 样本×特征表格 + 每样本图像或文本 | 冻结 TabPFN v2；块内依次做 feature attention 与 sample attention | 图像用 DINOv2 ViT-B/14 `[CLS]`；文本用 ELECTRA `[CLS]` | MGM 将单向量扩成多 token；CAP 用 cross-attention 压缩和平衡 token 数 | TabPFN backbone | 与表格空间对齐的图像/文本 token | CVPR 2026；代码公开，需用户另备 TabPFN checkpoint |

### 4. 多模态序列推荐编码器

| 模型 | 行为输入 | 物品模态前端 | 序列编码器 | 融合方式 | 用户表示/输出 | 训练目标 | 统计表格分支 |
|---|---|---|---|---|---|---|---|
| MP4SR / MSM4SR | 有序 item 交互序列 | 图片经 CLIP 检索关键词；图像关键词和文本描述统一经 Sentence-BERT | 文本序列与视觉序列分别编码，再进 Transformer sequence layers | 随机 dropout 后做 complementary sequence mixup | 多模态用户序列 embedding；下一 item 分数 | 模态内 next-item prediction + 跨模态对比损失 | 无 |
| Molar | 有序 item ID 与内容序列 | MLLM 取 `[Cur_Item]` hidden state 作为图文 item embedding | DUEG 编码多模态 item embedding 序列 | 内容侧用户表示与 ID-CF 用户表示做后对齐 | 对齐后的用户 embedding；下一 item 分数 | 序列推荐损失 + 对比对齐 | 无 |
| MLLM-MSR | 有序 item 序列与历史偏好 | MLLM 将每个 item 图文压成文本摘要 | 递归更新用户偏好摘要，不使用独立连续时序 encoder | 新 item 摘要与已有偏好文本迭代融合 | 文本化用户偏好摘要 | 指令式下一 item 推荐 | 无 |

这三类模型的“多模态”来自物品内容，不包含 LUMOS 的连续行为统计，也不包含 FOUNDv2 的结构化表格属性。

## 编码器设计

### LUMOS：先在每个时间点融合，再做时序建模

LUMOS 以天为时间单位。用户活动向量、事件上下文向量和静态用户属性分别进入两层 MLP，三路 embedding 拼接后再经投影 MLP，形成一个 `d_model` 维 daily token。历史 token 由 Transformer encoder 自注意力编码。未来已知事件形成 decoder query，通过 cross-attention 查询历史；decoder 去掉 self-attention，使每个未来时间点只依赖历史与该时间点的已知上下文。最后的投影头同时输出多个行为指标。

这种设计适合“行为序列本身就是一串连续统计向量”的任务。它没有把数值转成文本，也没有先离散成 item ID。

### FOUNDv2：先统一语义空间，再做多视图残差量化

FOUNDv2 先编码文本、行为序列和表格属性。论文与本库来源显示，文本/行为主要借助预训练 embedding 模型，表格保留专用 MLP 通道。连续表示随后进入 Multi-View RQ-VAE：

1. 共享码本学习跨来源共性；
2. 来源专属码本保留不同数据源的残差；
3. 多级残差量化将用户历史压缩成短离散 token 序列；
4. token、时间窗口、语义三级未来对齐目标，使 token 保留短期转移和长期周期信息。

它更像用户 tokenizer，不是一个直接生成文本答案的 LLM。

### TableGPT2：表格结构编码后接语言模型

论文中的 Semantic Table Encoder 不按普通文本顺序扫描单元格，而是在无位置 embedding 的条件下分别建模行向和列向关系。表格—语言 Adapter 为每列配置若干 learnable queries，通过 Q-Former 风格 cross-attention 把变长的行压成固定数量列表示，再映射到 Qwen2.5 embedding 空间并与文本 token 拼接。

发布边界需要单独说明：截至 2026-10-28，Hugging Face 上公开的 TableGPT2-7B 是可独立运行的 decoder，模型卡明确写 table encoder 仍在准备中；其示例仍把 `df.head()` 序列化成文本输入。因此，论文架构可作为设计参考，但公开权重不能直接证明完整表格编码器已可用。

### MultiModalPFN：把图像/文本变成 TabPFN 可消费的 token

MultiModalPFN 保留 TabPFN v2 的表格分支，并为图像和文本增加独立编码器：

- 表格：冻结的 TabPFN v2 encoder，交替执行 feature attention 与 sample attention；
- 图像：DINOv2 ViT-B/14 的 `[CLS]`；
- 文本：ELECTRA 的 `[CLS]`；
- 连接器：Multi-head Gated MLP 将单个非表格向量扩展为多个候选 token，Cross-Attention Pooler 再压缩为平衡后的 token 集。

所有 token 对齐到 TabPFN 空间后进入其 backbone。该路线适合表格为主、图像/文本为辅助的分类或回归，不适合直接替代长行为序列模型。

### MP4SR 与 Molar：行为序列中加入物品内容

MP4SR 先用 CLIP 从图片检索关键词，再让图片关键词和文本描述都通过 Sentence-BERT，从源头缩小图文表示差异。文本序列与视觉序列分别编码，经过随机 dropout、互补 mixup 和 Transformer 层；训练同时使用模态内 next-item loss 与跨模态对比损失。

Molar 则用 MLLM 把单个物品的图文压成 `[Cur_Item]` hidden state，再由 DUEG 编码物品 embedding 序列。内容侧用户表示最后与 ID-based 协同过滤用户表示做对比式后对齐。它保留了协同信号，但没有统计表格专用分支。

## 工程选型

| 需求 | 更接近的公开设计 | 原因 |
|---|---|---|
| 短/中行为序列 + 连续统计 + 静态字段 | LUMOS | 每个时间点直接融合连续向量，时序结构明确 |
| 多源长历史需要压缩成可复用 token | FOUNDv2 | 共享/专属码本和多级残差量化控制容量 |
| 整张表与自然语言联合问答/分析 | TableGPT2 论文架构 | 行列结构编码 + 列级查询压缩 |
| 小中型表格 + 图像/文本预测 | MultiModalPFN | 复用 TabPFN prior，并控制非表格 token 数 |
| 下一物品预测 + 物品图文内容 | MP4SR / Molar | 专门建模行为顺序与内容模态 |
| 接入 Qwen3-VL 做受控实验 | LUMOS 式连续前端 + 独立 projector | 先保留统计和时序结构，再按需生成少量 soft token |

## 边界

- “多模态”在这些论文里含义不同：有的是连续行为、事件和静态属性，有的是表格、图像和文本，还有的是 ID、图像与商品描述。
- 论文公开、代码公开和权重可下载是三种不同状态。
- 以上架构不能跨任务按论文分数排序；数据规模、目标、候选集和服务约束不同。
- 对固定 schema 的分类任务，LightGBM/CatBoost、GRU/BERT4Rec、FT-Transformer/TabPFN 仍应保留为强基线。
