## 设计取舍的三个轴

### 轴 1：LLM 介入程度（运行时 vs 训练期）

- **ARGOS** 把 LLM 限制在训练期生成规则，运行时纯规则推理 → 最可复现、推理最快（3.0×–34.3× 加速），但牺牲运行时自适应。
- **CALM/SAGE/AD-Agent** 运行时依赖 LLM → 更灵活但引入方差/成本；CALM 用 temperature 与闭环微调缓释，SAGE 用 temperature=0 + rubric 打分缓释，AD-Agent 用 Reviewer dry-run 纠错。

### 轴 2：可解释中间表示

- ARGOS = Python 规则代码；SAGE = 证据记录 + 诊断报告；CALM = LLM 判官的理由；AD-Agent = 流程脚本。**可解释性递减**：规则 > 证据报告 > LLM 理由 > 黑箱脚本。

### 轴 3：自适应机制

- CALM 闭环持续微调（实时）> ARGOS 周期重训 > SAGE/AD-Agent 静态。**自主性递减**：CALM > ARGOS > SAGE/AD-Agent。

## 与风控治理的同构（[[流量风控技能栈与Agent治理]]）

四法在治理诉求上与风控"可解释 + 可追溯 + 可干预"一一对应：

- ARGOS 规则可审计 ↔ 风控全链路追溯、归因重构。
- CALM LLM-as-a-Judge ↔ 风控控制论闭环（传感器-控制器-执行器-反馈，[[来源-基于控制论的内容风控系统全流程方案-2026-06-21]]）。
- SAGE 诊断可结构化 ↔ 风控可干预处置（告警级别 + 建议动作）。
- AD-Agent 流程可自动化 ↔ 风控技能栈治理（Agent 调用链自动化）。

## 小结

四法无绝对优劣，按场景选：**高可复现 + 低运行时成本** → ARGOS；**实时漂移自适应** → CALM；**结构化诊断 + 证据可审** → SAGE；**非专家快速建管线 + 开源可扩展** → AD-Agent。生产环境可分层编排：AD-Agent 建管线 → ARGOS 落规则 → SAGE 做诊断 → CALM 管漂移。

**延伸两法（垂域/安全攸关）**：**AgentFM** 适用于分布式系统运维——按角色拆分 + meta-agent 编排，适合"角色边界清晰、需统一归因"的 DBA/运维场景（preliminary，未开源）。**IoT-XAI** 适用于关键基础设施——LLM + XAI 混合强可解释 + 人在回路，适合"安全攸关、需人类可审计"的 IoT/CPS 场景（仿真口径，未开源）。二者不在通用时序 SOTA 竞争线上，而是补"垂域落地 + 可解释治理"两个维度。

## 冲突与不确定性

- 各法量化口径不可直接横比：ARGOS（F1）/ CALM（ROC AUC，所读页未给数字）/ SAGE（benchmark 排名，所读页未给数字）/ AD-Agent（成功率+AUROC）/ AgentFM（IoTDB 角色分 precision/recall/F1，preliminary）/ IoT-XAI（仿真准确率 95.4% vs 82.1%，AUC 0.972）。
- 开源状态：仅 AD-Agent 明确开源；其余（含 AgentFM、IoT-XAI）未在读页给出仓库，复现需联系作者或等发布。
- "可解释性"在各法中内涵不同（规则代码 vs 证据报告 vs LLM 理由 vs XAI 可视化 vs 角色拆分），同词不同义，对照需谨慎。
- AgentFM / IoT-XAI 均为 preliminary / 仿真口径，非成熟系统级定论，宜作"范式与场景对照"。
