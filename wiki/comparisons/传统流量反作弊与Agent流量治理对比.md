# 传统流量反作弊与Agent流量治理对比

> 关联来源：[[来源-搜索归档-流量风控skills-2026-06-20]]

## 对比目的

明确“已有流量反作弊体系”与“面向 Agent 的流量治理”之间的边界与增量能力，避免把旧方案直接套用到新场景。

## 对比表

| 维度 | 传统流量反作弊 | Agent 流量治理 |
|---|---|---|
| 主要对象 | 点击/曝光/转化中的无效与作弊流量 | Agent 驱动的 API/工具调用链行为 |
| 核心信号 | 设备、IP、网络环境、基础行为异常 | 指纹 + 时序 + 调用链 + 参数漂移 |
| 检测粒度 | 单事件或短窗口 | 跨步骤链路与会话级行为 |
| 处置方式 | 过滤、打标、返款策略 | 限流、熔断、二次验证、skills 下线、审计追溯 |
| 归因体系 | 渠道与触点归因 | “用户路径 vs 代理路径”双轨归因 |
| 风险焦点 | 刷量、假量、低质量流量 | 越权调用、插件污染、批量异常执行 |

## 结论

1. **传统反作弊是必要基础，但不足以覆盖 Agent 风险面。**
2. **网关层可见性 + 调用链建模**是 Agent 治理的关键增量。
3. **治理闭环**（识别-处置-追溯-归因）比单点识别更重要。
