## 内部文章共同结论

两篇文章共同支持：

- Jev 是 `State + Questions → typed decisions + probabilities` 的语义决策模型；
- `Choice`、`Score`、`Noul` 适合有界分类、路由、评分和语义是非判断；
- 类型安全只能防止输出 Schema 越界，不能防止模型在合法选项中判断错误；
- 更合理的分工是通用模型负责生成和复杂推理，Jev 负责流程岔路判断，代码负责精确计算和执行；
- 生产接入前需要影子运行、自有数据校准、低置信度升级、版本固定和回放评测。

## 内部实测补充

《Jev 实测》使用真实接口覆盖内容审核、工单紧急度、意图识别、检索过滤、销售线索、模糊判断和 30 个补测 Case，并与 Seed 2.0 Lite 做结构化输出对照。

关键发现：

- 多数语义分类、是非和评分任务的判断方向一致；
- Jev 在错误大数加法上出现明显误判，精确计算应交给代码；
- 对“1 月 31 日按月续订、2 月 28 日是否准时”这类规则未定义问题，Jev 与 Seed 出现分歧，说明系统应先明确业务规则；
- 重复调用的分类结论较稳定，但具体概率会受问题措辞影响；
- 完全无意义输入有时仍会得到高置信答案，需要额外拒绝和兜底逻辑；
- Jev 仅处理文本，不能从图片 URL 中真正读取图像。

文章报告的免费接入链路约 1.3–1.6 秒，Seed 2.0 Lite 对照约 3–9 秒。这是作者当时的网络、免费模型和接入方式下的实测，不是正式服务的统一延迟承诺。

## 公开与社区补充

### 1. 我把 Jev 部署到了一个开源 Agent Harness 中

- 链接：[WaytoAGI 飞书页面](https://waytoagi.feishu.cn/wiki/NkknwTOIzimajRkwBepc3KbWnwe?from=from_copylink)
- 原始转载：[I put Jev inside an Open Agent Harness](https://x.com/akshay_pachaar/status/2109678653974155459)
- 时间：2026-10-13
- 主题：Jev + TrueForge

分享以客户请求匹配 GitHub issue 为例，先用代码将 300 个 issue 短列为 10 个候选，再让 Jev 从候选中选择匹配项或 `none`，低置信度结果交给强模型复核，最终由人批准写入。

分享强调 TrueForge 的四种上下文工程机制：延迟加载工具、超大结果外置到沙箱、Code Mode 和 Subagent；同时用 Harness 保存凭证、审批写操作并维护会话状态。

作者报告 40 条请求中 Jev 版本和无 Jev 版本均命中 37 条，但 Jev 版本把更多不确定结果升级复核，因此捕获了更多错误。该结果只适用于这组测试和阈值，不能直接外推为普遍性能结论。

## 证据与限制

- **高置信**：Jev 的核心定位、三类输出、类型安全边界和“生成/判断/执行”分工，由两篇内部文章与官方资料交叉支持。
- **中置信**：内部实测支持 Jev 在有界语义判断上的稳定性和工程价值，但样本由作者设计，不能直接外推到其他业务。
- **低置信/待复现**：40 条请求命中 37 条、与 Opus 同精度、1/150 成本、200x/450x 等外部数字均依赖具体工作流、模型、候选集、阈值和计费口径。
- **限制**：本次没有取得 Jev 内部权重、训练数据或大规模业务评测；内部文章仍属于作者研究与实测，不等于平台级承诺。
