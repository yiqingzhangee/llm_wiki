## 内容摘要

该文将 Agent 系统类比为“面向交付物的声明式操作系统”，提出以 **model + harness + surface** 为核心三层，并把多 Agent 协作、运行时治理、沙箱隔离、记忆层级、可观测与审批机制统一到类似 K8s 的抽象框架中。

文中强调：

1. 交互层应从“操作 Agent”转向“声明目标交付”；
2. runtime（harness）是稳定上线能力的关键载体；
3. Swarm 调度不只是并发执行，还包括任务拆解、关键路径优化与治理约束；
4. 随着模型能力增强，harness 的“可让渡层”会收缩，但权限/审计/并发/可观测等“不可让渡层”仍是长期核心。

## 可提取的关键结论

- **Agent 工程的竞争焦点从“模型能力”转向“运行时治理能力”**：包括权限、审计、可恢复、可追踪。
- **多 Agent 不是目标，调度质量才是目标**：任务分解、并行深度、汇聚策略决定系统上限。
- **应采用“为删除而构建”的 harness 策略**：模型能接管的编排逻辑应可移除，保留稳定的基础设施层。
