# 来源：LoRA（低秩适配）原理（2026）

- **原始路径**：[`raw/transcripts/LoRA.md`](../../../raw/transcripts/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%9F%BA%E7%A1%80/LoRA.md)
- **类型**：面试讲解 / 参数高效微调原理说明
- **同步日期**：2026-09-03
- **证据等级**：**E3**（高密度解释型材料，适合沉淀原理框架与术语澄清，不宜单独承载严格量化结论）

## 一句话摘要

这份材料把 **LoRA（Low-Rank Adaptation）** 压缩成适合工程沟通的最小骨架：**冻结主干权重，只训练低秩增量矩阵 `A` 与 `B`，推理时把 `BA` 合并回原权重，因此显存低、权重小、切换快，且在合并部署时几乎不增加推理时延**。

## 核心结论

### 1. LoRA 的本质不是“新增一层”，而是“对原权重做低秩增量”

材料用最小公式概括 LoRA：

$$
\Delta W = BA, \quad h = Wx + BAx
$$

其中主干权重 `W` 冻结，只训练低秩矩阵 `A`、`B`。这说明 LoRA 的核心不是像 Adapter 那样在网络里长期插入一个新模块，而是把**任务相关的权重变化压缩成低秩增量**。

### 2. LoRA 的工程价值来自“三小一不变”

- **训练参数小**：只训练低秩矩阵，显存与优化状态成本显著下降；
- **权重文件小**：便于为不同任务保存多套适配权重；
- **切换成本小**：多任务部署时更适合按场景装卸；
- **推理主链不变**：若将 `BA` 合并回原权重，线上推理路径基本保持不变。

因此，LoRA 适合“底座稳定、任务分叉多、算力受限”的场景，是参数高效微调（PEFT）家族里最常见的默认起点。

### 3. 它解决的是“如何便宜地学会任务增量”，不是“如何完成偏好/推理对齐”

材料聚焦 LoRA 本身，因此很适合与 [[来源-GRPO分组相对策略优化原理-2026]] 对照：

- **LoRA** 解决的是“**参数怎么高效更新**”；
- **GRPO** 解决的是“**策略怎么依据奖励继续优化**”。

二者常常串联使用，而不是互相替代：先用 SFT/LoRA 学会任务，再用 DPO/GRPO 这类对齐方法继续优化偏好或推理行为。

### 4. LoRA 的落点已经从语言模型扩展到多模态与扩散模型

虽然原始材料是通用面试讲解，但它与本库已有材料形成明显互证：

- 在 [[Stable-Diffusion微调技术矩阵]] 中，LoRA 已是 SD 微调默认路线之一；
- 在 [[来源-Qwen2.5与Qwen3微调深度调研-2026-06-21]] 中，LoRA / QLoRA 又成为语言模型 SFT 阶段的主流选择。

这说明 LoRA 更像一种**跨模态通用的参数更新约束**，而不只是某个单独模型家族的技巧。

## 冲突与不确定性

- 这是一份**解释型材料**，适合沉淀概念，不适合直接引用其中的参数量/显存节省比例做严格横比。
- 材料突出“推理无额外延迟”，这一结论默认建立在**权重已合并**前提下；若做动态 LoRA 装载或多 LoRA 叠加，实际工程仍可能有额外代价。
- 文中提到“原始论文主要作用于 Attention 的 Q、V”，这适合作为历史起点，但当前工程实践已常扩展到 `K/O` 甚至 `MLP`，不能把早期实现边界误读为今天的硬约束。
