# 来源：GRPO（分组相对策略优化）原理（2026）

- **原始路径**：[`raw/transcripts/GRPO原理.md`](../../../raw/transcripts/GRPO%E5%8E%9F%E7%90%86.md)
- **类型**：面试讲解 / 对齐训练算法原理说明
- **同步日期**：2026-09-03
- **证据等级**：**E3**（高密度解释型材料，适合澄清 PPO/GRPO 关系与训练链路，不宜单独承载性能优劣定论）

## 一句话摘要

这份材料把 **GRPO（Group Relative Policy Optimization）** 概括为：**取消 PPO 的 value head，不再单独学习价值函数，而是对同一 prompt 的多条回答按奖励做组内归一化，用“相对好坏”直接构造优势函数，再配合 clip + KL 约束完成策略更新**。

## 核心结论

### 1. GRPO 解决的是“大模型对齐里优势函数怎么便宜、稳定地估计”

传统 PPO 在大模型对齐里往往需要：

- 一个策略模型；
- 一个价值网络 / value head；
- 奖励模型；
- 外加较重的稳定化技巧。

这份材料强调，GRPO 的关键简化是**直接移除 value head**，改为在同一 prompt 下采样 `G` 条回答，再对奖励做组内标准化：

$$
\hat{A}_i = \frac{r_i-\mu_r}{\sigma_r}
$$

也就是说，它不再依赖“单点价值估计”，而依赖“**同题多答的相对排序**”。

### 2. 它保留了 PPO 的约束思想，但把优化重点改成“相对优势”

材料明确指出，GRPO 并不是完全抛弃 PPO，而是保留 PPO-clip 与 KL 惩罚这些“防止策略漂移”的核心护栏，只是把优势项替换为组内相对优势。

这意味着 GRPO 的工程意义主要有两层：

- **省掉价值头，减轻显存与训练复杂度**；
- **降低对奖励绝对数值尺度的敏感性**，更强调同组样本之间谁更好。

### 3. GRPO 与 LoRA 不在同一层：一个管“怎么训得动”，一个管“往哪儿对齐”

与 [[来源-LoRA低秩适配原理-2026]] 对照时，这份来源页很有价值，因为它把训练栈的分层说清楚了：

- **LoRA / QLoRA**：控制参数更新成本；
- **GRPO**：控制策略优化方向；
- 二者常常组合出现，而不是二选一。

因此，GRPO 更适合被放进“后训练 / 对齐训练”这一层，而不是当作通用微调的替代名词。

### 4. GRPO 的代价不是白拿的：省 value head，换来多样本采样成本

材料同时提醒了一个常被忽略的现实：

- 若每个 prompt 只生成 1 条样本，就不存在组内比较；
- GRPO 要想稳定，往往必须每组生成多条回答；
- 如果组内回答过于相似，标准化后的优势会接近 0，训练信号可能变弱。

所以它不是“无代价更优”，而是把成本从**价值估计**转移到了**多样本采样与奖励评估**。

### 5. 它适合作为本库里“推理类对齐”与“风控 GUI Agent 奖励训练”的连接点

这份材料与已有页面形成两类直接连接：

- [[来源-Qwen2.5与Qwen3微调深度调研-2026-06-21]] 已将 GRPO 作为推理类对齐主流算法之一提及；
- [[来源-视频审核与电商风控GUI-Agent批次-2026]] 中的 **RISK-R1** 也明确采用基于 **GRPO** 的强化微调，并引入输出级 / 步级 / 多步轨迹级奖励。

因此，GRPO 在本库里不只是“LLM 对齐算法名词”，也是把**推理优化**和**GUI Agent 行为训练**连起来的桥梁。

## 冲突与不确定性

- 这是一份**解释型材料**，适合做算法骨架澄清，不适合单独用来证明“GRPO 必然优于 PPO / DPO”。
- 材料提到“参数量减半”，更准确地说，是**省去了独立 value head/价值网络带来的额外成本**；对大模型整体训练成本的影响仍取决于采样数、奖励模型、参考模型与实现细节。
- “训练更稳”在不同任务上依赖奖励模型质量与组内样本多样性；如果奖励模型偏差很大，GRPO 一样会把系统往错误方向推。
