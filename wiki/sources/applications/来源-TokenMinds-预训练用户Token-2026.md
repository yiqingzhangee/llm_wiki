# 来源：TokenMinds——面向大规模推荐系统的预训练用户 Token 与 Embedding（2026）

> 原始来源：[`raw/articles/llm4rec/2606.25147v1.pdf`](../../../raw/articles/llm4rec/2606.25147v1.pdf)（arXiv 2606.25147 [cs.IR]；Google DeepMind / YouTube，作者含 Qingyun Liu、Lichan Hong、Li Wei、Xinyang Yi 等）。已部署在多个 YouTube 表面、全量用户流量（数十亿用户）上。
>
> 关联概念：[[LLM用户表征基础模型与场景适配]]、[[LLM推荐系统的分层改造与评估]]、[[来源-LLM推荐技术范式与落地边界-2026]]。

## 一句话主张

在工业推荐场景，用户建模通常只产出定长稠密 embedding，受固定维度表征能力限制；而"用 LLM 生成文本型用户 token"虽能捕获主题共现，却难以捕获深层序列行为动态、也难以接地到物品属性。TokenMinds 把 PLUM 框架从**物品检索**扩展到**用户建模**，用一个由预训练 LLM 适配的 encoder-decoder 同时产出 **基于 Semantic ID(SID) 的离散用户 token** 与 **稠密用户 embedding**，在保持与依赖稠密 embedding 的下游模型兼容的同时，提供离散、语义可接地的用户表示。

## 关键设计

- **双输出**：离散 SID 用户 token + 稠密 user embedding，二者互补，服务于不同下游排序系统。
- **共享 SID 词表自然外推到跨场景建模**：把长视频与短视频行为统一进同一模型，显著降低训练与服务成本（跨场景统一代价）。
- **encoder-decoder 结构**：由预训练 LLM 适配而来（延承 PLUM 的范式）。
- **动机对照**：SID-based 物品 tokenization 已被证明能改善生成式推荐的泛化，但**基于 SID 的用户表示此前基本未被探索**——这正是本工作的补位。

## 在用户表征四路线中的位置

TokenMinds 放在 [[LLM用户表征基础模型与场景适配]] 的**统一量化与跨场景/容量**路线上，并显式补上了"**离散 SID 用户端**"这一此前空缺：

- 与 [[来源-FOUNDv2统一量化用户Tokenizer-2026]] 同为"压缩用户历史"方案，但 TokenMinds 用 **LLM encoder-decoder + 共享 SID 词表**，并明确要做 **跨场景（长/短视频）统一**；FOUNDv2 侧重共享/源特定码本与多尺度预训练。
- 它**不应与物品 Semantic ID 混为一谈**：TokenMinds 是**用户**侧的 SID 化表示（供用户建模），与物品目录/生成约束无关；这正是既有 [[来源-LLM推荐技术范式与落地边界-2026]] 关于"语义 ID 是架构取舍"论断在**用户侧**的延伸样本。

## 关键实证与边界

- 主下游用例确认了 SID-based user tokens 在**工业规模**的可行性，且**token 与稠密 embedding 在多个生产排序系统上提供互补价值**。
- 受 arXiv v1（2026-06-23）信息量限制，离线指标与各表面指标细节未在本页展开；上线收益按"不同生产排序系统互补"来定性表述，不应拼成统一 CTR/GMV 排行榜（与既有用户表征批次的证据边界一致）。

## 冲突与不确定性

1. "LLM 文本型用户 token 捕捉主题共现而非深层序列行为"是对**别的方案**的批评，不是 TokenMinds 自身局限；它对 SID 抽样的序列接收能力应回原文方法节核验。
2. 精确指标、模型容量、成本节省量、跨场景收益数值需回 arXiv 2606.25147 原文核验；本页按报告口径定性记录。
