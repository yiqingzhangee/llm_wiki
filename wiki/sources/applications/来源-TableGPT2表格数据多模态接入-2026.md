## 内容提要

原始转录将 TableGPT2 描述为把数据库、表格和 JSON 等结构化数据作为独立模态接入语言模型的方案：由表格编码器保留 schema 与单元格内容，经适配器投影到与文本交互的表示空间，再与语言主干联合处理。转录还提到持续预训练、指令微调、Python/SQL 工具调用以及金融、医疗、工业等应用设想。

## 可吸收的设计信号

1. **表格不是天然文本。** 列语义、单位、有效位数、缺失和跨列关系应由专门通道保留；把表格序列化为文本可作为低成本基线，但不能默认无损。
2. **连接器与主干职责分离。** 表格编码器/投影器负责将结构化表示接入语言主干；语言模型负责任务条件化解释、问答或代码生成。该分工与外部连续特征适配器、LoRA 的职责区分一致。
3. **工具调用仍是确定性边界。** 对 SQL、Python、统计计算和阈值判断，生成模型可提出查询或解释结果，但应由受控执行器复算并保留审计记录。
4. **联合训练不替代强基线。** 面向固定 schema 的预测任务，树模型、表格 Transformer、文本化 LLM、独立编码器晚融合都应处于同一消融与服务 SLO 比较中。

## 不可直接采信的表述

- 原始转录给出的训练 token、样本比例、准确率、平均提升幅度和“超越某模型”等数值，未经本次回原论文逐项核验，不进入跨研究性能比较。
- “首次”“最强”“替代传统 BI”等营销式结论不构成可迁移的工程结论。
- 金融、医疗和工业案例是应用候选，仍需按数据可见性、隐私、延迟、校准与人为复核要求分别验证。

## 对既有结论的影响

该材料支持 [[多模态结构保真与统一对齐]] 中“统一接口不等于统一原始表示”的原则，也为 [[异构数据接入大模型的四档方案对比-2026]] 的“独立编码器 + 投影器”路线补充了表格模态案例。它不推翻既有“先文本化与强基线、再逐层升级”的门禁；反而说明端到端融合需要更严格的结构消融和部署验证。

## 一手核验补充（2026-10-28）

论文中的 Semantic Table Encoder 使用无位置 embedding 的行列双维注意力，并通过分层特征提取同时建模单元格、行、列和整表。表格—语言 Adapter 对每列执行 Q-Former 风格 cross-attention，用固定数量 learnable queries 将变长行压缩为列表示，再对齐到 Qwen2.5 文本 embedding 空间。

公开状态与论文架构并不等价。官方 [TableGPT2-7B 模型卡](https://huggingface.co/tablegpt/TableGPT2-7B) 明确说明：

- 目前公开的是 7B standalone decoder；
- table encoder 仍在准备中；
- QuickStart 仍把 `df.head().to_string()` 作为文本输入。

因此，TableGPT2 论文可作为表格专用编码器设计证据，但公开的 7B 权重不能直接当作“完整表格编码器已经可下载”的证据。
