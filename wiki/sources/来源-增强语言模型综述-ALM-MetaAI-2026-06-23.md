## 摘要

本综述由 Meta AI 研究团队撰写（Yann LeCun 参与署名），提出了**增强语言模型**（Augmented Language Models, ALMs）这一统一概念，用于描述那些在标准语言建模目标基础上，通过推理（Reasoning）和工具使用（Tools）来突破纯统计语言建模范式的模型。文章从动机出发定义了推理、工具、行动三个核心概念，并将其组织为一个三维分类体系：推理增强策略（通过提示激发、递归式提示、显式训练）、工具使用与行动（调用其他模型、信息检索、符号计算、虚拟与物理世界行动），以及学习方式（监督学习 vs 强化学习 vs 启发式规则）。结论指出，ALM 方向有潜力缓解传统语言模型的可解释性差、一致性和可扩展性等根本局限。

## 关键主张

1. **纯统计语言建模范式的根本缺陷**：LLM 通常在"单一参数化模型 + 有限上下文"设定下训练，导致必须极度庞大才能在参数中存储大量知识。幻觉、规模依赖、持续学习困难等问题的根源在此。

2. **推理与工具是一体两面**：推理将复杂任务分解为简单子任务，工具则保证每一步的正确性（如精确计算、事实检索）。两者结合，使 ALM 能够在不依赖启发式规则的前提下解决更广泛的复杂任务并具备更好的泛化能力。推理是"组合工具以解决复杂任务的机制"，工具是"确保正确分解下推理不会失败的手段"。

3. **推理的三种实现范式**：（a）**通过提示激发推理**：思维链（CoT）是最代表性的零样本/少样本技术，自一致性（Self-consistency）通过采样多样化推理路径并选最一致答案进一步提升性能；（b）**递归式提示**：显式将问题分解为子问题序列，如 Least-to-most 提示，支持解决比演示示例更难的问题；（c）**显式训练推理**：通过草稿本（Scratchpad）或工作记忆 token 在训练阶段教会模型逐步推理，避免提示长度昂贵和示例手动构造的问题。

4. **工具使用的五大类**：（a）**调用其他模型**：包括迭代式调用自身（如 PEER 通过反复规划和编辑改进输出）、跨模态模型组合（Flamingo、Socratic Models）；（b）**信息检索**：稀疏/稠密检索器 + 条件建模（REALM、RAG、RETRO、Atlas），检索增强可缩小与更大参数模型的性能差距；（c）**搜索引擎查询**：LaMDA、BlenderBot、ReAct 等使模型在推理中间步骤主动发起搜索；（d）**符号计算**：通过 Python 代码解释器等执行精确计算；（e）**虚拟与物理世界行动**：网页搜索、机械臂操控等具有外部效应的工具调用。

5. **学习方式的辩证选择**：启发式规则简单但缺乏泛化性，监督学习需要高质量标注示范，强化学习可探索更优策略但训练复杂、需要可靠奖励信号。不同 ALM 系统在不同场景下采用不同策略去学习何时以及如何使用推理和工具。

6. **推理的务实定义**：从工程角度看，ALM 语境下的"推理"更准确地描述为"在给出答案前为模型提供更多计算步骤"。社区尚不能确定模型是否在真正推理，还是仅生成了更长的上下文以提高正确预测概率，但术语已被广泛接受。

## 核心架构洞察

- **检索增强的语言模型正在缩小与超大模型的差距**：RETRO 使用冻结的 BERT 检索器 + 分块交叉注意力，在不进一步训练检索器的情况下达到与 GPT-3 相当的性能；Atlas 联合训练检索器与 seq2seq 模型，以显著更少的参数获得强少样本学习能力。
- **ReAct 是推理与工具协同的里程碑**：在推理与行动之间交替进行，在问答、事实核查和网络导航等多种任务上均表现出色，证明了推理和工具不应被孤立增强。
- **工具调用可统一到同一 API 范式**：无论是调用计算器、搜索引擎还是机械臂，从模型视角看都是通过特殊 token 或规则调用某个外部模块，输出纳入上下文——这为 ALM 的理论统一提供了基础。

## 待验证 / 局限性

- **"推理"概念的定义模糊**：社区对语言模型是否真正在进行推理仍存争议，ALM 采用了务实的操作化定义（"更多计算步骤"），但这可能掩盖了对推理能力的过度乐观解读。
- **覆盖时效性**：本文发表于 2023 年 2 月，后续推理技术（如 Tree-of-Thoughts、Graph-of-Thoughts）和工具增强方案（如 MCP 协议、Function Calling 标准化）当时尚未出现，部分结论的普适性需要更新验证。
- **缺少系统性评测**：对不同推理策略和工具组合的横向对比（成本、延迟、成功率）不足，多为各工作独立报告的结果，可比性有限。
- **推理不一定总是有益**：如文中指出，多步推理也可能引入级联错误（某一步出错导致后续全部出错），回滚和验证机制的缺失是实际部署中的现实风险。
