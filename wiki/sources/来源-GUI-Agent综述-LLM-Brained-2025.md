## 摘要

本文是对“以 LLM 为大脑的 GUI 智能体”这一新兴领域的首批系统性综述之一，覆盖 500 余篇参考文献，从开发到部署的完整生命周期提供了全方位视角。论文追溯了 GUI 自动化从随机/规则/脚本式方法到机器学习增强再到 LLM 驱动范式的历史演进，系统拆解了核心架构组件（运行环境、提示工程、模型推理、动作执行、记忆），并提供了构建 LLM-Brained GUI Agent 的完整“菜谱”。同时，论文覆盖了数据集采集、专用大动作模型（Large Action Model, LAM）训练、评估基准与指标、以及真实世界应用场景。特别强调了 GUI Agent 与 API Agent 的互补关系——最优方案可能是混合架构。

## 关键主张

1. **LLM-Brained GUI Agent 的形式化定义**：在 GUI 环境中运行的智能体，以大语言模型作为其核心推理与认知引擎，用于以灵活、自适应的方式生成、规划并执行动作。可类比为“虚拟助手”，颇有 J.A.R.V.I.S. 的意味。

2. **五阶段历史演进路线**（RQ1）：早期自动化（随机/规则/脚本式）→ 机器学习增强（CV + NLP + RL）→ LLM 驱动的兴起（2023 年是关键节点，在 Web/移动/桌面三平台同时爆发）→ 工业界模型跟进（Claude Computer Use、OpenAI Operator/CUA）→ 未来混合架构。这一演进脉络的梳理是该综述的独特贡献。

3. **核心架构组件“菜谱”**（RQ2）：运行环境（Web/移动/桌面三类平台，通过截图、控件树等感知环境状态）→ 提示工程（融合用户指令 + 视觉数据 + UI 元素属性 + 上下文）→ 模型推理（通用或微调 LLM 作为推理引擎）→ 动作执行（点击/输入/手势/API 调用）→ 记忆（内部记忆追踪进度 + 外部记忆支持持续学习）。

4. **GUI Agent vs. API Agent 的权衡分析**（RQ3）：GUI 操作提供通用控制接口（高度可泛化，跨应用适用），但多步操作增加决策开销；API 调用高效直接，但受限于可用性和泛化性。最优方案是混合架构——通过 GUI 操作获得广泛兼容性，在可用时利用原生 API 最大化效率。

5. **大动作模型（LAM）的概念**（RQ5）：类比 LLM 的“语言建模”，LAM 是从 GUI 交互数据中训练出的面向动作的专用模型。通过收集用户请求、GUI 截图和动作序列三元组，经微调后使模型能在 GUI 场景中直接输出可执行动作，而非仅生成文本。

6. **数据采集的三阶段方法论**（RQ4）：自动化探索（随机或规则式遍历 GUI 收集初始数据）→ 人工标注（人类专家演示任务执行过程）→ LLM 辅助生成（利用 LLM 生成额外的指令和动作序列扩充数据集）。

7. **评估分类体系**（RQ6）：将评估指标分为三类——任务成功率（是否完成指定任务）、执行效率（步骤数、时间消耗、资源消耗）和交互质量（动作的自然度、与人类操作的相似度）。同时整理了各平台（Web/移动/桌面）的主流基准。
