# 来源：ARGOS — LLM 自主生成异常规则的时序异常检测（2025）

- **原始路径**：[`papers/2501.14170.pdf`](../../raw/articles/time_series_agent/papers/2501.14170.pdf)（arXiv 2501.14170，UW/Microsoft Research，2025-01）
- **类型**：系统论文（agent 流水线 + 模型融合）
- **同步日期**：2026-08-31
- **证据等级**：**E2**（含实验与系统设计；定量为作者报告口径）

## 一句话摘要

**ARGOS** 用 LLM 在**训练阶段**自主生成**可解释、可复现的 Python 异常规则**，部署时**不**调用 LLM——以规则代码作中间表示，同时满足异常检测系统三大刚需：可解释性、可复现性、自主性。三 Agent（Detection / Repair / Review）+ 选择器迭代修正，并与现有生产检测器做**模型融合**保精度。

## 动机：三属性不可能三角

作者据微软大规模事件管理经验，提出异常检测系统必须同时具备：

1. **可解释性**（Explainability）——on-call 工程师须理解告警原因。
2. **可复现性**（Reproducibility）——同输入同结果，否则浪费工程力。
3. **自主性**（Autonomy）——分布漂移时无需人工干预。

既有方法各缺一角：深度学习缺可解释、需调超参；LLM 直接推理不可复现（SigLLM 10 次试验结果各异）；规则法可解释可复现但需人工写规则、阈值难调（无 one-size-fits-all）。

## 方法要点

### 规则即中间表示

- 规则写成**可执行 Python**（`def inference(sample: np.ndarray) -> np.ndarray`），先在注释里描述异常规则，再写实现——对人可读、对 LLM 可生成、Turing 完备。
- 关键设计：LLM **只在训练阶段**生成规则，**运行时不调用 LLM** → 规避 LLM 非确定性，保可复现。

### 三 Agent + 选择器（迭代反馈环）

- **Detection Agent**：据数据提出初始规则集。
- **Repair Agent**：执行规则于 dummy 数据，遇语法错则用错误信息/栈轨重新提示修正，循环至语法正确。
- **Review Agent**：在验证集评估精度，若新规则劣于上一轮，给对比指标/代码 diff/错分样本供改进；可回退上一轮代码防训练阻塞。
- **Data Selector / Rule Selector**：每轮提候选规则集，选最优进入下一轮精修。

### 模型融合（Accuracy Guarantee）

- LLM 缺领域知识，生成规则可能不如生产成熟检测器。
- ARGOS 对现有检测器的**假阴性**与**假阳性**分别训练规则集，运行时**聚合**新规则 + 旧检测器预测。

## 实验与量化

- 基线对比（强基线）：**KPI 数据集 F1 +9.5%**、**Yahoo +4.8%**、**内部微软数据集 +28.3%**。
- 推理加速：KPI/Yahoo/内部 分别 **3.0× / 34.3× / 1.5×**（规则推理远快于深度模型）。
- LLM 直接生成规则的问题量化（KPI）：50 次 GPT 生成平均语法错误率 **4.8%**、平均 F1 仅 **0.129**（最佳深度法 0.819）；LLM 收敛到准确规则平均 **113 分钟**。
- 单规则示例：da403 用 z-score>3；1c35d 用滑窗均值 ±20% + level shift 检测。

## 冲突与不确定性

- 三属性框架是作者经验归纳，非普适标准；不同业务对三性权重不同。
- +28.3% 为内部微软数据集口径，外部不可复现；KPI/Yahoo 的 +9.5%/+4.8% 为公开基线对比。
- "LLM 仅训练期介入"牺牲了运行时自适应——分布漂移后需重新触发训练，自主性是**周期性**而非**实时**的。
- 未开源，方法细节（融合权重、选择器打分）披露有限。
