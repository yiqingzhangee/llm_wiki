# AI Safety 长期研究与项目路线图

> 日期：2026-10-22
>
> 个人主轴：**可审计的 Agentic AI Safety**。重点不是泛化覆盖所有 AI Safety，而是研究模型在不可信证据、长期状态和高影响工具面前，如何保持可授权、可追溯、可回放和可恢复。
>
> 项目章程见 [[AI-Safety项目组合-2026]]。

## 一句话方向

把已有的风控、Agent、图与时序、多模态、对抗样本和证据仲裁积累，收敛为一个连续问题：

> **不可信信息如何进入 AI 系统、如何改变其状态和行动，以及独立策略层如何限制、解释并恢复这些变化。**

这个方向同时覆盖三类失效：

1. **行动面**：Agent 被注入后误用工具、越权、外泄或执行写操作；
2. **感知面**：视觉注入、规避内容和对抗变换让系统看不见或误解证据；
3. **状态面**：记忆、RAG 和长期证据被投毒、过期、冲突或错误修订。

## 为什么这条路线适合当前积累

| 既有积累 | 可形成的独特能力 |
|---|---|
| briccli、Agent Harness、技能与调用链治理 | 在真实工具语义上做行动安全，而不只做聊天拒答 |
| 风控识别—处置—治理闭环 | 用影响、授权、回滚和人工复核评估安全 |
| 图像对抗、VLM 与视频审核 | 把视觉攻击放入分层审核和工具行动链 |
| EviState、时序、图与证据仲裁 | 研究跨会话污染、版本冲突和长期风险状态 |
| Wiki 证据分级与来源治理 | 建立可追溯研究资产和高质量评测协议 |

因此，最有辨识度的定位不是“通用大模型安全研究者”，而是：

> **面向高影响 Agent 的运行时治理与长期证据安全研究者。**

## 研究判断

### 1. 近期应优先做系统安全，不应先训练安全大模型

AgentDojo 与 NIST 的结果表明，攻击效果会随自适应红队和重复尝试显著变化；CaMeL 则说明控制流、数据流和 capability 可以在模型外提供更强约束。近期最有价值的工作是 benchmark、策略执行和审计，而不是先训练一个新的拒答模型。

### 2. 多模态不是独立支线，而是不可信证据入口

VPI-Bench 说明视觉内容可直接劫持 Computer-Use Agent；EVADE-Bench 说明中文真实规避内容同时挑战 OCR、规则理解和意图判断。本地图像链路又表明“看不见”与“判断错”需要不同处理。因此多模态项目应作为 Agent 安全的感知扩展。

### 3. 长期记忆安全是中期研究差异点

AgentPoison 与 PoisonedRAG 已证明低比例投毒足以产生高成功率；HoH 与 RAGuard 进一步表明，非恶意的过期和误导证据也会使 RAG 退化。当前公开工作多聚焦单次检索、目标攻击或存储完整性，较少统一处理时间 cutoff、版本、修订、撤回、来源冲突和行动授权。EviState 正好可以承接这个缺口。

## 项目递进路线

```text
0—3 个月：BRIC-SafeAct
行动安全 benchmark + capability/HITL 策略网关
        |
        | 复用事件、影响评分、策略与回放
        v
3—6 个月：MM-SafeRoute
视觉注入/规避 -> 恢复/OCR/VLM/人工的安全路由
        |
        | 复用多模态证据、来源和状态变化
        v
6—12 个月：EviGuard
跨会话投毒、过期、冲突、修订与回滚的长期证据安全
```

关键纪律：任一时点只有一个主项目。后续项目只有在前一项目产出可复用基础设施后才启动。

## 一年目标：形成可重复的研究—工程闭环

### 定位

成为团队内能独立完成“威胁建模—场景构造—基线—防御—影响评测—上线门禁”的 Agent 安全负责人。

### 必达成果

- 完成 BRIC-SafeAct，至少覆盖 6 个 mock 工具域、40 个正常任务和 120 个攻击场景；
- 做出模型外策略网关，覆盖 capability、参数约束、HITL 和审计回放；
- 完成 MM-SafeRoute 的离线 MVP，证明分层路由相对单模型直判或全量重审的价值；
- 启动 EviGuard 合成 benchmark，打通版本、cutoff、correction/retraction 与回滚；
- 形成 1 份可公开脱敏的技术报告或 benchmark、1 个内部可运行原型、2 次高质量分享；
- 建立固定的攻击场景、评测脚本、证据卡与复现实验模板。

### 能力栈

- Agent 工具与 Computer-Use Agent 威胁建模；
- OAuth/IAM、capability、最小权限、HITL 与 non-repudiation；
- 红队场景生成、自适应攻击和重复尝试评测；
- VLM/OCR/多模态内容审核与成本敏感路由；
- RAG、向量检索、版本化数据和长期记忆；
- 实验设计、统计显著性、最差切片和安全—效用 Pareto 分析。

## 三年目标：建立统一的 Agent 安全证据与评测体系

### 定位

从单项目负责人升级为“Agent 行动、感知和长期状态”统一安全架构的技术负责人。

### 目标成果

- 将三个项目收敛为统一平台：场景注册、攻击编排、策略执行、状态记录、影响评分和审计回放；
- 建立跨工具、跨模态、跨会话的标准化安全评测协议；
- 推动至少一项能力进入生产或准生产灰度，并有持续监控、回滚和人工复核；
- 形成 2—3 个可引用成果：高质量论文、行业 benchmark、开源脱敏工具或内部标准；
- 主导跨 Agent 平台、风控、多模态和安全团队的联合项目；
- 培养 2—4 人的稳定协作小组，自己聚焦问题定义、评测严谨性和关键架构。

### 研究主张

三年内应能用实证回答：

> 与只依赖模型拒答相比，显式身份、capability、证据来源、时间版本和行动策略能在多大程度上降低 Agent 的实际风险，并保留多少正常效用？

## 五年目标：成为可审计自适应 AI 系统的领域专家

### 定位

形成有辨识度的长期方向：**Auditable Adaptive AI Systems**，即能使用工具、感知多模态环境、积累长期状态，同时保持授权边界、证据溯源与可恢复性的 AI 系统。

### 目标成果

- 负责或共同负责一套组织级 Agent 安全评测与运行时治理平台；
- 在 Agent identity/authorization、长期记忆安全或证据状态评测上形成被复用的方法或标准；
- 累积一组连贯成果，而不是互不相关的论文：benchmark、系统、真实部署证据和方法论；
- 参与行业标准、开源社区或跨组织评测，建立稳定的外部影响力；
- 能把新型 Agent、VLM、记忆架构快速映射到统一威胁模型与控制框架。

五年目标不以论文数量单独衡量，而以“是否形成别人可复用的评测协议、系统组件和安全决策依据”衡量。

## 年度成果组合

每年维持四类成果，避免只做文档或只做工程：

| 类型 | 年度最低目标 |
|---|---|
| 研究证据 | 1 个严谨 benchmark 或系统研究 |
| 工程资产 | 1 个可运行、可回放的防御组件 |
| 业务证据 | 1 个离线真实分布或受控灰度结果 |
| 知识影响 | 2 次分享 + 持续维护的 Wiki/技术报告 |

## 季度复盘指标

### 研究质量

- 核心结论是否有正常任务、攻击任务和消融对照；
- 是否覆盖自适应攻击、重复尝试和最差切片；
- 指标是否区分检测、阻断、最终影响和可恢复性；
- 是否记录负结果、失效条件和证据等级。

### 工程价值

- 是否在模型之外形成可执行控制；
- 是否具备完整日志、版本、授权和回滚；
- 新项目复用旧项目基础设施的比例是否超过 60%；
- 是否有明确延迟、成本和人工负载预算。

### 方向纪律

- 同时进行的主项目是否仍为 1 个；
- 是否因为热点偏离“行动—感知—状态”主轴；
- 是否产生可公开、可内部评审或可部署的具体资产；
- 若连续两个季度没有可验证结果，是否缩小问题或停止项目。

## 不做什么

- 不把 jailbreak 拒答率等同于 Agent 系统安全；
- 不在未授权生产环境验证攻击；
- 不把不同 benchmark 的 ASR 直接拼成排行榜；
- 不以“训练更大模型”替代身份、权限、策略和审计；
- 不同时启动三个项目；
- 不把 EviState 的 deterministic fixture 当作真实风险模型结果；
- 不因追求统一架构而跳过简单规则、OCR、专模或人工基线。

## 未来四周启动清单

1. 冻结 BRIC-SafeAct v0 威胁模型，只覆盖间接注入、工具替换、外泄链和高影响写操作；
2. 定义 12 个 mock 工具及其 capability、读写副作用和确定性检查；
3. 完成首批 10 个正常任务和 20 个攻击场景；
4. 跑无防御与“白名单 + 写操作 HITL”两条基线；
5. 输出单次、10 次尝试、影响加权风险和正常任务效用；
6. 第四周做 go/no-go 复盘，再决定是否扩展域和实现 capability 数据流策略。

## 外部证据锚点

- [AgentDojo](https://arxiv.org/abs/2406.13352)：动态工具 Agent 攻防评测。
- [NIST Agent Hijacking Evaluations](https://www.nist.gov/news-events/news/2025/01/technical-blog-strengthening-ai-agent-hijacking-evaluations)：自适应攻击、任务级风险与重复尝试。
- [NIST AI Agent Standards Initiative](https://www.nist.gov/artificial-intelligence/ai-agent-standards-initiative)：身份、认证、授权和安全评测。
- [CaMeL](https://arxiv.org/abs/2503.18813)：控制流、数据流与 capability 防御。
- [VPI-Bench](https://arxiv.org/abs/2506.02456)：Computer-Use Agent 视觉提示注入。
- [EVADE-Bench](https://arxiv.org/abs/2505.17654)：中文真实电商多模态规避内容。
- [AgentPoison](https://papers.neurips.cc/paper_files/paper/2024/hash/eb113910e9c3f6242541c1652e30dfd6-Abstract-Conference.html)：长期记忆与知识库后门。
- [PoisonedRAG](https://www.usenix.org/conference/usenixsecurity25/presentation/zou-poisonedrag)：RAG 知识库目标化投毒。
- [HoH](https://arxiv.org/abs/2503.04800)：过期证据对 RAG 的影响。
- [RAGuard](https://arxiv.org/abs/2502.16101)：真实误导与冲突检索。
- [TREC 2025 RAG Track](https://pages.nist.gov/trec-browser/trec34/rag/proceedings/)：完整性、归因和一致性评测。

## 不确定性

- briccli 的沙箱、写权限和测试账号尚未确认，因此近期项目以 mock 和 dry-run 为硬边界。
- 公开 benchmark 与内部风控数据分布不同，不能直接外推绝对攻击成功率。
- 多模态基准覆盖的规则、语言和页面形态有限，需要单独报告最差切片。
- 长期状态项目的研究价值成立，但 EviState 真实数据契约尚未完成；在此之前只能验证机制，不能比较真实业务效果。
