## 摘要

生物医学知识图谱（knowledge graph，KG）编码了横跨文献、基因、通路、药物、疾病和临床试验的海量异构信息，但要将这些信息综合用于科学发现仍然十分困难。它们在结构上的差异、持续演化以及跨资源对齐能力有限，要求研究者投入大量人工进行整合，从而限制了知识探索的深度与规模。我们提出 DeepEvidence，这是一种旨在跨多种异构生物医学知识图谱开展深度研究（Deep Research）的 AI 智能体框架。不同于主要依赖互联网规模文本的通用深度研究系统，DeepEvidence 引入专门的知识图谱工具和协同探索策略，以系统性连接异构资源。该框架的核心是一个编排器，用于调度两类互补智能体：广度优先研究（Breadth\-First ReSearch，BFRS）智能体负责广泛的多图谱实体搜索，深度优先研究（Depth\-First ReSearch，DFRS）智能体负责多跳、证据聚焦的推理。系统内部逐步构建的证据图谱，为检索到的实体、关系及支持证据提供结构化记录。为支持大规模运行，DeepEvidence 提供查询多种生物医学 API 的统一接口，并设置执行沙箱，以支持程序化的数据检索、提取与分析。在既有深度推理基准以及生物医学发现生命周期的四个关键阶段——药物发现、临床前实验、临床试验开发和循证医学——中，DeepEvidence 在系统化探索和证据综合方面均展现出显著提升。这些结果表明，由知识图谱驱动的深度研究有望加速生物医学发现。

## 引言

知识图谱现已成为当代生物医学发现的基础，支持文献挖掘、化学物与药物注释、基因与蛋白质表征、通路分析以及疾病\-表型理解等任务。代表性资源包括：用于从出版物中获取知识的 PubTator \[1\] 和 PKG \[2\]，用于通路与功能注释的 KEGG \[3\] 和 Gene Ontology \[4\]，用于基因\-疾病关联的 OpenTargets \[5\]，以及用于统一化学物与基因注释的 BioThings \[6\]。这些知识库共同提供了关于生物医学实体、关系和注释的丰富且互补的表示，为现代研究工作流程奠定基础。然而，综合利用这些资源仍极具挑战：它们的结构差异显著、持续演化，而且很少能够顺畅对齐，因而互操作性有限，跨资源推理在实践中也十分困难。因此，整合、对齐或遍历这些异构知识图谱仍需大量人工投入，现有标准化或合并工作也高度依赖人力，难以实现可持续的规模化。

将人工智能（AI）智能体引入生物医学研究正受到快速增长的关注，相关应用已扩展至系统性文献综述 \[7, 8\]、基因组学研究 \[9, 10\]、空间生物学 \[11\]、生物标志物发现 \[12\] 等领域。这一趋势的核心概念是“AI 科学家”：由大语言模型（LLM）驱动的智能体与多种科学知识源及计算工具交互，以精简、增强或自动化研究流程中的部分环节 \[13–15\]。与此同时，多种通用生物医学智能体也已被开发出来 \[16, 17\]。在这一背景下，“深度研究”代表一类基于 LLM 的智能体，它们能够自主搜索、推理，并综合文献和知识库中的证据，从而开展端到端科学探究；OpenAI DeepResearch \[18\]、Gemini Deep Research \[19\] 和 Perplexity Deep Research \[20\] 等均为此类代表。尽管取得了这些进展，重大挑战依然存在。尤其是，大多数现有智能体仅依赖互联网规模的文本语料库，这留下了一个核心问题：我们能否设计出能够深入、系统地探索大型异构生物医学知识图谱的智能体，将这些图谱连接起来，揭示对现代生物医学发现不可或缺的细微关系与联系？

本文提出 DeepEvidence，这是一套专门用于借助生物医学知识图谱开展深度研究的 AI 智能体系统。不同于通用深度研究系统，DeepEvidence 利用专门的知识图谱工具，在异构图谱间定位并连接实体，并通过广度优先研究（BFRS）和深度优先研究（DFRS）的协同组合来遍历图谱；这两种策略相互补充，可用于系统化图谱探索。DeepEvidence 还引入内部证据图谱记忆；智能体在遍历和综合信息的过程中会持续更新该记忆，为发现过程提供结构化、透明的记录。我们将这些原则落实为一种“编排器\-子智能体”架构，其中专门的 BFRS 和 DFRS 智能体协同构建并完善最终证据图谱（图 1）。

我们的实证评估首先考察 DeepEvidence 在既有生物医学基准上的表现，这些基准要求对文献开展深度探索与推理，包括 Humanity’s Last Exam（HLE）\[21\]、LabBench\-LitQA2 \[22\]、SuperGPQA \[23\] 和 TrialPanorama\-EvidenceQA \[24\]。随后，我们展示 DeepEvidence 在生物医学发现生命周期四个关键阶段中的实际效用：（1）药物发现；（2）临床前体内实验；（3）临床试验开发；（4）循证医学。这些结果共同说明，由知识图谱驱动的深度研究具有支持并加速生物医学发现的潜力。

## 结果

### DeepEvidence 概述

DeepEvidence 是一个深度研究框架，旨在通过由 LLM 驱动的 AI 智能体处理异构生物医学知识图谱（KG）。其核心是一个编排器智能体，负责将任务分派给一组称为研究智能体的专门子智能体，由后者执行知识图谱探索（图 1a）。在整个过程中，编排器维护并逐步更新内部证据图谱，记录回答查询所需的关键实体与关系（图 1b）。研究智能体以两种互补模式运行。广度优先研究（BFRS）发起广泛的多图谱查询，以快速考察一跳邻域（例如，在疾病\-药物图谱或基因\-疾病图谱中识别与某种疾病相关的药物），并捕获大量候选实体及关系。深度优先研究（DFRS）则以 BFRS 发现的重要实体为基础，在问题需要多步推理或更丰富的证据发现时开展更深入的多跳探索（例如，递归追踪出版物之间的引用关系，为系统性文献综述构建完整证据图谱）。我们将这两种模式称为 BFRS 和 DFRS，而不是传统的 BFS/DFS，因为所提出的 AI 智能体会自主选择遍历步骤，而非遵循固定的图论规则。此外，AI 智能体还可通过识别共享实体或推断跨图谱关系，在异构知识图谱之间建立连接（图 1a 中称为“桥接实体”）。

我们创建了一套集成环境与工具集，使 DeepEvidence 能够规模化探索多种生物医学知识图谱（图 1c）。许多生物医学知识图谱通过异构 Web API 提供访问。为支持高效的 BFRS，我们针对主要生物医学领域实现了统一的实体搜索和数据获取接口，覆盖出版物、临床试验、化学物、基因、药物、疾病、表型和蛋白质。例如，智能体发起一次药物查询，即可自动触发对 KEGG \[3\]、ChEMBL \[25\]、OpenFDA \[26\]、OpenTargets \[5\] 及其他资源的并行检索。由于这些操作涉及大量 API 调用并生成异构数据，我们为系统配备了执行沙箱，使智能体能够以编程方式开展研究。在该沙箱中，智能体可以编写并执行代码，以规模化查询知识图谱 API；将检索结果以结构化文件（如电子表格）形式持久化保存；并在受控环境内完成后续提取和分析。这一设计确保多步研究工作流程兼具效率与可复现性。

DeepEvidence 通过智能体式工作流程支持通用生物医学研究任务，其中编排器根据查询动态确定研究计划（图 1d）。研究开始时，编排器选择 BFRS 与 DFRS 的执行顺序和配合方式，并确定每一步的研究目标。随后，每个研究智能体自主决定其行动，例如查询哪些知识图谱，以及执行哪些程序来提取和分析数据。不过，系统仍完全可控：用户可以指定与某项查询相关的生物医学领域，从而限制搜索空间；也可以提供专家先验，以指导并加速深度研究过程。

### DeepEvidence 在生物医学研究基准上表现优异

我们在四个具有挑战性的开放基准上评估了 DeepEvidence，这些基准要求具备通用生物医学知识、多跳推理和循证研究能力：Humanity’s Last Exam（HLE）\[21\]、LabBench \[22\]、SuperGPQA \[23\] 和 TrialPanorama \[24\]（图 1e）。为凸显所提出深度研究框架的贡献，我们将 DeepEvidence 与多种强基线进行比较：（1）两个配备文献搜索能力的前沿 LLM（GPT\-5 和 Sonnet\-4\.5）；（2）两个通用生物医学智能体（Biomni \[16\] 和 ToolUniverse \[17\]）。为确保公平，所有智能体系统（包括 DeepEvidence）均使用同一个底层 LLM（GPT\-5）运行。

在全部四项基准上，DeepEvidence 始终取得最佳表现（图 1e）。在 HLE\-Medicine 上，DeepEvidence 达到 40\.0%，显著优于 Biomni（20\.0%）、ToolUniverse（10\.0%）、Sonnet\-4\.5（3\.3%）和 GPT\-5（3\.3%）。在要求检索并综合出版物证据的 LabBench\-LitQA2 上，DeepEvidence 达到 80\.0%，是 Biomni（32\.0%）的两倍以上，并超过 Sonnet\-4\.5（48\.0%）。在强调高难度机制推理的 SuperGPQA\-Medicine\-Hard 上，DeepEvidence 达到 47\.1%，高于所有基线（Biomni 为 40\.7%；Sonnet\-4\.5 为 43\.6%）。最后，在基于真实世界临床试验的临床证据推理任务 TrialPanorama\-EvidenceQA 上，DeepEvidence 达到 96\.0%，优于 Biomni（84\.0%）和 Sonnet\-4\.5（88\.0%）。

这些结果证明了生物医学深度知识图谱研究的价值。尽管 Biomni 和 ToolUniverse 等智能体能够访问许多知识图谱 API，但它们通常只开展浅层探索，在作答前仅进行少量搜索。其庞大的工具集还可能引发工具混淆，导致智能体选择无关工具或沿错误的推理路径推进。相比之下，DeepEvidence 在持续更新的证据图谱引导下执行结构化的 BFRS\-DFRS 探索，从而实现更深入、更具针对性且更可靠的知识图谱调查。这一设计直接支持其在需要多跳推理和证据综合的任务上取得更优表现。

为进一步评估 DeepEvidence 在真实生物医学研究场景中的泛化能力，我们整理了六项新基准任务，覆盖生物医学发现的完整生命周期，包括药物发现、临床前研究、临床试验开发和循证医学。下文将逐项详细介绍并分析这些基准。

### DeepEvidence 用于药物发现与临床前研究

药物发现与临床前研究构成药物开发生命周期的前两个阶段。药物发现侧重识别可干预的生物学靶点，临床前研究则旨在阐明作用机制，并在实验模型中评估靶向生物学反应。本节评估 DeepEvidence 支持这两个阶段的能力。我们首先在一项用于药物发现的靶点识别任务上评估 DeepEvidence，随后开展两项临床前机制推理任务，考察通路层面的解释以及体内代谢反应预测能力（图 2a 和图 3）。

第一项任务是靶点识别，要求通过整合基因、通路、生物标志物和既往研究中的证据，针对给定疾病情境识别有前景的治疗或诊断靶点。如图 2a 所示，系统向智能体提供研究问题，以及对靶点用途和方法类别的约束；智能体必须迭代搜索、汇总和评估证据，最终收敛到证据充分的靶点。性能结果见图 2b。在此任务上，DeepEvidence 的准确率为 68%，显著优于 Biomni 的 56%、ToolUniverse 的 40% 和通用 LLM 的 42%。这一差距主要反映了研究策略上的差异。DeepEvidence 对经过整理的生物医学知识源开展有指导、结构化的深度探索，在不同数据库间对基因身份进行统一定位，并逐步维护证据图谱以组织发现。相比之下，Biomni 和 ToolUniverse 虽提供大量异构工具，却缺少充分的领域特定指导，常常导致工具选择不准确、证据检索浅表，以及因工具输出噪声大或不完整而产生混淆。

随后，我们评估智能体如何探索并综合生物医学文献、实验研究和分子数据，以解释临床前作用机制、通路相互作用以及分子扰动的生物学后果。如图 5a 所示，这些问题覆盖广泛而真实的临床前推理场景，包括解释信号串扰、解读药物机制和生物标志物、分析 bulk 与单细胞转录组数据、评估磷酸化蛋白质组学方法，以及将分子观察结果与表型或治疗结局联系起来。图 5b 的准确率比较显示，DeepEvidence 达到 72%，显著优于均为 44% 的 Biomni 和 ToolUniverse，也优于达到 52% 的通用 LLM。这些结果表明，DeepEvidence 更能将不同实验的证据整合为连贯且在生物学上合理的机制解释，而基线智能体往往难以协调异构数据源，或难以超越表层关联进行推理。

最后，我们在一项反映常见临床前研究设计的体内代谢通量反应任务上评估 DeepEvidence。如图 5c 所示，智能体需要识别在酶抑制后最可能表现出强烈靶向代谢抑制的肿瘤队列或生物标志物。图 5d 的结果显示，DeepEvidence 的准确率达到 80%，优于 Biomni 的 68%、通用 LLM 的 60% 和 ToolUniverse 的 52%。我们观察到相似的模式：基线智能体难以将代谢背景与实验设计整合，而 DeepEvidence 通过聚焦且以证据为基础的探索，能更可靠地将靶酶与通路层面的依赖关系对应起来。

### DeepEvidence 用于临床试验开发

每一种新的候选治疗方案都必须通过临床试验开展人体研究，以确定其针对特定疾病和患者队列的安全性与有效性（图 4a）。本节评估 DeepEvidence 支持临床试验开发的能力，重点考察核心设计决策。具体而言，我们设计了三项具有挑战性的试验规划任务：样本量估计、药物方案设计和替代终点发现。要成功完成这些任务，通常需要广泛考察既往临床证据，并对疾病生物学与治疗机制进行专家级推理。

第一项任务是“样本量估计”，要求确定为使研究在具有足够统计功效的情况下达到预期显著性水平所需的受试者人数。如图 4b 所示，智能体收到一个问题，以及统计假设和治疗组定义，随后尝试推断所需样本量。性能结果见图 4c。在此任务上，DeepEvidence 的准确率达到 68%，显著超过三个基线：Biomni（20%）、ToolUniverse（32%）和具备 PubMed 搜索能力的 LLM（24%）。我们认为，DeepEvidence 的优异表现来自其能够全面审查相关研究采用的样本量估计策略，并汇总类似临床试验中的样本量模式与设计设置。相比之下，通用智能体要么只执行浅层搜索，要么未收集实质性证据便直接尝试推断样本量。

第二项任务是“药物方案设计”（图 4d），要求为联合用药选择适当策略，包括起始剂量水平、剂量递增方法、剂量限制性毒性定义和治疗时间表；这些因素共同决定如何平衡治疗效果与受试者安全。每个问题都要求审查特定药物组合的历史证据，智能体必须根据这些证据和既定评分准则识别正确的用药方案策略。性能结果见图 4e。DeepEvidence 的准确率达到 52%，优于 Biomni（36%）、ToolUniverse（28%）和具备 PubMed 搜索能力的 LLM（20%）。对智能体行为的分析显示，DeepEvidence 能够持续从 FDA 批准药物参考资料和相关文献中检索信息，从而全面把握历史剂量和毒性模式；基线智能体收集的证据则往往不完整。

第三项任务是“替代终点发现”（图 4f），智能体根据新疗法的作用机制和生物学背景，对候选替代终点的合理性进行排序。解决该任务需要搜索生物医学知识库，识别疾病通路、药物靶点及相关生物过程，再判断哪些终点具有机制证据支持。图 4g 的结果采用平均精确率、召回率和 F1 分数进行评估。DeepEvidence 的精确率为 73\.2%、召回率为 75\.0%、F1 为 73\.3%。Biomni 分别为 60\.8%、64\.3% 和 60\.9%；ToolUniverse 分别为 57\.7%、69\.0% 和 61\.9%；LLM 分别为 58\.4%、61\.9% 和 58\.7%。我们发现，DeepEvidence 检索证据更为完整，并能正确区分药物靶点、通路和生物标志物之间的上游与下游关系，因而可在更充分的机制依据上选择替代终点。

### DeepEvidence 用于循证医学

循证医学（evidence\-based medicine，EBM）通过将决策建立在高质量临床证据之上来指导临床实践 \[27\]。EBM 的核心是综合已发表的临床研究，并随着新发现出现而持续更新。当后续随机对照试验改变了对既有治疗的认识时，原有证据可能过时，从而形成证据缺口。为评估 AI 智能体能否识别此类缺口，我们构建了一个聚焦于检测新近相关临床试验的基准。如图 5a 所示，智能体会收到一项系统性综述的设置，包括研究问题、综述目标和纳入标准，并必须识别原始综述未纳入、但为保持临床证据时效性而应当补充的新近试验。

我们从两个维度评估智能体表现：（1）缺口检出率，定义为智能体提出的 30 项最可能试验中是否至少出现一项真阳性；（2）召回率，定义为识别出的前 30 项试验所覆盖的真阳性比例。解决该任务需要深入研究文献，并依据细致的筛选标准认真评估研究资格。

结果见图 5d。DeepEvidence 的缺口检出率最高，为 90\.0%；相比之下，Biomni 为 50\.0%，ToolUniverse 为 15\.0%，具备 PubMed 搜索能力的 LLM 为 10\.0%。在召回率方面，DeepEvidence 达到 44\.14%，同样优于 Biomni 的 30\.17%、ToolUniverse 的 5\.06% 和 LLM 的 2\.67%。这些结果表明，DeepEvidence 能够更有效地识别证据缺口，并更广泛地覆盖相关研究。其优势来自对相关系统性综述、随机对照试验及其引文网络开展全面深度研究，并辅以疾病和药物知识图谱，以增强文献检索与研究筛选。

为理解 DeepEvidence 优于通用智能体的原因，我们考察了其行为模式和内部工作流程。图 5e 所示的编排器流程表明，DeepEvidence 遵循结构化、迭代式的深度研究管线，类似于人类评审者更新系统性综述的过程。它识别核心疾病实体，映射相关药物实体，并在系统性综述、随机对照试验及其引文网络间开展广度优先和深度优先探索，从而重建广阔的证据全貌。图 5c 的证据图谱与图 5b 中智能体生成的发现共同表明，DeepEvidence 能够追踪疾病术语、治疗类别、突变特异性人群和纳入标准之间的机制联系，使其能够聚类相关试验并发现新近相关研究。这些行为说明，DeepEvidence 的成功来自全面开展深度研究、整合多个生物医学知识源的证据，以及利用证据图谱作为研究优先级排序的支架。因此，与仅依赖简单搜索或直接推断的智能体相比，DeepEvidence 能更有效地识别证据缺口并追踪新出现的临床发现。

## 讨论

DeepEvidence 是构建面向生物医学研究的全面深度研究系统的重要进展。它表明，以多种生物医学知识图谱为基础的智能体框架，能够显著提升系统在各类领域专用资源间浏览广泛且碎片化知识的能力。DeepEvidence 通过编排专门的检索行动，并运用现代大语言模型的推理能力，为覆盖生物医学发现完整生命周期的任务生成以证据为基础的答案，包括药物发现、临床前研究、临床试验和循证医学。

DeepEvidence 提出了一种不同于既往知识图谱检索研究的视角；后者主要关注文本文件索引，以及使用大语言模型改进文档层面的检索 \[28–30\]。本研究并未将知识图谱视为文本挖掘的辅助结构，而是展示了如何在异构生物医学知识图谱之上明确构建深度研究系统，以共同支持复杂生物医学任务中的检索和多步推理。通过直接处理基因、疾病、药物、通路、试验及其关系，DeepEvidence 能够开展高效、有效、以证据为驱动的研究，超越以文档为中心的管线。明确构建证据图谱还提供了透明且可追踪的推理过程，使人类能够检查和验证中间实体关系与支持证据。这种基于证据图谱的形式，为生物医学深度研究提供了一种有原则且可解释的范式，而纯文本驱动的检索系统很难实现这一点。

系统仍存在若干局限。尽管我们已纳入多类生物医学实体和领域专用知识库，但覆盖范围仍不完整，现有基准也只反映了生物医学研究任务的一个子集。系统目前使用 KEGG 和 Gene Ontology 等经过良好整理、具有稳定模式和高质量 API 的知识图谱。未来版本必须适应专有或内部托管的图谱，这些图谱可能存在缺失值、结构不一致或接口不完整等问题。这要求赋予智能体构建新工具以访问这些图谱的能力。现有系统还聚焦两种有理论依据的图谱遍历策略，即广度优先研究和深度优先研究。与通用智能体相比，这些策略带来显著改进，但不太可能已达到最优。DeepEvidence 在许多任务上尚未达到专家水平；未来的提升既取决于更强的底层语言模型，也取决于允许智能体通过自主适应发现更优研究策略的方法。最后，我们当前的工作主要聚焦基于文本的模态；未来还可扩展至影像、结构生物学和蛋白质组学信息等多模态数据，以适用于更广泛的生物医学研究任务。

展望未来，我们设想 DeepEvidence 成为深入探索生物医学知识图谱的基础，并成为通用 AI 智能体的补充组件。通过与人类专家更紧密地协作，DeepEvidence 可支持需要严格证据基础的研究，并借助结构化、透明的深度研究范式，协助生成和验证具有科学意义的假设。

## 方法

### 处理开放基准

开放基准实验通过从 Humanity’s Last Example（HLE）\[21\]、LabBench LitQA2 \[22\]、SuperGPQA \[23\] 和 TrialPanorama \[24\] 中选择并改编任务来构建。

对于 Humanity’s Last Example（HLE），我们首先选择学科领域标记为“Medicine”的问题，然后移除需要额外图像作为输入的问题。之所以进行这一步筛选，是因为我们观察到，HLE 中的医学问题往往需要基于文献的推理来完成诊断或临床决策，而非视觉解读。筛选后共得到 30 个问题。

对于 LabBench，我们聚焦于 LitQA2 子集，因为该部分明确要求检索科学文献，以支持推理和答案生成。我们从该子集中随机抽取 25 个问题组成评估集。对于 SuperGPQA，我们首先将基准限制为难度等级标记为“Hard”的问题；在该子集中，再选择领域为“Clinical Medicine”的问题。由此得到一个包含 172 个问题的精选数据集，我们称之为 SuperGPQA hard clinical medicine set。

对于 TrialPanorama，我们从该基准中选择“EvidenceSummary”任务，然后保留最新的 50 个问题。在原始设定中，每个问题都是一项证据总结任务：系统提供多项研究的摘要，并要求模型总结证据以选出正确选项。在我们的设定中，这些摘要从输入上下文中被移除，因而智能体必须主动检索文献以确定正确答案。经过修改的设定构成了我们的 TrialPanorama EvidenceQA 数据集。

### 构建靶点鉴定任务

对于靶点鉴定任务，我们从 KGML 格式的 KEGG 疾病通路文件中提取通路拓扑，以构建评估实例。我们解析了 85 条人类疾病通路，涵盖癌症、代谢性疾病、感染和自身免疫性疾病，并据此建立有向信号图；其中节点表示基因/蛋白质，边表示调控关系（激活、抑制、阻遏或表达）。对于每条疾病通路，我们将靶点鉴定设计为一道多项选择题，要求从取自通路成员的 10 个候选选项中，选出最有希望成为治疗靶点的基因。该任务的一个示例实例见补充表 2。

为了依据通路结构而非人工标注计算标准答案，我们开发了一个拓扑逻辑引擎，根据三项标准为每个候选靶点赋予 Gain 分数（0、1 或 2）。第一，我们查找从候选基因到疾病终点节点的所有简单路径，并计算每条路径上边权重的累积乘积，从而得到路径极性；激活边贡献 1，抑制边贡献 −1。平均路径极性 \> 0\.5（即促进疾病进展）的基因，在使用抑制剂进行靶向时获得 Gain 2；路径极性为负（抑制疾病）的基因获得 Gain 0，以反映抑制保护性因子这一生物学矛盾。第二，我们引入图论分析中的介数中心性：中心性得分位于前 10% 且路径极性为正的基因，被优先视为最佳靶点（Gain 2），因为它们是信号汇聚的关键瓶颈。第三，我们应用成药性过滤：通过将基因符号与关键词匹配来识别不可成药的蛋白质类别（例如核糖体蛋白、细胞骨架组分），并将其 Gain 赋为 0。

我们还实现了疾病特异性逻辑配置，在不同通路类型中对各基因功能类别赋予不同权重。对于癌症通路，提高激酶和酶的优先级；对于耐药通路，强调转运蛋白和受体；对于感染通路，优先考虑模式识别受体和细胞因子。基因功能类型依据 KGML 条目元数据推断，包括酶的 EC 编号和图形注释；若这些信息不可用，则根据基因符号与精选基因家族词典进行模式匹配。最终的多项选择题以“GENE\_SYMBOL – functional\_type”的形式呈现选项，答案对应所有 Gain 2 选项，从而评估 AI 智能体能否依据通路拓扑识别具有治疗可操作性的靶点。

### 构建体内代谢通量响应任务

对于体内代谢通量响应预测任务，我们构建评估实例，以判断 AI 智能体能否预测临床前小鼠模型中药理性抑制靶酶后预期出现的代谢扰动。我们解析 KGML 格式的 KEGG 疾病通路文件，同时提取反应图（$\mathrm{substrate} \rightarrow \mathrm{product}$，即底物→产物关系）和信号图（调控关系），以模拟代谢通量动力学。对于每条通路，我们选择一个靶基因，并将任务设计为一道多项选择题，询问靶点受到抑制后哪些肿瘤队列会呈现最佳代谢通量响应，同时给出 7 个候选表型结局。该任务的一个示例实例见补充表 4。

标准答案依据通路拓扑通过三层验证系统计算。第一，我们进行拓扑一致性检查：从靶基因节点出发开展广度优先搜索，识别下游代谢物（在两个反应步骤内可到达的产物）和上游底物（在两个步骤内的前体）。根据酶抑制逻辑，下游产物的同位素示踪标记应减少，而上游底物应积累；反映这一模式的选项获得 Gain 2，表述相反情况的选项（例如“尽管受到抑制，下游产物水平仍升高”）因违反质量平衡原理而获得 Gain 0。第二，我们识别通路终点，即反应图中出度为零的末端节点，并将终点合成持续受到抑制标记为最佳响应指标。第三，我们通过强连通分量分析检测反馈环；参与循环的节点可能出现短暂或代偿性响应，因此获得 Gain 1，以反映部分但不稳定的靶点作用。

为保证生物学依据，选项文本使用从 KGML 反应元素中提取的真实化合物名称动态生成，而非使用通用占位符。对于每个靶基因，我们遍历反应图以收集真实代谢物名称（例如“丙酮酸标记减少 40% 的肿瘤”，而不是抽象指代），从而提供具体的分子背景。问题题干中的代谢依赖性和过程描述，在可行时同样源自通路特异性化合物；仅当化合物提取失败时，才回退到精选模板（例如“谷氨酰胺代谢”“氧化还原平衡”）。最终的多项选择题以随机顺序呈现 7 个表型结局，答案对应所有 Gain 2 选项，从而评估 AI 智能体能否根据通路拓扑对代谢通量扰动进行推理。

### 构建作用机制与通路推理任务

针对涵盖肿瘤学和分子生物学的临床前研究任务，我们构建了以证据为依据的多项选择题，其中既包括单选题，也包括多选题。这些问题旨在反映真实的临床前研究场景；在这些场景中，正确结论依赖机制特异性、实验背景和方法学约束，而不是孤立的事实回忆。我们通过识别临床前研究中反复出现的分析和决策问题来界定任务范围。精选问题涵盖以下核心主题：靶向药物作用机制表征、肿瘤治疗策略的局限性、癌细胞系性质与药物敏感性、组学数据分析工作流、信号转导机制、实验测定验证、肿瘤分子亚型与转移机制，以及基因表达模式与表型或临床读数之间的关联。主题优先选自已形成充分临床前共识的领域，以尽量减少对初步、存在争议或相互矛盾的发现的依赖。

对于每项任务，题干和候选答案均以根据任务相关性选择的权威临床前证据来源为依据。这些来源包括描述体外实验、体内肿瘤模型和分子机制研究的同行评议临床前文献，以及临床前研究中常用的精选资源，例如 ATCC 和 DSMZ 等癌细胞系资源库、GDSC 等药物敏感性数据库、GEPIA2 或 GEPIA3、TIMER、Kaplan Meier Plotter 等基因表达与生存分析平台，以及 KEGG 等通路数据库。适当时，我们也采用既定实验原理和技术指南。证据来源在单项任务层面应用，以确保论断的内部一致性和可追溯性，但不对所有题目强制实施统一或自动化的验证流程。根据底层临床前问题是只有一个最佳答案，还是允许多个同时成立的解释，每项任务被设计为单选题或多选题。

答案选项由领域专家人工构建，并赋予分级正确性标签；Gain 分别为 2、1 或 0，反映其与符合任务情境的临床前证据偏离程度逐渐增大。严格归类为 Gain 2 的选项必须同时满足以下条件：与确定性的临床前证据或广泛接受的机制认识一致；得到同行评议文献或精选数据库记录支持，且无矛盾发现；明确匹配问题所隐含的实验场景，包括准确指定分子靶点、细胞系特征、测定方法或数据解释标准；确保所有生物学论断在事实层面准确、无歧义，并可追溯至具体证据，如文献图表、数据库记录或实验方案。Gain 1 选项表示部分正确的推理路径：其中包含有效的生物学或方法学要素，但遗漏关键约束、从相关系统过度推广，或依赖不足以支持确定性结论的关联。Gain 0 干扰项在机制上看似合理，却与既有证据或实验逻辑不一致；其错误通常源于混淆不同实体、误解测定能力或直接违背共识性发现。有些干扰项改编自相邻研究情境中的真实陈述，以保持表面合理性。所有题目均经过审查，以确保不能仅凭通用生物学知识判断答案，而必须结合每项任务的特定实验或分析背景进行有依据的推理；同时，问题文本中不出现明确的数据库登录号或记录标识符，但会在方法学相关时保留对常用平台的引用。

### 构建临床试验开发任务

对于样本量估计任务，我们从 TrialPanorama 基准提供的样本量估计实例出发，并从该集合中选择最新的 25 项试验作为测试集，由此构建评估划分。对于每个实例，我们将基准提供的标准样本量视为正确答案，并通过对真实值进行乘法扰动生成 4 个合理的干扰项，将问题转换为多项选择题。具体而言，我们从 0\.25–4\.00 的范围内采样一个扰动比（即比标准答案小 75% 至大 300%），将其应用于真实样本量并四舍五入为整数，同时实施基本有效性约束，例如要求结果位于合理的样本量范围内且不等于正确值。随后，我们将 5 个选项随机排序，并把相应的选项字母记录为答案标签，从而可以直接按准确率评估 AI 智能体能否从相互竞争的备选项中选出正确的样本量。该任务的一个示例实例见补充表 6。

对于给药方案设计任务，我们基于一个结构化毒性与剂量探索语料库构建了证据引导的多项选择数据集；该语料库由早期肿瘤联合用药试验人工提取而来 \[31\]。我们首先从标准化表格中载入试验层级元数据（例如人群和剂量限制性毒性〔DLT〕评估窗口）、方案层级药物属性（药物名称和给药途径）、剂量层级阶梯、各剂量水平观察到的 DLT 汇总、方案中的 DLT 定义、报告的最大耐受剂量（MTDs），以及剂量递增设计描述信息（如有）。利用语料库中的所有单药方案，我们计算每种药物的单药治疗基线，包括参考单药 MTD（各单药试验报告的最大 MTD）和去重后的单药 DLT 术语列表。

随后，对于每种多药方案，我们通过以下步骤推导方案特异性证据特征：（i）分析剂量阶梯，以估计相对于单药 MTD 的起始剂量强度和最大剂量强度；（ii）量化不同剂量水平的 DLT 模式，并以联合用药 DLT 类型中亦见于单药治疗的比例来估计毒性重叠评分；（iii）提取人群和给药途径等辅助背景。我们使用基于规则的分类器，将这些证据特征映射到四级设计类别标签（I–IV 类）；该分类器优先考虑获批状态代理指标、单药剂量探索证据的可用性、毒性重叠和相互作用风险代理指标。最后，我们为每个符合条件的方案生成一道设计策略多项选择题：题干概述支持性证据，所有答案选项使用相同的药物组合，仅在与各类别对应的拟议试验设计策略上有所不同，例如安全性验证/有限调整、在接近单药 MTD 时降低剂量、标准剂量递增，或采用谨慎导入期并延长 DLT 观察窗且强制进行 PK/相互作用评估。我们排除了单药方案以及剂量/DLT 证据不足的联合方案。该任务的一个示例实例见补充表 7。

对于替代终点发现任务，我们以 KEGG 中近期获批的一组药物（批准日期为 2025 年的药物条目）为起点，并根据其通路注释自动构建具有机制依据的多项选择题。对于每种药物，我们从 KEGG 获取结构化药物记录，包括名称、临床评论/疗效文本、疾病注释、类别标签、靶基因标识符和关联通路，并保留至少映射到一个靶点和一条通路的药物。随后，我们为每种药物下载最多 5 条相关通路的 KGML 文件，并将其解析为有向相互作用图。为将药物机制与可测量的中间结局连接起来，我们从合并通路图中的药物靶节点出发，执行双向广度优先遍历（深度上限为 10），并将可到达基因与预定义的生物学过程标志物集合库进行匹配，例如增殖、凋亡、代谢、DNA 损伤、炎症、血管生成、迁移和信号传导。我们还利用高优先级临床文本字段（COMMENT/EFFICACY）的关键词启发式方法，并以 DISEASE 和 CLASS 字段作为补充，将每种药物的治疗背景归为癌症、炎症、代谢、心血管、神经系统或其他类别。

根据推断出的下游过程效应，我们生成药物特异且考虑疾病背景的替代终点策略，作为正确选项（gain=2）；这些策略强调可在 2–12 周内测量的远端生物标志物，用以连接药效学调节与预期临床获益。我们还加入可接受但较弱的策略（gain=1），这类策略的测量时机不佳，或与临床结局联系较弱。为构建具有挑战性的干扰项（gain=0），我们采用两阶段构建方法：首先为每种药物生成正确的替代终点策略；然后针对某一种药物，从以下来源采样干扰项：（i）为其他药物生成的正确替代终点策略，这些策略在机制上看似合理，但与当前机制/适应证不匹配；（ii）距靶点深度 \<3 的上游/近端测量指标，这些指标主要反映靶点结合，而非下游获益。每个最终题目均为包含 6–10 个选项的多答案选择题，所有 gain=2 选项都标记为正确；我们还实施质量约束，例如要求存在多个正确选项/次优选项/干扰项，并从问题文本中移除明确的数据库标识符（例如 KEGG ID）。该任务的一个示例实例见补充表 5。

## 构建循证医学任务

对于循证医学（evidence\-based medicine，EBM）任务，我们使用连续更新之间结论发生变化的版本化 Cochrane 系统综述来构建测试数据。我们从一份经整理的已更新综述清单出发，通过将 DOI 解析至 PubMed 记录，并经由 NCBI E\-utilities 下载完整 XML，以程序化方式获取每篇综述的最新版本及其紧邻的上一版本。我们从每个综述版本中提取结构化元数据（标题及结构化摘要各部分），并解析综述明确标注的参考文献列表（例如，本综述纳入研究的参考文献和本综述排除研究的参考文献）。由此可获得从每篇综述到其纳入研究 PMID 集合的版本级映射，进而可利用共同的基础 DOI 对综述版本进行稳健配对，并精确比较纳入研究集合。该任务的一个示例见补充表 8。

随后，我们将最终 EBM 测试集构建为一项证据缺口识别任务。对于每一对综述（旧版本与新版本），我们提供更新版综述的研究背景（例如目标、资格/选择标准、结局），并在可获得时提供上一版本纳入的研究列表。模型需要识别更新综述时应新增哪些研究。真实答案定义为新版本与旧版本纳入研究 PMID 集合的差集，即出现在更新版综述纳入列表中、但此前未被纳入的研究。

## 协调器与研究智能体的实现

DeepEvidence 采用基于 LangGraph 状态机实现的分层多智能体架构。在顶层，协调器智能体接收用户的研究查询，并将复杂问题分解为有针对性的子任务，动态规划研究策略。协调器提示词见补充说明 A\.1。协调器维护一个状态机，用于跟踪搜索预算、管理证据图，并协调两个专门的研究子智能体：广度优先研究子智能体（Breadth\-First Research Subagent，BFRS）和深度优先研究子智能体（Depth\-First Research Subagent，DFRS）。BFRS 旨在跨指定知识库进行广泛探索，同时收集多个实体的多样化信息；DFRS 则沿引文链和实体关系深入追踪，以发现详细的机制性证据。BFRS 和 DFRS 的提示词分别见补充说明 A\.2 和 A\.3。协调器通过工具调用来启动这些子智能体；工具调用会指定搜索目标（包括实体名称以及 PubTator ID 或 UMLS CUI 等标准化标识符）、目标知识库，以及分配给搜索的行动预算。每个子智能体都作为独立状态图运行，并拥有自己的工具执行节点，从而支持模块化组合和受控的资源分配。

协调器和研究子智能体均以代码执行作为主要行动机制。每个工具并不返回静态输出，而是生成可执行的 Python 代码，并在沙箱环境中运行。这种以代码为中心的方法使智能体能够执行复杂操作，包括多步 API 查询、使用 pandas 进行数据转换、统计分析和结构化报告生成。例如，在搜索基因时，智能体会执行代码以查询多个数据库，将结果汇总为统一的 DataFrame，并把输出保存到共享工作区，供后续分析步骤使用。沙箱会跟踪执行指标（运行时间和内存使用量），并在多次工具调用之间保持持久状态，使智能体能够在先前结果的基础上继续工作。该设计具备透明性和可复现性，并使智能体能够处理固定工具输出难以支持的任意数据处理工作流。

DeepEvidence 将显式证据图作为一等记忆结构，并由智能体在深度研究过程中持续增量构建和维护。该图仅存储高价值、标准化的生物医学实体，如基因、疾病、药物、通路、论文和具体发现；在存在规范标识符时使用规范标识符，并在全局范围内去重。边表示一组受控的机制、成员归属、关联和证据层级关系；每个节点和关系均有来自原始文献或精选知识图谱的明确来源依据。智能体并不把上下文编码为自由文本，而是将简短的事实观察附加至实体，记录实验环境、方法学以及定量或机制性结果。推理期间，智能体会在添加新内容前查询现有图谱，合并近似重复项，通过更新观察而非创建冗余节点来维护信息，并用独立的证据链接记录相互冲突的发现。我们将补充说明 A\.4 中的提示词加入智能体的系统提示词，作为额外指导。智能体与证据图之间的紧密耦合支持迭代式假设优化和证据汇总，并提供透明的可追溯性，从而确保结论源自明确、结构化且可审计的生物医学证据体系。

为促进跨知识库研究和实体桥接，我们实现了按模态统一的搜索工具，通过单一接口汇总多个权威来源的信息。例如，统一基因搜索工具会同时查询 BioThings（MyGene\.info）、KEGG 和 Open Targets，并返回包含跨数据库标识符的整合结果。疾病、药物、化合物、靶点、通路和变异也有类似的统一工具。除实体检索外，我们还通过 PubTator3 API 集成了基于关系的搜索能力，使智能体能够发现通过 TREAT、CAUSE、INTERACT、INHIBIT 和 ASSOCIATE 等特定语义关系相连的实体。这使智能体能够从疾病遍历至候选药物、从基因遍历至相关表型，或从化学物质遍历至其生物学靶点，从而支持机制性假设生成所需的深度优先推理模式。这些统一搜索工具和关系工具共同构成知识基础设施，使研究智能体能够连接异构知识图谱，并跨多个生物医学领域综合证据。

## 知识图谱工具的实现

我们在智能体工具库中纳入了以下知识库：BioThings \[6\]、ChEMBL \[25\]、ClinicalTrials\.Gov \[32\]、Gene Ontology \[4\]、Human Phenotype Ontology \[33\]、KEGG \[3\]、NCBI Datasets API \[34\]、OpenFDA \[26\]、Open Genes \[35\]、ProteinAtlas \[36\]、PubChem \[37\]、PubTator \[1\]、PubMed \[34\]、Reactome \[38\]、UMLS \[39\]、UniProt \[40\]。详细工具列表见补充表 1。

我们开发了模块化工具库，使智能体能够访问并查询 17 个生物医学知识图谱和数据库。每项知识图谱集成都遵循一致的双层架构：（1）封装 API 认证、速率限制、错误处理和响应解析的底层客户端类；（2）提供面向任务的接口、返回 pandas DataFrame 以及适合智能体读取的格式化输出字符串的高层工具函数。这种分层使同一个底层 API 客户端能够支持多个工具函数，同时保持代码的可复用性。所有工具函数均遵循统一的签名模式，接收搜索参数和可选的 `save_path` 参数，并返回 `(DataFrame, formatted_output_string)` 元组。格式化输出兼顾人类可读性与大语言模型可解析性，其中包括汇总统计、结果预览和文件保存确认。

对于 RESTful API（BioThings、PubChem、KEGG、ClinicalTrials\.gov、OpenFDA、ProteinAtlas、Open Genes、NCBI Datasets、HPO），我们使用 requests 库实现基于 HTTP 的客户端，并支持可配置的超时时间、重试策略和自定义用户代理标头。这些客户端将 JSON 或平面文件响应解析为结构化字典。对于基于 GraphQL 的 API（Open Targets Platform），我们构建了查询模板，并为靶点、疾病和药物搜索设置参数化变量。对于需要认证的编程式 API（UMLS、UniProt），我们实现了凭证管理和基于会话的认证流程。PubTator3 集成包括对实体类型布尔查询的专门支持（例如，`@CHEMICAL_remdesivir AND @DISEASE_COVID_19`），以及使用语义谓词（TREAT、CAUSE、INTERACT、INHIBIT、ASSOCIATE）进行的关系搜索。部分知识图谱需要特殊处理：ChEMBL 使用 Tanimoto 系数支持基于 SMILES 的相似性搜索和子结构搜索；Reactome 使用稳定标识符遍历通路层级；KEGG 则采用独特的平面文件格式，需要自定义解析逻辑。

为实现跨数据库实体解析和全面的信息检索，我们实现了统一搜索工具，通过单一接口汇总多个来源的结果。例如，`search_genes_unified` 会并发查询 BioThings（MyGene\.info）、KEGG、Open Targets，以及可选的 MyVariant\.info，并将结果与交叉引用标识符（Entrez、Ensembl、KEGG ID）合并。类似地，`search_drugs_unified` 会汇总来自 BioThings（MyChem\.info）、OpenFDA（Drugs@FDA 和药品标签）、KEGG Drug、Open Targets 及 ChEMBL 的结果。这些统一工具使用 `ThreadPoolExecutor` 并发执行以尽量降低延迟，并返回带有来源归属信息的整合 DataFrame。工具输出旨在支持下游分析，包括用于详细记录的 JSON 文件、用于表格数据的 CSV 文件，以及供研究智能体即时解读的 Markdown 格式摘要。

```markdown
"""
# 记忆图谱协议

## 1. 存储内容
仅保留与研究问题直接相关、简洁且高价值的事实。
图谱中的每一项都应表示一个独特且可复用的概念，而非同义改写。

### 生物医学实体
- 类型：GENE / PROTEIN（HGNC、NCBI Gene、UniProt 等）
- 类型：DISEASE / PHENOTYPE（DOID、MeSH、UMLS）
- 类型：CHEMICAL / DRUG（ChEBI、DrugBank 等）
- 类型：CELL LINE / TISSUE（Cellosaurus 等）
- 类型：PATHWAY / GENE_SET（Reactome、KEGG、GO、MSigDB 等）
- 类型：PAPER（PMID；可选用短标题）
- 类型：FINDING（仅用于记录具体的定量结果或机制性结果）

### 关系
- 机制性：ACTIVATES、INHIBITS、BINDS、PHOSPHORYLATES、REGULATES_EXPRESSION
- 成员关系/注释：MEMBER_OF_PATHWAY、HAS_GENESET_MEMBER、EXPRESSED_IN
- 关联性：ASSOCIATED_WITH、CO_OCCURS（仅在没有更精确谓词适用时使用）
- 证据层级：SUPPORTS、REFUTES、INCONCLUSIVE_FOR、CITES
- 来源追踪：DERIVED_FROM_KG:<name@version>

### 证据摘要
- 使用简短的事实性句子（<= 30 个单词），说明方法、背景以及定量结果（如有）。
- 背景（物种、细胞类型、实验测定）应保留在观察记录内部；除非会被多个发现重复使用，否则不要建立独立的背景节点。

## 2. 标识符与命名规则
- 优先使用规范 CURIE（HGNC:XXXX、DOID:XXXX、CHEBI:XXXX、PMID:XXXX）。
- 若没有规范 ID，则保留人类可读标签，并注明其来源知识图谱。
- 论文实体：名称始终以“PMID:”开头；后面可附可选的短标记。
- 名称不得超过 5 个单词或 40 个字符。
- 切勿因大小写或措辞差异而为同一概念创建多个节点。
- 遇到近重复项时：
  - 若 ID 相同：更新现有节点上的观察记录。
  - 若标签相同（不区分大小写）：视为同一节点。
  - 若标签不同但明显对应同一 PMID 或 KG ID：合并；不要创建新节点。

## 3. 关系标准
- 使用最小且一致的谓词集合；除非绝对必要，否则不要引入新动词。
- 方向：始终为主语 -> 宾语，不得仅出于行文风格而反向表示。
- 当背景已记录在观察文本中时，避免使用泛化的 ASSOCIATED_WITH 边。
- 限制背景边：
  - 每个发现最多两条（例如，一条连接 MEASURE，一条连接 CELLTYPE）。
  - 不要把每一种实验测定/物种都作为单独的 ASSOCIATED_WITH 边连接。
- 每条关系必须引用至少一个证据来源（PMID 或 KG 来源追踪信息）。

## 4. 图谱维护与反冗余规则
- GLOBAL 图谱仅允许追加，但须依据规范 ID 和标准化标签去重。
- 每个合并周期：<=10 个新实体，<=16 条新关系。
- 在创建任何实体或关系之前，代理必须：
  1. 检查是否已存在等价项（按 ID 或标准化名称）。
  2. 如已找到，则更新其观察记录，而不是创建新节点。
- 对于相互冲突的结果：
  - 保留具有不同证据的两条关系；使用 `conflict_group:<id>` 标记。
  - 不要仅为容纳不同发现而复制整个实体。
- 添加简单背景时，始终优先使用观察记录，而不是新建边。
- 每篇论文仅出现一次（每个 PMID 一个节点）。
- 每项发现针对每个独特的定量结果或机制性结果仅出现一次。
- 每个背景概念（物种、细胞类型、实验测定）针对每个规范 ID 仅出现一次。

## 5. 来源追踪与审查
- 每个节点和每条边都必须包含来源说明（PMID 或 KG@version）。
"""
```
