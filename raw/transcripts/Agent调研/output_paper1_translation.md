# 基于大语言模型（Large Language Model, LLM）的自主智能体（Autonomous Agents）综述

#### Lei Wang, Chen Ma[*], Xueyang Feng[*], Zeyu Zhang, Hao Yang, Jingsen Zhang, Zhi-Yuan Chen, Jiakai Tang, Xu Chen(�), Yankai Lin(�), Wayne Xin Zhao, Zhewei Wei, Ji-Rong Wen

**摘要** 自主智能体（autonomous agent）长期以来一直是学术界和工业界研究的焦点。以往研究通常侧重于在封闭环境中训练具有有限知识的智能体，这与人类的学习过程存在显著差异，并使得这些智能体难以实现类人决策。近年来，随着从互联网上获取海量知识，大语言模型（Large Language Model, LLM）展现出具备类人智能的潜力，由此催生出大量基于大语言模型的自主智能体研究。在本文中，我们对这些研究进行了全面综述，从整体视角系统性地回顾了基于 LLM 的自主智能体。我们首先讨论基于 LLM 的自主智能体的构建，提出了一个统一框架，涵盖了大部分已有工作。随后，我们概述了基于 LLM 的自主智能体在社会科学、自然科学和工程学等领域的多种应用。最后，我们深入探讨了评估基于 LLM 的自主智能体时常用的策略。在既有研究的基础上，我们还提出了该领域面临的一些挑战及未来的发展方向。

**关键词** 自主智能体，大语言模型（Large Language Model, LLM），类人智能（human-level intelligence）

自主智能体长期以来被认为是实现通用人工智能（artificial general intelligence, AGI）的一种有前景的途径，人们期望它能够通过自我主导的规划和行动来完成任务。在以往研究中，通常假设智能体基于简单且启发式的策略函数行事，并在孤立且受限的环境中进行学习 [1–6]。这类假设与人类的学习过程存在显著差异，因为人类思维极其复杂，个体能够从更加多样化的环境中进行学习。由于这些差异，以往研究中得到的智能体通常难以在无约束的开放领域环境中复刻类人的决策过程。

近年来，大语言模型（Large Language Model, LLM）取得了显著成功，展现出实现类人智能的巨大潜力 [5–10]。这种能力源于对大规模训练数据集的利用以及海量模型参数的支撑。在此基础上，一个新兴研究方向开始涌现，即使用大语言模型作为核心控制器来构建自主智能体，从而获得类人的决策能力 [11–17]。

与强化学习（reinforcement learning）相比，基于 LLM 的智能体拥有更为全面的内部世界知识，使其即便在未针对特定领域数据进行训练的情况下，也能够做出具有依据的行动。此外，基于 LLM 的智能体可以为人与系统的交互提供自然语言接口，从而带来更高的灵活性和更强的可解释性。沿着这一方向，研究者提出了大量颇具前景的模型（整体概况见图 1），其关键思想在于为 LLM 配备诸如记忆（memory）和规划（planning）等人类能力，使其能够像人类一样行动并有效完成各类任务。过去，这些模型大多是彼此独立地被提出的，对于它们进行系统性的总结与比较的工作还相对有限。然而，我们认为，对这一快速发展领域进行系统性的总结，对于全面理解该领域具有重要意义，也有助于激发未来的研究。

#### 2 基于 LLM 的自主智能体构建（LLM-based Autonomous Agent Construction）

基于 LLM 的自主智能体被期望能够利用 LLM 的类人能力来高效地执行多样化任务。为了实现这一目标，需要重点考虑两个方面：（1）应该设计怎样的架构以更好地使用 LLM；（2）在给定架构的基础上，如何使智能体获得完成特定任务所需的能力。在架构设计方面，我们对现有研究进行了系统性的归纳，总结出了一个统一的框架。针对第二个方面，我们根据是否对 LLM 进行微调，总结了智能体获取能力的策略。若将基于 LLM 的自主智能体与传统机器学习进行类比，架构设计类似于定义网络结构，而能力获取则类似于学习网络参数。下文中，我们将对这两个方面进行更为详细的讨论。

### 2.1 智能体架构设计（Agent Architecture Design）

近期在大语言模型方面的进展表明，LLM 具有以问答（question-answering, QA）形式完成广泛任务的巨大潜力。然而，构建自主智能体远不止问答这么简单，因为智能体需要扮演特定角色，并能够在环境中自主感知和学习，从而像人类那样不断演化自身。为了弥合传统 LLM 与自主智能体之间的差距，关键的一点是在架构上进行合理设计，以帮助 LLM 最大程度地发挥其能力。沿着这一方向，既有工作提出了许多模块来增强 LLM。在本节中，我们提出了一个统一的框架来总结这些模块。

具体而言，我们的统一框架整体结构如图 2 所示，由画像模块（profiling module）、记忆模块（memory module）、规划模块（planning module）和行动模块（action module）组成。画像模块的目标是确定智能体的角色。记忆模块和规划模块将智能体置于一个动态环境中，使其能够回忆以往行为、规划未来行动。行动模块则负责将智能体的决策转化为具体输出。在这些模块中，画像模块会影响记忆模块和规划模块，而这三个模块共同影响行动模块。下面我们将分别对这些模块进行详细说明。

#### 2.1.1 画像模块（Profiling Module）

自主智能体通常通过扮演特定角色来执行任务，例如程序员、教师以及领域专家等 [18, 19]。画像模块旨在给出智能体角色的画像，这些信息通常以提示词（prompt）的形式写入，从而影响 LLM 的行为。智能体画像通常包括基础信息，例如年龄、性别和职业 [20]，以及反映智能体个性的心理信息和描述智能体之间关系的社会信息 [21]。具体采用哪些信息来刻画智能体画像，在很大程度上取决于具体的应用场景。例如，如果应用目标是研究人类认知过程，那么心理信息就显得尤为关键。在确定了用于刻画画像的信息类型之后，下一个重要问题就是如何为智能体创建具体的画像。现有文献中常见的策略主要有以下三种。

**人工构造方法（Handcrafting Method）**：在这种方法中，智能体画像由人工指定。例如，如果希望设计具有不同人格特质的智能体，可以通过“你是一个外向的人（you are an outgoing person）”或“你是一个内向的人（you are an introverted person）”之类的描述来刻画智能体。人工构造方法在大量既有工作中被用于指定智能体画像。例如，Generative Agent [22] 通过姓名、目标以及与其他智能体的关系等信息来描述智能体。MetaGPT [23]、ChatDev [18] 和 Self-collaboration [24] 在软件开发任务中预先定义了多种角色及其对应职责，并为每个智能体手动分配不同的画像以促进协作。PTLLM [25] 旨在探索和量化 LLM 所生成文本中展现的人格特质。该方法通过人格评估工具（如 IPIP-NEO [26] 和 BFI [27]）手动定义不同的智能体角色，从而引导 LLM 生成多样化的回复。[28] 通过为 LLM 赋予不同角色（如政治家、记者和商人）进行提示，研究其输出的毒性。在总体上，人工构造方法非常灵活，因为研究者可以为智能体分配任意画像信息。然而，当需要处理大量智能体时，这种方法也会变得十分耗费人力。

**LLM 生成方法（LLM-generation Method）**：在这种方法中，智能体画像由 LLM 自动生成。通常做法是先说明画像生成规则，即阐明目标人群中智能体画像的组成和属性。然后，可以选择性地为少量智能体构造若干种子画像作为少样本（few-shot）示例。最后，利用 LLM 生成所有智能体的画像。例如，RecAgent [21] 首先为少数智能体手动创建种子画像，指定其年龄、性别、个人特质和电影偏好等属性。随后，它利用 ChatGPT 基于这些种子信息生成更多智能体画像。这一方法在构建大规模人群画像时显著降低了时间和人力成本。然而，它在对生成画像进行精细控制方面可能存在不足，易导致画像与预期特征不完全一致，或在某些方面出现偏离。

**数据集对齐方法（Dataset Alignment Method）**：在这种方法中，智能体画像来自真实世界数据集。通常的做法是，首先将数据集中关于真实人类的相关信息组织成自然语言提示语，然后利用这些提示语来刻画智能体。例如，在 [29] 中，作者根据美国国家大选研究（American National Election Studies, ANES）参与者的人口统计背景信息（例如种族/族裔、性别、年龄和居住州等），为 GPT-3 指定相应角色，并进一步研究 GPT-3 是否能够产生与真实人类相似的结果。数据集对齐方法可以准确捕捉真实人群的属性，从而使智能体的行为更加有意义，也更能反映真实世界场景。

_说明（Remark）_：尽管大多数既有工作是独立地采用上述画像生成策略之一，我们认为，将这些策略进行组合可能会带来额外收益。例如，为了通过智能体模拟来预测社会发展，可以首先利用真实世界数据为部分智能体构建画像，从而精准反映当前的社会状态。随后，可以为现实中尚不存在、但未来可能出现的角色手动指定画像，以此来预测未来社会的发展状况。除了这一例子之外，人们还可以灵活组合其他策略。画像模块是智能体设计的基础，对智能体的记忆、规划和行动过程具有重要影响。

#### 2.1.2 记忆模块（Memory Module）

记忆模块在智能体架构设计中发挥着非常重要的作用。它负责存储智能体从环境中感知到的信息，并利用已记录的记忆来促进其未来行动。记忆模块可以帮助智能体累积经验、自主演化，并表现出更加一致、合理且高效的行为。本节将围绕记忆模块的结构、形式和操作对其进行全面概述。

**记忆结构（Memory Structures）**：基于 LLM 的自主智能体通常从认知科学中关于人类记忆过程的研究中汲取灵感。人类记忆一般遵循这样的发展过程：由登记感知输入的感觉记忆（sensory memory），到短时间保持信息的短时记忆（short-term memory），再到在较长时间尺度上巩固信息的长时记忆（long-term memory）。在设计智能体记忆结构时，研究者从这些人类记忆的方面中获得启发。具体而言，短时记忆类似于由 Transformer 架构上下文窗口所约束的输入信息；长时记忆则类似于智能体可以按需快速查询和检索的外部向量存储。下面我们基于短时记忆和长时记忆介绍两类常用的记忆结构。

- **统一记忆（Unified Memory）**。该结构仅模拟人类的短时记忆，通常通过上下文学习（in-context learning）来实现，记忆信息会被直接写入提示词中。例如，RLP [30] 是一个对话智能体，它为说话者和听话者维护内部状态。在每一轮对话中，这些状态被用作 LLM 的提示，相当于智能体的短时记忆。SayPlan [31] 是一个专门为任务规划设计的具身智能体，在该智能体中，场景图（scene graph）和环境反馈被用作智能体的短时记忆，用于指导其行动。CALYPSO [32] 是一个为桌游“龙与地下城”（Dungeons & Dragons）设计的智能体，可以帮助地下城主（Dungeon Master）创建和叙述故事。其短时记忆由场景描述、怪物信息以及之前的摘要构成。DEPS [33] 也是一个为 Minecraft 设计的游戏智能体。该智能体首先生成任务计划，然后利用这些计划来提示 LLM，使其产生完成任务所需的行动。这些计划可以视为智能体的短时记忆。在实践中，实现短时记忆相对简单，并且能够增强智能体感知近期或与上下文密切相关的行为和观察的能力。然而，LLM 的有限上下文窗口限制了在提示中纳入全面记忆的能力，这可能削弱智能体的性能。该问题要求 LLM 具备更大的上下文窗口以及处理长上下文的能力。因此，许多研究者转向采用混合记忆系统来缓解这一问题。

- **混合记忆（Hybrid Memory）**。该结构显式建模人类的短时记忆和长时记忆。短时记忆暂存最近的感知信息，而长时记忆则在时间推移中巩固重要信息。例如，Generative Agent [20] 采用混合记忆结构来辅助智能体行为。短时记忆包含关于智能体当前情境的上下文信息，而长时记忆则存储智能体过去的行为和想法，可根据当前事件进行检索。AgentSims [34] 同样实现了混合记忆结构。提示中提供的信息可以视为短时记忆。为了增强记忆的存储能力，作者提出了利用向量数据库构建长时记忆系统，从而实现高效存储和检索。具体地，智能体的日常记忆被编码为向量并存储在向量数据库中。当智能体需要回忆先前记忆时，长时记忆系统会根据嵌入相似度检索相关信息。该过程可以提升智能体行为的一致性。在 GITM [16] 中，短时记忆存储当前轨迹，长时记忆则保存由过去成功轨迹总结而来的参考计划。长时记忆提供稳定的知识，而短时记忆则支持灵活的规划。Reflexion [12] 使用短时滑动窗口来捕捉最近的反馈，并引入持久化的长时存储以保留凝练后的洞见。这样的组合使智能体既能利用详细的即时经验，又能利用高层抽象。SCM [35] 会选择性地激活与当前对话最相关的长时知识，并与短时记忆结合，从而支持对复杂上下文对话的推理。SimplyRetrieve [36] 使用用户查询作为短时记忆，并通过私有知识库来存储长时记忆，这一设计在保障用户隐私的同时提升了模型精度。MemorySandbox [37] 将长时记忆和短时记忆用于存储不同的对象，这些对象可以在多轮对话中被访问。用户可以在同一画布上与多个不同智能体创建多轮对话，并通过简单的拖拽界面在智能体间共享记忆对象。在实践中，同时集成短时记忆与长时记忆可以增强智能体进行长程推理和累积有价值经验的能力，这对在复杂环境中完成任务至关重要。

_说明（Remark）_：细心的读者可能会注意到，还可能存在另一种类型的记忆结构，即仅基于长时记忆的结构。不过，我们发现这类结构在文献中鲜有明确记载。我们的推测是，智能体总是处于连续且动态的环境之中，连续动作之间通常具有高度相关性。因此，捕获短时记忆非常重要，通常无法忽略。

**记忆形式（Memory Formats）**：除了从记忆结构的角度进行分析，另一种分析记忆模块的视角是基于记忆存储媒介的形式，例如自然语言记忆或嵌入记忆。不同的记忆形式各具优势，适用于不同的应用场景。下面我们介绍几种具有代表性的记忆形式。

- **自然语言（Natural Languages）**。在这种形式中，记忆信息（例如智能体的行为和观察）直接用原始自然语言进行描述。这种形式具有多方面优势。首先，记忆信息可以以灵活且易于理解的方式表达。此外，它保留了丰富的语义信息，能够为智能体行为提供更全面的信号。在既有工作中，Reflexion [12] 将经验反馈以自然语言形式存储在滑动窗口中。Voyager [38] 使用自然语言描述来表示 Minecraft 游戏中的技能，并直接将这些描述存储在记忆中。

- **嵌入（Embeddings）**。在这种形式中，记忆信息被编码为嵌入向量，从而提高检索和读取效率。例如，MemoryBank [39] 将每一段记忆编码为嵌入向量，并采用双塔稠密检索模型来高效检索过去对话中的相关信息。

- **数据库（Databases）**。在这种形式中，记忆信息被存储在数据库中，使得智能体可以高效而全面地操作记忆。例如，ChatDB [40] 使用数据库作为符号记忆模块，智能体可以通过 SQL 语句对记忆信息进行精确的增删改操作。

- **结构化列表（Structured Lists）**。在这种形式中，记忆信息被组织为列表，记忆语义可以以高效且简洁的方式传达。例如，GITM [16] 将子目标（sub-goal）的动作序列存储在分层树结构中。分层结构显式刻画了目标与相应计划之间的关系。RET-LLM [41] 首先将自然语言句子转换为三元组（triplet）短语，然后再将其存储到记忆中。

_说明（Remark）_：这里我们仅展示了几种具有代表性的记忆形式，但需要注意的是，还有许多形式未被覆盖，例如 [38] 中使用的程序代码。此外，这些形式并不是彼此互斥的；许多模型会同时结合多种形式，以并行利用它们各自的优势。一个典型例子是 GITM [16] 的记忆模块，其采用键值列表结构：键由嵌入向量表示，值由原始自然语言构成。嵌入向量的使用使得记忆记录的检索更为高效，而自然语言则使得记忆内容更加全面，从而支持智能体做出更有依据的行为。

上述内容主要讨论了记忆模块的内部设计。下面我们将重点转向记忆操作，即记忆模块与外部环境交互的方式。

**记忆操作（Memory Operations）**：记忆模块在智能体与环境的交互过程中发挥着关键作用，使智能体能够通过与环境交互来获取、积累和利用重要知识。智能体与环境之间的交互是通过三类关键的记忆操作来完成的：记忆读取（memory reading）、记忆写入（memory writing）和记忆反思（memory reflection）。下面我们将更详细地介绍这些操作。

- **记忆读取（Memory Reading）**。记忆读取的目标是从记忆中提取有意义的信息，以增强智能体的行动。例如，使用先前成功的行动来实现类似目标 [16]。记忆读取的关键在于如何从历史行动中提取有价值的信息。通常，人们会采用三个常用标准来进行信息提取，即近期性（recency）、相关性（relevance）和重要性（importance）[20]。越是近期、越是相关、越是重要的记忆越有可能被提取出来。形式上，我们从既有文献中总结出如下记忆信息提取公式：

$\displaystyle m^{*} = \arg\max_{m\in M} \, \alpha s_{\text{rec}}(q, m) + \beta s_{\text{rel}}(q, m) + \gamma s_{\text{imp}}(m),$

其中，$q$ 表示查询（query），例如智能体需要解决的任务或其所处的上下文；$M$ 表示全部记忆的集合；$s_{\text{rec}}(\cdot)$、$s_{\text{rel}}(\cdot)$ 和 $s_{\text{imp}}(\cdot)$ 分别是衡量记忆 $m$ 的近期性、相关性和重要性的打分函数，分数越高分别表示记忆越新、越相关、越重要。这些打分函数可以通过多种方式实现，例如，$s_{\text{rel}}(q, m)$ 可以通过查询与记忆嵌入之间的向量相似度来计算。需要注意的是，$s_{\text{imp}}$ 只反映记忆自身的特征，因此与查询 $q$ 无关。$\alpha$、$\beta$ 和 $\gamma$ 为平衡参数，通过为它们赋予不同的值，可以获得不同的记忆读取策略。例如，当设置 $\alpha = \gamma = 0$ 时，许多研究 [16, 30, 38, 41] 在记忆读取时仅考虑相关性得分 $s_{\text{rel}}$；当设置 $\alpha = \beta = \gamma = 1.0$ 时，[20] 对上述三项指标赋予相同权重以从记忆中提取信息。

- **记忆写入（Memory Writing）**。记忆写入的目的在于将智能体对环境的感知信息存储到记忆之中。将有价值的信息写入记忆，为未来检索到具有信息量的记忆奠定了基础，从而使智能体能够更高效、更理性地行动。在记忆写入过程中，需要重点考虑两个潜在问题。（1）当新信息与已有记忆相似时，如何存储这些信息（即记忆重复，memory duplicated）。（2）当记忆达到存储上限时，如何删除信息以继续记忆过程（即记忆溢出，memory overflow）。下面我们分别对这些问题展开讨论。

  1）**记忆重复（Memory Duplicated）**。为了合并相似信息，人们提出了多种方法来整合新的和已有的记录。例如，在 [16] 中，与同一子目标相关的成功动作序列被存储在一个列表中。当列表大小达到 $N(=5)$ 时，列表中的所有序列会通过 LLM 被压缩为一个统一的计划方案，并用这一新生成的方案替换原先的所有序列。Augmented LLM [42] 通过累加计数的方式聚合同一信息，避免冗余存储。

  2）**记忆溢出（Memory Overflow）**。为了在记忆满载时继续写入信息，人们设计了不同的方法来删除已有信息，从而持续记忆过程。例如，在 ChatDB [40] 中，用户可以通过显式命令删除记忆。RET-LLM [41] 使用固定大小的缓冲区来存储记忆，当缓冲区满时，采用先进先出（first-in-first-out, FIFO）的方式覆盖最早写入的条目。

- **记忆反思（Memory Reflection）**。记忆反思模仿的是人类审视和评估自身认知、情感及行为过程的能力。在智能体上，记忆反思的目标是赋予智能体独立总结并推断更加抽象、复杂和高层信息的能力。更具体地，在 Generative Agent [20] 中，智能体具备将其存储在记忆中的过往经验总结为更广泛、更抽象见解的能力。首先，智能体会基于最近的记忆生成三个关键问题；然后，利用这些问题查询记忆以获得相关信息；在此基础上，智能体会生成五条洞见，这些洞见反映了智能体的高层想法。例如，低层记忆“Klaus Mueller 正在写一篇研究论文”“Klaus Mueller 正与图书管理员交流以推进其研究”和“Klaus Mueller 正在与 Ayesha Khan 讨论他的研究”等，可以被概括为高层洞见“Klaus Mueller 专注于他的研究”。此外，反思过程还可以以层次化方式展开，即可以在已有洞见的基础上进一步生成更高层的洞见。在 GITM [16] 中，那些成功完成子目标的动作会被存储在一个列表中，当列表中元素数量超过五个时，智能体会将其总结为一个共有且更加抽象的模式，并用这一模式替换所有元素。在 ExpeL [43] 中，作者为智能体引入了两种获取反思的方式：一是智能体在同一任务中比较成功和失败的轨迹；二是智能体从一组成功轨迹中学习经验。

传统 LLM 与自主智能体之间一个重要差别在于，后者必须具备在动态环境中学习和完成任务的能力。如果把记忆模块视为负责管理智能体过去行为的模块，那么还需要另一个重要模块来帮助智能体规划其未来行动。下面我们将概述研究者如何设计规划模块。

### 2.1.3 规划模块（Planning Module）

当面对复杂任务时，人类往往会将其分解为若干更简单的子任务并逐一解决。规划模块旨在赋予智能体这种人类能力，从而期望智能体的行为更加合理、强大且可靠。具体而言，我们根据智能体在规划过程中是否可以接收反馈，对既有研究进行了归纳，下文将详细展开。在规划模块中，我们根据智能体在规划过程中是否能够接收反馈，将既有研究划分为不同类别，具体如下。

**无反馈规划（Planning without Feedback）**：在这种方法中，智能体在采取行动之后不会接收到能够影响其未来行为的反馈信号。下面我们介绍几种具有代表性的策略。

- **单路径推理（Single-path Reasoning）**。在这一策略中，最终任务被分解为若干中间步骤，这些步骤以级联方式串联，每一步仅通向唯一的下一步。LLM 按照这些步骤执行，从而实现最终目标。具体而言，Chain of Thought（CoT）[45] 提出在提示词中输入求解复杂问题的推理步骤，这些步骤作为示例，激发 LLM 以逐步（step-by-step）的方式进行规划与行动。在这种方法中，计划是基于提示中示例所带来的启发而生成的。Zero-shot-CoT [46] 则通过向 LLM 提供诸如“think step by step”之类的触发句（trigger sentence）来引导其生成任务的推理过程。与 CoT 不同，这种方法不会在提示中显式加入推理步骤示例。RePrompting [47] 在生成计划之前，会检查每一步是否满足必要的前置条件；若某一步不满足前置条件，则向 LLM 提供一条关于前置条件错误的提示信息，并要求其重新生成计划。ReWOO [48] 提出了一种将规划与外部观察分离的范式，智能体首先独立地生成计划并获得观察结果，然后再将二者组合起来推导最终结果。HuggingGPT [13] 则首先将任务分解为多个子目标，然后基于 HuggingFace 平台逐一解决这些子目标。与一次性输出全部推理步骤的 CoT 与 Zero-shot-CoT 不同，ReWOO 和 HuggingGPT 需要多次调用 LLM 才能得到最终结果。SWIFTSAGE [49] 受到人类认知双系统理论（dual-process theory）[50] 的启发，将 SWIFT 模块与 SAGE 模块结合起来，用于复杂交互任务中的规划：SWIFT 模块基于已学习的模式快速给出响应，而 SAGE 模块则借助大语言模型，通过提出关键问题并生成行动序列来进行更深入的规划，从而保证任务的成功完成。

- **多路径推理（Multi-path Reasoning）**。在这种策略中，得到最终计划的推理步骤被组织成树状结构，每一个中间步骤都可能通向多个后继步骤。这种方式类似于人类的思考过程，因为人在每一步推理时可能都有多种选择。具体而言，自一致链式思维（Self-consistent CoT, CoT-SC）[51] 认为，每一个复杂问题都可能存在多种推理路径可以导出最终答案。因此，它首先利用 CoT 生成多条推理路径及相应答案，随后选取出现频率最高的答案作为最终输出。Tree of Thoughts（ToT）[52] 则通过树状推理结构来生成计划。在该方法中，树上的每一个节点代表一个“思维（thought）”，对应一个中间推理步骤，这些中间步骤的选择基于 LLM 的评估。最终计划可以借助广度优先搜索（breadth-first search, BFS）或深度优先搜索（depth-first search, DFS）来生成。与一次性生成所有规划步骤的 CoT-SC 相比，ToT 需要在每一个推理步骤上单独调用 LLM。在 RecMind [53] 中，作者设计了一个“自激发（self-inspiring）”机制，即在规划过程中被丢弃的历史信息也会被重新利用，以生成新的推理步骤。在 GoT [54] 中，作者将 ToT 中的树状推理结构拓展为图结构，从而获得更强的提示（prompting）策略。在 AoT [55] 中，作者通过在提示中加入算法示例（algorithmic examples）来增强 LLM 的推理过程，该方法只需对 LLM 进行一次或少数几次查询即可。在 [44] 中，LLM 被用作零样本规划器（zero-shot planner）：在每一步规划时，模型首先生成多种可能的下一步，然后根据这些步骤与可接受动作之间的距离来选出最终步骤。[56] 在 [44] 的基础上进一步改进，在提示中加入与查询相似的示例。RAP [57] 构建了一个世界模型（world model），并基于蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）模拟不同计划的潜在收益，最终通过汇聚多次 MCTS 迭代结果生成最终计划。为了便于理解，我们在图 3 中给出了单路径推理与多路径推理策略的对比示意。

- **外部规划器（External Planner）**。尽管 LLM 在零样本规划方面展现出强大能力，但要为特定领域问题高效生成计划仍具有很大挑战。为了解决这一问题，研究者开始采用外部规划器。此类工具通常已较为成熟，并使用高效搜索算法，以便快速找到正确甚至最优的计划。具体而言，LLM+P [58] 首先将任务描述转化为形式化的规划领域定义语言（Planning Domain Definition Language, PDDL），然后使用外部规划器来处理 PDDL，最后再由 LLM 将生成结果转回自然语言。类似地，LLM-DP [59] 利用 LLM 将观测、当前世界状态及目标转化为 PDDL，随后将这些信息交给外部规划器，从而高效地确定最终的动作序列。CO-LLM [22] 证明，LLM 擅长生成高层计划，但在低层控制方面存在困难。为此，作者设计了一个启发式的外部低层规划器，用于根据高层计划有效地执行具体动作。

**带反馈规划（Planning with Feedback）**：在许多真实场景中，智能体需要进行长时间跨度（long-horizon）的规划，才能解决复杂任务。面对这类任务，上述不带反馈的规划模块可能由于以下原因而效果有限：首先，从一开始就直接生成完美计划极其困难，因为需要考虑各种复杂的前置条件，因此简单地遵循初始计划往往会导致失败。此外，计划的执行可能会受到不可预测的转移动力学（transition dynamics）影响，使得初始计划变得不可执行。同时，当我们观察人类如何解决复杂任务时，会发现个体往往会基于外部反馈不断地迭代制定并修正自己的计划。为模拟这一人类能力，研究者设计了多种带反馈的规划模块，使智能体在采取行动后可以接收反馈。反馈信号可以来自环境、人类以及模型，下面分别介绍。

- **环境反馈（Environmental Feedback）**。这类反馈来自客观世界或虚拟环境，例如游戏中的任务完成信号，或智能体执行动作后的观测结果。具体而言，ReAct [60] 提出使用“思考-行动-观测（thought-act-observation）”三元组构造提示，其中“思考”部分用于进行高层推理和规划，从而指导智能体行为；“行动”表示智能体采取的具体动作；“观测”则对应动作的结果，可通过搜索引擎结果等外部反馈获得。下一轮思考会受到先前观测结果的影响，从而使生成的计划更具环境适应性。Voyager [38] 在规划时引入了三类环境反馈，包括程序执行的中间进度、执行错误以及自我验证结果，这些信号可以帮助智能体为下一步行动制定更优计划。与 Voyager 类似，Ghost [16] 也在推理与动作执行过程中引入了反馈，该反馈既包括环境状态，也包括每一个已执行动作的成功与失败信息。SayPlan [31] 利用来自场景图模拟器的环境反馈来验证和优化其策略规划。该模拟器能够判断智能体执行动作后的结果及状态转移，从而帮助 SayPlan 迭代地调整策略，直到找到可行的计划。在 DEPS [33] 中，作者认为，仅告知任务是否完成通常不足以纠正规划错误，因此他们提出向智能体提供详细的失败原因，以便其更有效地修正计划。LLM-Planner [61] 提出了有“落地性”的重新规划（grounded re-planning）算法，当任务执行过程中出现对象不匹配或计划不可达等情况时，该算法会动态更新由 LLM 生成的计划。Inner Monologue [62] 在智能体采取行动后向其提供三类反馈：（1）任务是否成功完成；（2）被动场景描述；（3）主动场景描述。其中前两类来自环境，有助于使智能体行为更加合理。

- **人类反馈（Human Feedback）**。除了从环境获取反馈之外，直接与人类交互也是增强智能体规划能力的一种非常直观的策略。人类反馈是一种主观信号，它可以有效地使智能体对齐人类价值和偏好，同时有助于缓解幻觉（hallucination）问题。在 Inner Monologue [62] 中，智能体的目标是在 3D 视觉环境中执行高层自然语言指令。该智能体具备主动向人类询问场景描述反馈的能力，随后会将人类反馈纳入提示，从而进行更充分的信息规划与推理。在上述案例中我们可以看到，不同类型的反馈可以组合使用，以增强智能体的规划能力，例如 Inner Monologue [62] 便同时收集环境反馈和人类反馈来辅助智能体规划。

- **模型反馈（Model Feedback）**。除了上述来自环境和人类的外部反馈信号之外，研究者还探索了利用智能体自身产生的“内部反馈”的方法。这类反馈通常基于预训练模型生成。具体而言，[63] 提出了一种自我改进（self-refine）机制，其由输出（output）、反馈（feedback）和改进（refinement）三个关键部分构成。首先，智能体生成一个输出；随后，它调用 LLM 对该输出进行反馈，并给出如何改进的指导；最后，依据反馈对输出进行改进。上述“输出—反馈—改进”过程会迭代进行，直到满足某些期望条件。SelfCheck [64] 允许智能体检查并评估在不同阶段生成的推理步骤，然后通过比较结果来纠正错误。InterAct [65] 使用不同的语言模型（如 ChatGPT 和 InstructGPT）作为检查者（checker）、排序者（sorter）等辅助角色，以帮助主语言模型避免错误且低效的行动。ChatCoT [66] 利用模型反馈来提升推理过程的质量，反馈由一个监控智能体推理步骤的评估模块产生。Reflexion [12] 则通过详细的语言反馈来增强智能体的规划能力。在该模型中，智能体首先根据记忆生成行动，然后由评价者（evaluator）以智能体轨迹为输入生成反馈。与以往仅给出标量反馈的工作不同，该模型利用 LLM 生成更加细致的语言反馈，为智能体规划提供了更全面的支持。

_说明（Remark）_：总体而言，不带反馈的规划模块实现相对简单，但主要适用于仅需少量推理步骤的简单任务；而带反馈的规划策略在处理反馈时需要更精心的设计，但其能力也更为强大，能够有效应对包含长程推理的复杂任务。

#### 2.1.4 行动模块（Action Module）

行动模块负责将智能体的决策转化为具体结果。该模块位于整个结构最下游的位置，直接与环境交互，并受到画像、记忆和规划模块的共同影响。本节从四个方面介绍行动模块：（1）行动目标（action goal）：行动期望达到什么结果？（2）行动产生（action production）：行动是如何生成的？（3）行动空间（action space）：可用的行动有哪些？（4）行动影响（action impact）：行动会带来哪些后果？其中，前两个方面关注行动发生之前（“before-action”）的问题，第三个方面关注行动本身（“in-action”），第四个方面则强调行动之后（“after-action”）的影响。

**行动目标（Action Goal）**：智能体可以带着多种不同目标来执行行动。这里给出几个代表性例子。（1）**任务完成（Task Completion）**。在这种场景中，智能体的行动旨在完成特定任务，例如在 Minecraft 中打造一把铁镐 [38]，或在软件开发任务中实现一个函数 [18]。这类行动通常具有明确的目标，每一步行动都会对最终任务的完成作出贡献。在现有文献中，这类以任务完成为目标的行动非常常见。（2）**沟通交流（Communication）**。在这种情形下，行动是为了与其他智能体或真实人类进行沟通交流，以分享信息或开展协作。例如，在 ChatDev [18] 中，不同智能体之间可以相互交流，共同完成软件开发任务。在 Inner Monologue [62] 中，智能体会主动与人类交互，并根据人类反馈调整其行动策略。（3）**环境探索（Environment Exploration）**。在这种场景中，智能体旨在探索陌生环境，以扩展自身感知，并在探索（exploration）与利用（exploitation）之间取得平衡。例如，在 Voyager [38] 中，智能体在完成任务的过程中会探索未知技能，并在环境反馈的基础上通过试错不断改进技能执行代码。

**行动产生（Action Production）**：与普通 LLM 直接将输入映射到输出不同，智能体可以通过多种策略与来源来生成行动。下面我们介绍两类常见的行动生成策略。（1）**基于记忆回溯的行动（Action via Memory Recollection）**。在该策略中，智能体会根据当前任务从记忆中提取信息，以此作为提示来触发行动。例如，在 Generative Agents [20] 中，智能体维护一条记忆流（memory stream），在每次采取行动之前，它会从记忆流中检索近期、相关且重要的信息来指导行动。在 GITM [16] 中，为达成某个低层子目标，智能体会查询其记忆，以判断是否存在与当前任务相关的成功经验；如果此前已完成过相似任务，智能体就会直接调用这些成功行动来处理当前任务。在 ChatDev [18] 和 MetaGPT [23] 等协作型智能体中，不同智能体之间会进行沟通，在这一过程中，对话历史会被记录到各自的记忆中，每一次智能体生成的发言都会受到其记忆的影响。（2）**基于计划执行的行动（Action via Plan Following）**。在该策略中，智能体按照预先生成的计划来执行行动。例如，在 DEPS [33] 中，对于给定任务，智能体首先生成行动计划，如果没有信号表明计划失败，智能体将严格按照计划执行。在 GITM [16] 中，智能体通过将任务分解为多个子目标来制定高层计划，随后围绕这些计划采取行动，依次解决各个子目标以完成最终任务。

**行动空间（Action Space）**：行动空间是指智能体可执行的全部可能行动集合。一般而言，我们可以将这些行动大致分为两大类：（1）外部工具（external tools）；（2）LLM 的内部知识（internal knowledge）。下面对这两类行动做更详细说明。

- **外部工具（External Tools）**。尽管 LLM 已经在大量任务上表现出较强能力，但在某些需要丰富专家知识的领域，其表现仍然有限。此外，LLM 还可能出现难以自行消除的幻觉问题。为缓解上述问题，人们赋予智能体调用外部工具执行行动的能力。下面列举一些文献中使用的代表性工具。

  （1）**API**。近年来，利用外部 API 来补充和扩展行动空间是一种流行范式。例如，HuggingGPT [13] 集成了 HuggingFace 平台上庞大的模型生态系统，以应对复杂用户任务。类似地，WebGPT [67] 在回答用户问题时，会自动生成查询以从外部网页中提取相关内容。TPTU [68] 探索了 LLM 通过策略性任务规划与 API 工具来解决复杂任务的潜力。Gorilla [69] 提出了一种经过微调的 LLM，可以为 API 调用生成精确的输入参数，从而在使用外部 API 时有效缓解幻觉问题。ToolFormer [15] 通过自监督学习（self-supervised learning）来学习在何时、以何种方式调用外部工具，并利用工具 API 的示例进行训练。API-Bank [70] 提供了一个涵盖多种 API 工具的综合基准，用于系统评估具备工具使用能力的 LLM，并构建了高质量训练数据集以增强模型的工具集成能力。ToolLLaMA [14] 提出了一套包含数据收集、训练与评估的工具使用框架，其微调后的模型在多种 API 上展现了优异表现。RestGPT [71] 将 LLM 与遵循广泛采用的 Web 服务开发标准的 RESTful API 相连接，从而使生成的程序更易在真实应用中部署。TaskMatrix.AI [72] 则将 LLM 与大规模 API 生态相连以支持任务执行，其核心是一个多模态对话基础模型（multimodal conversational foundational model），负责与用户交互、理解用户目标和上下文，并为具体任务生成可执行代码。从本质上说，这些智能体通过策略性地利用外部 API 这一多功能工具，系统性地扩展了行动空间，并通过集成多样的计算能力，突破了传统语言模型的固有限制。

  （2）**数据库与知识库（Databases & Knowledge Bases）**。集成外部数据库或知识库使得智能体可以获取特定领域信息，从而生成更符合现实的行动。例如，ChatDB [40] 通过 SQL 语句查询数据库，以更加逻辑化的方式支持智能体行动。MRKL [73] 和 OpenAGI [74] 则引入多种专家系统（如知识库和规划器），以访问特定领域的信息。

  （3）**外部模型（External Models）**。既有研究还常常使用外部模型来扩展可能行动的范围。与单一 API 相比，外部模型通常能够处理更复杂的任务，每一个外部模型往往对应多条 API 接口。例如，ViperGPT [75] 首先使用基于语言模型实现的 Codex 将文本描述转换为 Python 代码，然后执行这段代码以完成给定任务。ChemCrow [76] 是一个用于有机合成、药物发现与材料设计等任务的基于 LLM 的化学智能体，它利用 17 个专家设计的模型来辅助自身操作。MM-REACT [77] 集成多种外部模型，如用于视频摘要的 VideoBERT、用于图像生成的 X-decoder、用于语音处理的 SpeechBERT，从而增强其在多模态场景中的能力。

- **内部知识（Internal Knowledge）**。除了利用外部工具之外，许多智能体仅依赖 LLM 的内部知识来指导行动。下面我们概括几项对智能体合理且高效行为尤为重要的 LLM 能力。（1）**规划能力（Planning Capability）**。既有工作已表明，LLM 可以作为优秀的规划器，将复杂任务分解为若干简单任务 [45]，甚至在不提供示例的情况下，也能被触发出这种能力 [46]。基于 LLM 的规划能力，DEPS [33] 构建了一个 Minecraft 智能体，通过子目标分解来解决复杂任务。类似的智能体，如 GITM [16] 和 Voyager [38]，也在很大程度上依赖 LLM 的规划能力来成功完成多种任务。（2）**对话能力（Conversation Capability）**。LLM 通常能够生成高质量的对话内容，这一能力使得智能体的行为更接近人类。在既有研究中，许多智能体都会基于 LLM 强大的对话能力采取行动。例如，在 ChatDev [18] 中，不同智能体可以围绕软件开发流程进行讨论，并反思各自行为。在 RLP [30] 中，智能体可以根据听众对其发言的潜在反馈与其进行交流。（3）**常识理解能力（Common Sense Understanding Capability）**。LLM 的另一项重要能力是对人类常识的良好理解。得益于此，许多智能体可以模拟人类日常生活并做出类人的决策。例如，在 Generative Agent [20] 中，智能体可以准确理解自己的当前状态及周围环境，并基于基本观察总结高层想法；若缺乏这类常识理解能力，这些行为便难以被可靠地模拟。类似的结论也适用于 RecAgent [21] 和 S3 [78]，这两类智能体都专注于模拟用户的社会行为。

**行动影响（Action Impact）**：行动影响是指智能体行动带来的结果。尽管潜在影响的范围非常广泛，我们在此仅列举几个关键示例以便说明。（1）**改变环境（Changing Environments）**。智能体可以通过行动直接改变环境状态，例如移动自身位置、采集物品、建造建筑等。例如，在 GITM [16] 和 Voyager [38] 中，智能体在完成任务的过程中会改变环境，具体来说，当智能体采集资源（如收集三块木头）时，这些资源会从环境中消失。（2）**改变内部状态（Altering Internal States）**。智能体采取的行动还可以改变其内部状态，包括更新记忆、形成新计划、获取新知识等。例如，在 Generative Agents [20] 中，智能体在系统中执行行动后，其记忆流会被更新；类似地，SayCan [79] 允许智能体通过行动来更新其对环境的理解。（3）**触发新行动（Triggering New Actions）**。在任务完成过程中，一次行动往往会引发后续行动。例如，在 Voyager [38] 中，当智能体收集到所需资源后，就会触发建筑物的建造。

### 2.2 智能体能力获取（Agent Capability Acquisition）

在前面的章节中，我们主要关注如何设计智能体架构，使其更好地利用 LLM 的能力来完成类似人类的任务表现。架构可以视作智能体的“硬件”。然而，仅依赖硬件并不足以保证有效的任务执行，因为智能体可能缺乏完成具体任务所需的能力、技能和经验，这些可以被视为“软件”资源。为了为智能体配备这些资源，人们提出了多种策略。总体而言，我们根据是否需要对 LLM 进行微调（fine-tuning），将这些策略划分为两大类。下面分别介绍。

**通过微调获取能力（Capability Acquisition with Fine-tuning）**：提升智能体完成任务能力的一种直接方式，是利用任务相关数据集对模型进行微调。这些数据集可以来自人工标注、LLM 生成的内容或真实世界应用。下面分别讨论这些方法。

- **基于人工标注数据集的微调（Fine-tuning with Human Annotated Datasets）**。在多种应用场景中，利用人工标注数据来微调智能体是一种通用且有效的方法。该方法通常先设计标注任务，然后招募标注者完成。例如，在 CoH [85] 中，作者的目标是让 LLM 与人类价值和偏好对齐。不同于其他仅以简单符号化方式利用人类反馈的模型，这一方法将人类反馈转换为自然语言形式的详细比较信息，并直接基于这些自然语言数据集微调 LLM。在 RET-LLM [41] 中，为了更好地将自然语言转换为结构化记忆信息，作者基于人工构建的数据集对 LLM 进行微调，其中每个样本是一个“三元组—自然语言”对。在 WebShop [86] 中，作者从 amazon.com 收集了 118 万个真实商品，并构建了一个模拟电商网站，其中包含若干精心设计的人类购物场景。基于这一网站，作者招募了 13 名标注者，收集了一个真实的人类行为数据集，最终又基于该数据集训练了三种方法，分别基于启发式规则、模仿学习和强化学习。虽然作者并未直接微调基于 LLM 的智能体，但我们认为该文提出的数据集具有极大潜力，可用于提升网页购物领域智能体的能力。在 EduChat [87] 中，作者旨在增强 LLM 在教育场景中的功能，例如开放域问答、作文评分、苏格拉底式教学以及情感支持等。他们基于覆盖多种教育场景和任务的人类标注数据集对 LLM 进行了微调。

- **基于 LLM 生成数据集的微调（Fine-tuning with LLM Generated Datasets）**。构建人工标注数据集通常需要招募标注者，成本较高，尤其是在大规模标注任务中。考虑到 LLM 在多种任务上已具备类人能力，一个自然的想法是利用 LLM 来完成标注任务。尽管这类数据集的质量可能略逊于人工标注数据，但其成本要低得多，并且可以轻松生成更多样本。例如，在 ToolBench [14] 中，为提升开源 LLM 的工具使用能力，作者从 RapidAPI Hub 收集了覆盖 49 个类别的 16,464 个真实世界 API，并利用这些 API 提示 ChatGPT 生成多样化指令，涵盖单工具与多工具两种情形。基于该数据集，作者对 LLaMA [9] 进行微调，在工具使用能力方面取得了显著提升。在 [83] 中，为赋予智能体社会能力，作者设计了一个沙盒环境并部署多个智能体进行交互。给定一个社会问题（social question）时，中心智能体首先生成初始回答，然后将其分享给周围智能体以收集反馈。在反馈及其详细解释的基础上，中心智能体会修正初始回答，使之更加符合社会规范。在这一过程中，作者收集了大量智能体社会交互数据，随后用于微调 LLM。

- **基于真实世界数据集的微调（Fine-tuning with Real-world Datasets）**。除了基于人工或 LLM 标注构建数据集之外，直接使用真实世界数据集来微调智能体也是一种常见策略。例如，在 MIND2WEB [88] 中，作者收集了大量真实世界数据以提升网页领域中的智能体能力。与先前研究不同，该数据集覆盖了多样任务、真实场景以及完整的用户交互模式：作者从 31 个领域的 137 个真实网站中收集了超过 2 000 个开放式任务（open-ended tasks），例如电影发现和机票预订等，并基于这些数据对 LLM 进行微调，从而提升其在网页相关任务（如电影发现与票务预订）上的表现。类似地，在 SQL-PaLM [89] 中，研究者利用包括 Spider 和 BIRD 在内的跨领域大规模 text-to-SQL 数据集对 PaLM-2 进行微调，使得模型在 text-to-SQL 任务上取得了显著性能提升，进一步证明了真实世界数据集在特定领域应用中的有效性。

**无需微调的能力获取（Capability Acquisition without Fine-tuning）**：在传统机器学习时代，模型能力主要通过从数据集中学习来获得，知识被编码进模型参数之中。而在 LLM 时代，模型能力既可以通过训练/微调模型参数获得，也可以通过设计精巧的提示（prompt engineering）来获得。在提示工程中，人们需要将有价值的信息写入提示中，以增强模型能力或激发已有的 LLM 能力。在智能体时代，模型能力的获取可以基于三种策略：（1）模型微调（model fine-tuning）；（2）提示工程（prompt engineering）；（3）设计合适的智能体演化机制（我们称之为机制工程，mechanism engineering）。机制工程是一个广义概念，涵盖了开发专门模块、引入新的工作规则等多种方式，以增强智能体能力。为更清晰地展现模型能力获取策略的演变，我们在图 4 中给出了示意。

下面我们分别介绍提示工程与机制工程。

- **提示工程（Prompting Engineering）**。由于 LLM 具备强大的语言理解能力，人们可以直接用自然语言与其交互。这带来了一种新的增强智能体能力的策略：研究者可以用自然语言描述所需的能力，并将其作为提示来影响 LLM 的行动。例如，在 CoT [45] 中，为赋予智能体复杂任务推理能力，作者将中间推理步骤作为少样本（few-shot）示例写入提示中；类似技术在 CoT-SC [51] 和 ToT [52] 中也被采用。在 RLP [30] 中，作者通过在提示中写入智能体对自己以及听众心理状态的信念信息，来增强对话中智能体的自我意识，从而生成更具吸引力且更具适应性的发言；同时，通过将听众的目标心理状态纳入提示，智能体可以制定更具策略性的计划。Retroformer [90] 提出了一个回顾模型（retrospective model），使智能体能够对自身过去的失败进行“反思”，并将这些反思写入 LLM 的提示中，从而引导其后续行动；此外，该模型还利用强化学习（reinforcement learning）迭代优化回顾模型，从而间接优化 LLM 的提示。

- **机制工程（Mechanism Engineering）**。不同于模型微调与提示工程，机制工程是一种通过设计运行机制来提升智能体能力的独特策略。下面介绍几种具有代表性的机制工程方法。

  （1）**试错机制（Trial-and-error）**。在这种方法中，智能体首先执行某一行动，然后调用预定义的“评论者（critic）”对该行动进行评估。如果行动被认为不满意，智能体就会基于评论者的反馈进行反应和调整。例如，在 RAH [91] 中，智能体作为推荐系统中的用户助手，其重要职责之一是模拟人类行为并代表用户生成响应。为此，智能体首先生成一个预测响应，并将其与真实的人类反馈进行比较；若二者存在差异，评论者就会生成失败信息，并在智能体下一次行动时将其纳入。在 DEPS [33] 中，智能体首先为给定任务制定计划；在执行过程中，如果某一步行动失败，解释器（explainer）会生成详细的失败原因，然后由智能体利用这些信息重新设计计划。在 RoCo [92] 中，针对多机器人协作任务，智能体首先为每个机器人提出子任务计划以及三维路径点（3D waypoints），随后通过一系列环境检查（如碰撞检测和逆运动学）验证这些计划和路径；若任何检查失败，对应反馈会被写入各个智能体的提示中，并开启新一轮对话，智能体通过 LLM 讨论并改进计划和路径，直到通过所有检查。PREFER [93] 在这一思路基础上进一步扩展，当智能体表现不佳时，利用 LLM 生成更为详细的反馈，从而支持迭代式改进与性能提升。

  （2）**群体众包（Crowd-sourcing）**。在 [94] 中，作者设计了一种辩论机制，通过集结群体智慧来提升智能体能力。首先，不同智能体针对同一问题分别给出回答；若它们的回答不一致，则会被要求将其他智能体的解法纳入自身回答中并给出更新版本。该过程会多次迭代，直至得到最终共识答案。在这一方法中，每个智能体的能力都通过理解并吸收其他智能体的观点而得到提升。

  （3）**经验积累（Experience Accumulation）**。在 GITM [16] 中，智能体在一开始并不知道如何解决任务，它会进行探索，一旦成功完成某个任务，与该任务相关的动作序列就会被存储到智能体记忆中；之后，当智能体再次遇到类似任务时，会检索相关记忆并利用其中经验完成当前任务。在这一过程中，智能体能力的提升来自特定设计的记忆积累与利用机制。Voyager [38] 引入了一个技能库，将具体技能的可执行代码通过与环境交互不断加以改进，从而在时间推移中实现更高效的任务执行。AppAgent [95] 将智能体设计为像人类用户那样与应用程序交互，既通过自主探索也通过观察人类示范来学习，并在这一过程中构建知识库，用以支撑其在移动设备上的多应用复杂任务执行。MemPrompt [96] 要求用户以自然语言对智能体的解题意图提供反馈，并将这些反馈写入记忆，当智能体遇到相似任务时，会检索相关记忆以生成更合适的响应。

  （4）**自驱演化（Self-driven Evolution）**。该方法允许智能体通过自我驱动的学习和反馈机制自主提升能力。LMA3 [97] 使智能体能够自主为自己设定目标，并通过探索环境与从奖励函数获取反馈的方式逐步提升能力。在这一机制下，智能体可以根据自身偏好获取知识并发展能力。SALLMMS [98] 将 GPT-4 等先进 LLM 集成到多智能体系统中，智能体在与环境交互中通过高级通信能力来适应和执行复杂任务，从而实现自驱演化。在 CLMTWA [99] 中，作者以大型语言模型作为教师、较弱语言模型作为学生，教师通过心智理论（theory of mind）为学生生成并传递自然语言解释，以提升学生的推理能力，并可以根据干预效用（expected utility of intervention）在必要时进行个性化解释与干预。与此同时，NLSOM [100] 通过智能体之间的自然语言协作，根据反馈动态调整角色、任务与关系，从而解决单一智能体无法处理的复杂问题。

_说明（Remark）_：综合比较上述智能体能力获取策略可以发现，微调方法通过调整模型参数来提升智能体能力，可以融入大量任务特定知识，但通常只适用于开源 LLM；无需微调的方法则主要依赖精巧的提示设计或机制工程，它们既可用于开源 LLM，也可用于闭源 LLM。然而，由于 LLM 输入上下文窗口的限制，这些方法不能纳入过多任务信息；此外，提示与机制的设计空间极其庞大，寻找最优方案并不容易。

在上述小节中，我们详细介绍了基于 LLM 的智能体构建，重点围绕架构设计与能力获取两个方面展开。我们在表 1 中给出了已有工作与上述分类体系之间的对应关系。需要指出的是，为了完整性，我们还纳入了几项虽未明确提出“基于 LLM 的智能体”，但与该领域高度相关的研究。

#### 3 基于 LLM 的自主智能体应用（LLM-based Autonomous Agent Application）

得益于强大的语言理解能力、复杂任务推理能力以及常识理解能力，基于 LLM 的自主智能体在多个领域都展现出显著潜力。本节对既有研究进行简要总结，并根据其应用领域将其划分为三大类：社会科学、自然科学与工程（全局概览见图 5 左侧部分）。

### 3.1 社会科学（Social Science）

社会科学是科学的一个分支，致力于研究社会以及社会中个体之间的关系。基于 LLM 的自主智能体可以利用其类人理解、思考与任务求解能力促进该领域的发展。下面我们讨论几个可能受到基于 LLM 的自主智能体影响的重要方向。

**心理学（Psychology）**：在心理学领域，基于 LLM 的智能体可以用于进行模拟实验、提供心理健康支持等 [101–104]。例如，在 [101] 中，作者为 LLM 设定不同的画像，并让其完成心理学实验。实验结果表明，LLM 能够生成与真人受试者研究结果相一致的结果；此外，还观察到更大规模的模型通常比小模型产生更准确的模拟结果。一个有趣的发现是，在许多实验中，ChatGPT 和 GPT-4 等模型往往给出“过于完美”的估计（称为“hyper-accuracy distortion”），这可能会影响下游应用。在 [103] 中，作者系统分析了基于 LLM 的对话智能体在心理健康支持方面的有效性。他们从 Reddit 收集了 120 条帖子，发现这类智能体可以在用户需要时帮助其应对焦虑、社会孤立和抑郁等问题；与此同时，他们也发现这些智能体有时会产生有害内容。

**政治学与经济学（Political Science and Economy）**：基于 LLM 的智能体也可用于研究政治学和经济学问题 [29, 104, 105]。在 [29] 中，基于 LLM 的智能体被用于意识形态（ideology）检测与投票模式预测。在 [104] 中，作者在基于 LLM 的智能体辅助下，研究政治演讲的话语结构及其说服要素。在 [105] 中，智能体被赋予才能、偏好和人格等特定特质，用于在模拟环境中探究人类经济行为。

**社会模拟（Social Simulation）**：以往针对人类社会开展实验往往成本高昂、存在伦理问题，甚至在某些情况下根本无法实施。随着 LLM 的不断发展，许多研究者开始尝试构建由基于 LLM 的智能体组成的虚拟环境，以模拟社会现象，例如有害信息传播等 [20, 34, 78, 80, 106–109]。例如，Social Simulacra [80] 模拟了一个在线社群，并探索通过基于智能体的模拟来帮助决策者改进社区规章的可能性。[106, 107] 研究了基于 LLM 的智能体不同行为特征在社会网络中的潜在影响。Generative Agents [20] 和 AgentSims [34] 在虚拟小镇中构建多个智能体，以模拟人类日常生活。SocialAI School [108] 利用基于 LLM 的智能体来模拟并研究儿童发展过程中基础社会认知能力的形成。S3 [78] 构建了一个社会网络模拟器，重点关注信息、情绪和态度的传播。CGMI [110] 则是一个多智能体模拟框架，它通过树状结构维护智能体的个性，并构建认知模型，作者利用 CGMI 模拟了课堂场景。

**法学（Jurisprudence）**：基于 LLM 的智能体可以在法律决策过程中提供辅助，帮助做出更为充分的信息化判决 [111, 112]。Blind Judgement [112] 利用多个语言模型模拟多名法官的决策过程，收集多元意见，并通过投票机制整合为最终结论。ChatLaw [111] 是一个重要的中文法律大模型，它同时支持基于数据库与基于关键词的检索策略，专门用于缓解此类模型中普遍存在的幻觉问题；此外，该模型还通过自注意力机制削弱引用不准所带来的影响，从而提升 LLM 的整体能力。

**研究助理（Research Assistant）**：除了在专业子领域中的应用之外，基于 LLM 的智能体也日益被用作广义社会科学研究中的通用助手 [104, 113]。在 [104] 中，基于 LLM 的智能体承担多种辅助任务，包括生成简明的文章摘要、抽取关键关键词以及撰写研究脚本等，展示了其丰富和简化研究流程的能力。同时，在 [113] 中，基于 LLM 的智能体作为写作助手，能够帮助社会科学研究者发现新的研究问题，从而为该领域探索与创新开启新的方向。这些例子凸显了基于 LLM 的智能体在提升社会科学研究的效率、创造力与广度方面的潜力。

### 3.2 自然科学（Natural Science）

自然科学是科学的一个分支，主要基于对自然现象的观察与实验所得经验证据，来描述、理解和预测自然现象。随着 LLM 的迅速发展，基于 LLM 的智能体在自然科学中的应用日益广泛。下面我们给出多个具有代表性的方向，展示基于 LLM 的智能体在自然科学中的作用。

**文献与数据管理（Documentation and Data Management）**：自然科学研究往往需要收集、整理和综合大量文献，这通常消耗大量时间和人力。基于 LLM 的智能体在语言理解以及利用互联网、数据库等工具进行文本处理方面表现出强大能力，这些能力使其在文献与数据管理相关任务上具有显著优势。在 [114] 中，智能体可以高效地查询和利用互联网信息，完成问答、实验规划等任务。ChatMOF [115] 利用 LLM 从人类撰写的文本描述中提取关键信息，并据此制定计划调用相关工具，以预测金属有机框架（metal-organic frameworks）的性质和结构。ChemCrow [76] 则利用化学相关数据库验证化合物表示的准确性，并识别潜在危险物质，通过保障数据准确性来提高科学研究的可靠性与完备性。

**实验助手（Experiment Assistant）**：基于 LLM 的智能体具备独立开展实验的能力，可以作为支持科学家研究项目的重要工具 [76, 114]。例如，[114] 提出了一种创新的智能体系统，利用 LLM 自动化实验的设计、规划与执行：系统在接收到实验目标后，会访问互联网并检索相关文献以汇总必要信息，随后利用 Python 代码完成关键计算，并执行后续实验。ChemCrow [76] 集成了 17 个专门为化学研究设计的工具，当接收到输入目标后，ChemCrow 能够为实验步骤提供有价值的建议，并强调实验中可能存在的安全风险。

**自然科学教育（Natural Science Education）**：基于 LLM 的智能体可以与人类流畅交流，因此常被用于开发以智能体为核心的教育工具。例如，[114] 构建了基于智能体的教育系统，以帮助学生学习实验设计、方法与分析，其目标是提升学生的批判性思维与问题求解能力，同时加深其对科学原理的理解。Math Agents [116] 可以帮助研究者探索、发现、求解和证明数学问题，并通过对话的方式帮助人们理解与使用数学。[117] 利用 CodeX [118] 的能力自动求解并解释大学水平的数学问题，可作为教学工具帮助学生和研究者学习。CodeHelp [119] 是一个面向编程教育的智能体，它支持设定课程特定关键词、监控学生提问并为系统提供反馈等多种功能。EduChat [87] 是一个专门面向教育场景的基于 LLM 的智能体，为教师、学生和家长提供个性化、公平且具同理心的教育支持。FreeText [120] 则是一个利用 LLM 自动评估学生开放式问题作答并给出反馈的智能体。

### 3.3 工程（Engineering）

基于 LLM 的自主智能体在辅助和提升工程研究与应用方面展现出巨大潜力。本节回顾并总结其在若干主要工程领域中的应用。

**计算机科学与软件工程（Computer Science & Software Engineering）**：在计算机科学与软件工程领域，基于 LLM 的智能体有望在代码编写、测试、调试以及文档生成等方面实现自动化 [18, 23, 24, 126–128]。ChatDev [18] 提出了一套端到端框架，其中多个智能体角色通过自然语言对话进行沟通与协作，以完成整个软件开发生命周期，该框架展示了高效且低成本地生成可执行软件系统的能力。MetaGPT [23] 抽象出产品经理、架构师、项目经理、工程师等多种角色，对代码生成过程进行监督，从而提升最终输出代码的质量，实现低成本的软件开发。[24] 提出了一种基于 LLM 的自协作（self-collaboration）代码生成框架，该框架假设多个 LLM 分别是特定子任务的“专家”，它们根据指定指令进行协作与交互，形成一个虚拟团队，相互促进，最终在无需人工干预的情况下完成代码生成任务。LLIFT [141] 利用 LLM 辅助进行静态分析，以识别潜在代码漏洞，在准确性与可扩展性之间取得了良好平衡。ChatEDA [123] 是一个面向电子设计自动化（electronic design automation, EDA）的智能体，通过集成任务规划、脚本生成与执行来简化设计流程。CodeHelp [119] 也是一个面向编程的教育与辅助智能体，其功能包括为错误信息提供详细解释、给出可能的修复建议以及检查代码正确性。PentestGPT [125] 是一个基于 LLM 的渗透测试工具，可以识别常见漏洞并分析源代码以生成攻击利用。D-Bot [122] 利用 LLM 的能力系统性评估数据库异常的潜在根因，并通过链式思维/思维树（tree of thought）方法，使 LLM 能够在当前步骤失败时回溯至前一步，从而提升诊断过程的准确性。

为了推动基于 LLM 的自主智能体在工程领域的应用，研究者还提出了许多开源库，使开发者能够根据自己的需求快速实现与评估智能体 [19, 82, 127, 142–155]。例如，LangChain [147] 是一个开源框架，可以自动化处理编码、测试、调试及文档生成等任务；通过将语言模型与数据源集成并支持与环境交互，LangChain 使得多个智能体角色可以通过自然语言沟通与协作，以高效、低成本完成软件开发。基于 LangChain，XLang [145] 提供了一整套工具和完整的用户界面，专注于可执行语言落地（executable language grounding），将自然语言指令转换为可在数据库、Web 应用和物理机器人等多种环境中执行的代码或动作序列。AutoGPT [82] 是一个完全自动化的智能体，它可以自行设定一个或多个目标，将其分解为相应任务，并循环执行这些任务直至目标完成。WorkGPT [148] 是一个类似 AutoGPT 与 LangChain 的智能体框架，给定一条指令和一组 API 后，它会与 AI 进行往复对话，直到完成该指令。GPT-Engineer [128] 与 DemoGPT [127] 是两个开源项目，专注于通过提示自动生成代码以完成开发任务。SmolModels [126] 提供了一系列适用于多种任务的小型语言模型。AGiXT [144] 是一个动态 AI 自动化平台，可以高效管理指令并在多个 AI 服务提供方之间执行复杂任务，集成了自适应记忆、智能特性和灵活的插件系统。AgentVerse [156] 是一个灵活的框架，便于研究者高效构建定制化的基于 LLM 的智能体模拟系统。GPT Researcher [150] 是一个实验性应用，利用 LLM 高效地提出研究问题、触发网页爬取、收集信息、总结文献并聚合摘要。BMTools [151] 提供了一个由社区驱动的工具构建与共享平台，支持多种类型的工具，允许使用多个工具并行执行任务，并通过简单的 URL 接口加载插件，从而促进 BMTools 生态中的便捷开发与贡献。

_说明（Remark）_：在上述应用中使用基于 LLM 的智能体同时也伴随风险与挑战。一方面，LLM 本身可能存在幻觉等问题，偶尔给出错误答案，从而导致错误结论、实验失败，甚至在危险实验中对人类安全造成威胁，因此在使用过程中，用户必须具备必要的专业知识并保持足够谨慎。另一方面，基于 LLM 的智能体也可能被用于恶意目的，例如开发化学武器等，这就需要通过人类对齐（human alignment）等安全机制来确保其使用的责任性与伦理性。

#### 4 基于 LLM 的自主智能体评估（LLM-based Autonomous Agent Evaluation）

与对 LLM 本身的评估类似，评估基于 LLM 的自主智能体的有效性同样是一项具有挑战性的任务。本节概述两类常用评估方式：主观评估与客观评估（subjective and objective methods）。整体概览见图 5 右侧部分。

### 4.1 主观评估（Subjective Evaluation）

主观评估是基于人类判断来衡量智能体能力的方法 [20, 22, 29, 80, 157]。当缺乏评估数据集，或难以设计量化指标（例如评估智能体的“智能水平”或“易用性”）时，这类方法尤为适用。下面我们介绍两种常用的主观评估策略。

**人工标注（Human Annotation）**：这种评估方法由人类评估者直接对不同智能体生成的输出进行打分或排序 [22, 29, 104]。例如，在 [20] 中，作者通过向大量标注者提出 25 个问题来评估智能体在五个与智能体能力密切相关的关键方面上的表现。在 [80] 中，标注者被要求判断特定设计的模型是否可以显著促进规则制定的发展。**图灵测试（Turing Test）**：这种评估策略要求人类评估者在不知道来源的情况下区分由智能体生成的输出与由人类生成的输出。如果在某一任务中评估者无法分辨哪些结果来自智能体、哪些来自人类，则可以认为该智能体在该任务上达到了类人水平。例如，在 [29] 中，研究者在自由形式的党派文本（free-form Partisan text）上开展实验，请人类评估者判断各个回答是来自真人还是基于 LLM 的智能体。

_说明（Remark）_：基于 LLM 的智能体通常是为了服务人类而设计的，因此主观评估在这一领域中极为重要，因为它直接反映了人类标准。然而，这种策略也面临成本高、效率低以及人群偏差等问题。为缓解这些问题，越来越多研究开始探索使用 LLM 本身作为“中介”来执行主观评估。例如，在 ChemCrow [76] 中，研究者利用 GPT 对实验结果进行评估，同时考虑任务是否完成以及底层过程是否正确。类似地，ChatEval [158] 提出了一种新方法，通过多个智能体以结构化辩论的形式对不同候选模型的结果进行批判与评估。这种将 LLM 用于评估的新思路，有望提升主观评估的可信度与实用性。随着 LLM 技术的持续演进，可以预期这类方法将愈发可靠并得到更广泛应用，从而在一定程度上克服直接人类评估所面临的限制。

### 4.2 客观评估（Objective Evaluation）

客观评估是指利用可计算、可比较并可随时间跟踪的量化指标来评估基于 LLM 的自主智能体的能力。与主观评估不同，客观指标旨在为智能体表现提供具体、可度量的洞见。在进行客观评估时，通常需要关注三个关键方面：评估指标（metrics）、评估协议（protocols）与评测基准（benchmarks）。下面分别介绍。

**评估指标（Metrics）**：为了客观评估智能体的有效性，设计合适的评估指标至关重要，这会直接影响评估的准确性与全面性。理想的评估指标既要能够精确反映智能体的质量，又要在真实场景中尽可能贴近人类的主观感受。现有工作中常见的代表性指标包括：（1）**任务成功类指标（Task success metrics）**：这类指标衡量智能体完成任务和达成目标的能力，常用指标包括成功率（success rate）[12, 22, 58, 60]、奖励/得分（reward/score）[22, 60, 161]、覆盖率（coverage）[16] 以及准确率/错误率（accuracy/error rate）[18, 40, 80, 101] 等。根据具体场景，准确率可以刻画程序是否可执行 [18]，或任务是否有效 [101]。在这些任务成功类指标上取得更高数值，表明智能体具备更强的任务完成能力。（2）**类人相似度指标（Human similarity metrics）**：这类指标从多个层面衡量智能体行为与人类行为的相似程度，关注人类特征相关的多种维度，例如连贯性（coherent）[104]、流畅性（fluent）[104]、与人类对话的相似度 [80] 以及人类接受率（human acceptance rate）[101] 等，相似度越高表示智能体在模拟人类方面表现越好。（3）**效率指标（Efficiency metrics）**：与前述用于衡量智能体“有效性”的指标不同，效率指标旨在评估智能体的“效率”，常见指标包括开发成本 [18]、训练效率 [16, 38] 等。

**评估协议（Protocols）**：除了评估指标之外，客观评估的另一重要方面是如何利用这些指标。现有工作中常见的评估协议包括：（1）**真实世界模拟（Real-world simulation）**：在该方法中，智能体被部署在沉浸式环境中进行评估，例如游戏和交互式模拟器。智能体需要在环境中自主执行任务，随后根据智能体的行为轨迹与完成目标情况，利用任务成功率、人类相似度等指标来评估其能力 [12, 16, 22, 33, 38, 60, 86, 161, 164, 168]。通过模拟真实世界场景，这一方法旨在对智能体的实际能力进行全面评估。（2）**社会评估（Social evaluation）**：该方法通过在模拟社会中考察智能体之间的互动来评估其社会智能。典型做法包括设计协作任务以评估团队合作能力、通过辩论任务分析论证推理能力，以及通过用户研究测量社会能力 [34, 80, 101, 163]，从连贯性、心智理论（theory of mind）、社会智商（social IQ）等角度评价智能体在协作、沟通、共情以及模拟人类社会行为等方面的表现。通过将智能体置于复杂的交互环境中，社会评估为其高层社会认知能力提供了有价值的洞见。（3）**多任务评估（Multi-task evaluation）**：在该方法中，研究者会从不同领域选取一组多样化任务来评估智能体，以有效衡量其在开放环境中的泛化能力 [12, 29, 86, 151, 162–164, 169, 170]。（4）**软件测试（Software testing）**：在该方法中，研究者让智能体执行软件测试相关任务，如生成测试用例、复现缺陷、调试代码、与开发者及外部工具交互等 [159, 160, 167]，然后使用测试覆盖率（test coverage）、缺陷发现率（bug detection rate）等指标来衡量基于 LLM 的智能体在软件测试场景中的有效性。

**评测基准（Benchmarks）**：在确定评估指标和评估协议之后，选择合适的评测基准是评估中的关键环节。随着时间推移，人们提出了多种基准，用于在不同领域和场景下评估基于 LLM 的智能体能力。许多研究采用 ALFWorld [60]、IGLU [161] 和 Minecraft [16, 33, 38] 等环境，在交互式、任务导向的模拟场景中评估智能体能力。Tachikuma [168] 通过 TRPG 游戏日志评估 LLM 对多角色与新颖物体之间复杂交互的理解和推理能力。AgentBench [169] 提供了一个系统框架，用于在多种环境中评估 LLM 作为自主智能体的表现，是首批在多领域真实挑战上系统评测 LLM 智能体的工作之一。SocKET [163] 是一个覆盖 58 个任务、五大类社会信息（幽默与讽刺、情感与感受、可信度等）的综合基准，用于评估 LLM 的社会能力。AgentSims [34] 是一个灵活的评估框架，研究者可以在其中自由设计智能体规划、记忆与行动策略，并在交互环境中测量不同模块的有效性。ToolBench [151] 专注于评估与提升语言模型的工具使用能力，包含 16,464 个真实 RESTful API 以及针对单工具与多工具场景设计的多样指令。WebShop [86] 构建了用于评估基于 LLM 的智能体在商品搜索与检索能力上的基准，其数据来源于 118 万个真实商品。Mobile-Env [164] 是一个可扩展的交互平台，用于评估基于 LLM 的智能体在多轮交互任务中的能力。WebArena [173] 提供了一个覆盖多领域的真实网站环境，用于以端到端方式评估智能体，并检查其完成任务的准确性。GentBench [171] 用于评估智能体在利用工具完成复杂任务时的推理、安全性与效率等能力。RocoBench [92] 包含六个任务，用于评估多智能体在不同场景中的协作能力，重点考察通信与协同策略，以及在协作机器人任务中的适应性与泛化性。EmotionBench [172] 评估 LLM 的情绪评估能力，即在给定特定情境时其“感受”如何变化，该基准收集了 400 多个引发八种负面情绪的情境，并通过自评量表衡量 LLM 与人类的情绪状态。PEB [125] 面向渗透测试场景评估基于 LLM 的智能体，包含来自主流平台的 13 个不同目标，覆盖多个难度等级，以更真实地反映智能体在渗透测试中的挑战。ClemBench [165] 通过五种对话游戏（Dialogue Games）评估 LLM 作为对话式智能体的能力。E2E [174] 是一个端到端基准，用于测试聊天机器人在准确性与有用性方面的表现。

_说明（Remark）_：客观评估为基于 LLM 的智能体能力提供了多维度的量化分析。尽管现有技术尚无法完美衡量所有类型的智能体能力，但客观评估仍为主观评估提供了重要补充。随着评测基准与客观评估方法的持续发展，将有助于进一步推动对基于 LLM 的自主智能体的理解与改进。

#### 5 相关综述（Related Surveys）

随着大语言模型的迅速发展，已经出现了多篇系统性的综述论文，从不同角度对相关研究进行详细介绍。[175] 对 LLM 的背景、主要发现与主流技术进行了全面介绍，涵盖了大量既有工作。[176] 则主要聚焦于 LLM 在各类下游任务中的应用及其部署过程中面临的挑战。为解决偏见与幻觉等问题，将 LLM 与人类智能对齐（human alignment）是一条重要研究路线。[177] 系统梳理了现有的人类对齐技术，包括数据收集与模型训练方法。推理（reasoning）是智能的重要组成部分，影响决策、问题求解及其他多种认知能力。[178] 概述了当前关于 LLM 推理能力的研究现状，并探讨了提升和评估其推理能力的各种方法。[179] 提出通过增强推理能力与工具使用能力来扩展语言模型，将这类模型称为增强语言模型（Augmented Language Models, ALMs），并系统性回顾了 ALM 方面的最新进展。随着大模型的广泛应用，对其进行评估变得愈发关键。[180] 从“评什么”“在哪里评”“如何评”等角度，系统讨论了 LLM 在下游任务及社会影响层面的评估问题。[181] 也从多个下游任务视角讨论了 LLM 的能力与局限性。上述研究从训练、应用与评估等多个方面系统性地综述了大模型相关工作。然而，在本文之前，还没有工作专门针对“基于 LLM 的智能体”这一快速兴起且前景广阔的方向开展全面综述。本文收集了 100 篇与基于 LLM 的智能体相关的研究，围绕其构建、应用与评估过程进行了系统梳理。

#### 6 挑战（Challenges）

尽管现有关于基于 LLM 的自主智能体的工作已经取得了许多令人瞩目的成果，但该领域整体仍处于早期阶段，在发展过程中仍存在若干重要挑战亟待解决。下面我们给出一些具有代表性的挑战方向。

##### 6.1 角色扮演能力（Role-playing Capability）

不同于传统 LLM，自治智能体通常需要扮演特定角色（例如程序员、研究者、化学家等）来完成不同任务，因此智能体的角色扮演能力至关重要。尽管 LLM 可以较好地模拟许多常见角色（如影评人），但对于某些角色及其特定方面，它们仍然难以精准刻画。首先，LLM 通常基于网络语料进行训练，对于在网络上很少被讨论的角色或新近出现的角色，LLM 可能难以有效模拟。此外，已有研究 [30] 表明，现有 LLM 可能无法很好地建模人类认知心理特征，导致在对话场景中缺乏足够的自我意识。这些问题的潜在解决思路包括对 LLM 进行微调，或精心设计智能体提示/架构 [182]。例如，可以先收集针对罕见角色或特定心理特征的真实人类数据，再利用这些数据对 LLM 进行微调；但如何在提升这些能力的同时保证模型在常见角色上的表现不受影响，仍是一项挑战。除此之外，还可以通过设计专门的智能体提示与架构来增强 LLM 的角色扮演能力，不过在庞大的设计空间中寻找最优提示与架构同样并不容易。

##### 6.2 广义人类对齐（Generalized Human Alignment）

在人类对齐问题上，已有研究已对传统 LLM 进行了大量讨论。在基于 LLM 的自主智能体领域，尤其是在智能体被用于仿真（simulation）时，我们认为这一概念应被更深入地讨论。为了更好地服务人类，传统 LLM 通常会被微调以对齐“正确”的人类价值，例如智能体不应为社会报复而规划制造炸弹。然而，当智能体被用于真实世界模拟时，一个理想的模拟器应该能够如实刻画人类的多样特质，包括一些并不“正确”的价值观。事实上，模拟人类的负面方面在很多情况下甚至更加重要，因为仿真的一个关键目标正是发现并解决问题；如果在模拟中完全不存在负面行为，则不存在需要解决的问题。例如，为真实社会建立模拟时，我们可能不得不允许部分智能体规划如何制造炸弹，并观察其实施计划的过程及其行为所带来的影响；基于这些观察，人类可以制定更优策略来阻止现实社会中类似行为的发生。受到这一案例启发，基于智能体的模拟中一个重要问题是如何实现“广义人类对齐”：即针对不同目的与应用场景，使智能体能够对齐多样的人类价值观。然而，现有许多强大的 LLM（包括 ChatGPT 与 GPT-4）普遍被对齐到一套相对统一的人类价值观。因此，一个有趣的方向是在保证安全的前提下，通过设计合适的提示策略，对这些模型进行“重新对齐”（realign）。

##### 6.3 提示鲁棒性（Prompt Robustness）

为了让智能体产生合理行为，设计者往往会在 LLM 上叠加记忆、规划等附加模块。然而，引入这些模块意味着需要构造更复杂的提示，以保证各模块之间协同运行并有效沟通。已有研究 [183, 184] 指出，LLM 的提示常常缺乏鲁棒性，即提示中的微小改动就可能导致输出结果发生显著变化。在构建自主智能体时，这一问题会更加突出，因为此时需要设计的不是单一提示，而是覆盖所有模块的提示框架（prompt framework），其中某一模块的提示可能会影响其他模块。此外，不同 LLM 之间可用的提示框架差异很大，如何设计一个适用于多种 LLM 的统一且鲁棒的提示框架仍是重要而尚未解决的问题。潜在解决思路包括：（1）通过大量试错手工构造关键提示元素；（2）利用 GPT 等模型自动生成提示。

##### 6.4 幻觉问题（Hallucination）

幻觉是 LLM 面临的一项基础挑战，指的是模型以高度自信生成错误信息的倾向。这一问题不仅存在于 LLM 本身，也在自治智能体领域中引发严重担忧。例如，[185] 观察到，在代码生成任务中，当给定过于简单的指令时，智能体可能出现明显的幻觉行为，产生错误或具有误导性的代码，进而带来安全风险和伦理问题 [185]。为缓解这一问题，将人类纠偏反馈直接纳入人机交互的迭代过程是一种可行思路 [23]。关于幻觉问题的更多讨论，可参考 [175]。

##### 6.5 知识边界（Knowledge Boundary）

基于 LLM 的自主智能体的一个重要应用，是模拟多样的现实人类行为 [20]。人类行为模拟的研究历史悠久，而近年来之所以重新受到关注，主要得益于 LLM 在模拟人类行为方面展现出的强大能力。然而，需要认识到 LLM 的强大能力有时也可能带来问题。从理想状态来看，一个好的模拟应该尽可能准确地再现人类的知识水平；在这一点上，LLM 由于训练时接触了远远多于普通个体的海量网络知识，往往会显得“过于强大”。这种过强能力可能削弱仿真的效果。例如，在模拟用户对电影的选择行为时，理想状态是让 LLM 在没有任何相关先验知识的情况下进行决策；然而，LLM 很可能已经在训练阶段接触过关于这些电影的信息。如果不采取适当策略加以限制，LLM 可能会基于自身庞大知识做出决策，而现实中的用户在观看之前并不了解这些电影的内容。基于上述例子，我们可以得出结论：在构建可信的智能体模拟环境时，一个关键问题是如何约束 LLM 使用那些现实用户“未知”的知识。

##### 6.6 效率（Efficiency）

由于自回归（autoregressive）结构的原因，LLM 的推理速度通常较慢，而智能体在执行每一步行动时，往往需要多次调用 LLM，例如从记忆中抽取信息、在行动前进行规划等。因此，智能体行动的整体效率在很大程度上受到 LLM 推理速度的影响。

#### 7 结论（Conclusion）

在本综述中，我们系统性地总结了基于 LLM 的自主智能体领域的已有研究，从智能体构建、应用与评估三个方面对相关工作进行了梳理。针对每一个方面，我们给出了详细的分类体系，梳理了现有研究之间的联系，总结了主要技术路线及其发展脉络。除了回顾既有工作外，我们还提出了该领域中若干重要挑战，希望能为未来的研究方向提供参考与启发。
