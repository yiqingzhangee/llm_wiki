# 任务计划

## 目标

将当前 Obsidian 知识库配置为跨项目长期记忆系统：按需读取相关记忆、每天 22:00 整理当天沟通、每周复盘去重并沉淀经验，同时保留原始来源与代理维护内容的边界。

## 背景与约束

- 现有 `CLAUDE.md` 已规定 `raw/` 默认只读、`wiki/` 由代理维护。
- 所有 `wiki/` 知识库正文使用简体中文。
- 需要兼容 Obsidian 浏览和现有 wiki 目录，不破坏已有项目资料。
- 需要区分稳定偏好、项目事实、进行中状态、临时会话记录和复盘经验。
- 定时任务必须可观察、可失败重试或人工补跑，不能静默修改大量历史资料。
- 当前工作区存在大量既有未提交和新增文件，不触碰与本任务无关的改动。

## 阶段划分

### 阶段 1：探索现状与明确范围
- **状态**: 进行中
- **描述**: 阅读仓库规则、目录、已有自动化命令，确认长期记忆的边界和需要补充的组件。
- **产出**: `findings.md`、本计划、用户范围确认。

### 阶段 2：提出架构方案并获得批准
- **状态**: 待开始
- **描述**: 比较最小方案、Obsidian 原生方案和命令/调度方案，确定记忆分层、写入规则、冲突处理和定时范围。
- **产出**: 经用户批准的设计文档。

### 阶段 3：实现知识库结构与操作协议
- **状态**: 待开始
- **描述**: 创建长期记忆入口、个人偏好、项目索引、项目页模板、每日沟通日志、周复盘页和代理操作说明。
- **产出**: `wiki/` 下的记忆与项目管理页面、必要的命令或脚本。

### 阶段 4：配置定时整理与按需读取
- **状态**: 待开始
- **描述**: 配置每天 22:00 的当天记录整理和每周一次复盘；定义输入范围、输出范围、幂等性、失败通知和人工补跑方式。
- **产出**: 调度配置、运行说明、验证记录。

### 阶段 5：验证与交付
- **状态**: 待开始
- **描述**: 用一条示例项目记录演练读取、晚间整理和周复盘，检查链接、重复写入、原始源保护和 Git 工作区边界。
- **产出**: 验证结果、使用说明、最终变更清单。

## 关键决策

| 决策 | 理由 | 时间 |
|------|------|------|
| 原始来源与代理维护区分离 | 保留可追溯性，避免代理改写人工来源 | 待批准 |
| 长期记忆按个人、项目、经验和日志分层 | 降低每次读取的范围，避免把全部历史塞进上下文 | 待批准 |
| 定时整理默认只处理当天新增沟通和明确变更 | 保持幂等，降低误改历史的风险 | 待批准 |
